Q1: 这篇论文试图解决什么问题？

该论文旨在解决**通过强化学习（RL）训练大规模稀疏混合专家（MoE）语言模型，使其在真实终端环境中自主执行长程任务**时所面临的核心难题。具体而言，其研究目标可分解为以下几个关键问题： ### 1. 长程终端任务的稀疏奖励与信用分配问题 现有智能体在长程终端任务（如代码调试、系统管理、科学发现）中，单次 rollout 可能消耗数百个 sandbox 小时，但传统的二元成功/失败奖励每个轨迹仅提供 1 bit 信号，导致学习效率极低。论文指出，仅依赖稀疏结果奖励的 RL 训练甚至无法超越有监督微调（SFT）基线。为此，需要设计一种**基于执行验证的密集过程奖励（Dense Process Reward）**，将任务验证器（verifier）的每个断言（assertion）结果转化为细粒度的学习信号。 ### 2. 稀疏 MoE 模型的训练-推理不一致性（Training-Inference Mismatch） 专家权重占模型参数的绝大部分（如 95.5%），且每个 token 通过离散的 TopK 路由器选择专家。推理（sampling）与训练（gradient computation）在不同系统上执行时，由于内核、归约顺序和张量布局的差异，微小的数值波动即可导致专家选择发生翻转。这使得重要性比率（importance ratio）可能比较的是两个不同的子网络，而非同一策略的两个版本。论文将此问题拆解为两个正交维度： - **Token 保真度**：多轮工具调用中，对话模板重渲染历史消息会导致 re-tokenization 漂移； - **路由保真度**：推理与训练端的路由器输出不一致。 ### 3. 长程交互中的策略稳定性与基础设施挑战 长程任务需要模型在数百轮工具调用中保持行为一致性，这对 RL 训练的基础设施提出严苛要求： - 需要在一个设备集合上时间复用共存的 122B actor-critic 网络对； - 单步训练耗时可达小时级，必须处理编译风暴、掉队者（straggler）尾延迟和分布式系统的活性（liveness）问题； - 需要管理大规模并发沙箱环境，并在过采样（oversampling）机制下平衡吞吐量与训练分布偏差。 ### 4. 避免基准过拟合的能力迁移验证 论文强调训练语料必须与评估基准完全分布外（out-of-distribution），即通过隔离种子和递归合成（Recursive Synthesis）生成与 Terminal-Bench 2.1 不相交的任务集合，以确保性能提升反映的是**真实能力迁移**而非对特定基准的过拟合。 ### 核心贡献概述 为应对上述问题，论文提出了 **T1**，一个 122B 总参数的 MoE 终端智能体，并给出了一套完整的训练配方： - **TITO（Token-In-Token-Out）**：通过传递采样时的精确 token ID 并在轮次边界进行漂移修复，保证训练端与推理端的输入前缀完全一致； - **R3（Rollout Routing Replay）**：记录推理时每层 MoE 的专家选择并在训练前向传播中重放，消除路由离散性带来的梯度错配； - **密集验证奖励（Dense Verification Reward）**：以固定全局尺度上的通过断言绝对数量作为奖励， harder tasks 自然携带更强信号； - **激进热启动的 Critic**：以 30 倍于 actor 的学习率预热 value 网络，使 explained variance 从负值迅速提升至 0.71–0.86，从而提供稳定的优势估计基线。 最终，该框架在 Terminal-Bench 2.1 上将 SFT 检查点从 49.4% 提升至 **64.0%**，在 Long-Horizon Terminal Bench 上达到 **27.9%**，验证了上述机制在提升长程终端代理能力方面的有效性。

Q2: 有哪些相关研究？

相关研究主要分布于**终端智能体数据合成**与**大规模稀疏模型强化学习稳定性**两个方向，此外还涉及长程任务基准测试与异步 RL 基础设施。以下按研究脉络梳理： --- ### 1. 终端智能体数据合成与训练 #### 1.1 任务构建范式 早期工作依赖专家手动编写终端任务，将指令、容器环境与可执行验证器配对（如 Terminal-Bench [14]）。为突破人工规模限制，近期研究沿三条路线程序化生成长程终端环境： - **仓库派生法**：从真实开发历史恢复工作区并复用既有测试（SWE-Gym [15]、R2E-Gym [7]、Large-scale trajectory generation [27]）。 - **扰动注入法**：在可运行仓库或 CLI 工作空间中人为注入故障（CLI-Gym [10]、SWE-smith [29]）。 - **任务条件合成**：从类别、能力分类法或技能图联合生成指令、环境与验证器（Endless Terminals [3]、CLIUniverse [5]、TermiGen [35]、Toward scalable synthesis via skill graphs [1]、Data engineering for scaling [16]）。 #### 1.2 自适应与进化式任务池 由于从零合成的任务很快会被前沿模型饱和，另一支研究致力于使任务池本身具备自适应能力： - **RST（Recursive Synthesis Terminal）** [8]：通过递归重播已验证任务包，逐步延长任务 horizon。 - **SETA / Environment Evolution** [2, 20]：逐代提升环境难度。 - **CalibForge** [13]：基于求解器反馈对抗式校准任务分布。 - **Terminal-Universe** [26]：将记录轨迹重建为可执行工作区，再跨工作区与对话轮次重查询。 #### 1.3 训练方法对比 上述管线大多仅通过监督微调（SFT）验证，强化学习证据局限于较小规模的稠密策略，且通常优化二元结果奖励，相对 SFT 检查点的提升往往只有几个百分点 [3, 6, 18, 25]。本文则聚焦**大规模 MoE 模型**、**密集执行奖励**与**长程交互**下的纯 RL 后训练。 --- ### 2. 训练–推理不匹配下的稳定强化学习 #### 2.1 问题根源 现代 RL 栈普遍采用异构系统：推理引擎（如 SGLang [34]）负责采样，训练引擎（如 Megatron [21]）负责梯度计算。两者在内核、数值精度与并行策略上的差异导致即使在零滞后（staleness）下，采样端的 log-probability 与训练端的复现结果仍会发散 [11]。对于稀疏 MoE 模型，该问题被进一步放大：同一前缀下，一次更新即可翻转约十分之一的激活专家，使得重要性比率（importance ratio）比较的是两个不同子网络而非同一策略的两个版本 [33]。 #### 2.2 目标函数层面的缓解方法 现有工作主要通过重加权、掩码或重塑目标函数来抑制失配带来的噪声： - **Truncated importance sampling** [32]：在位修正比率，但 token 级校正会引入有偏的状态分布。 - **IcePop** [31]：在固定双侧带外丢弃梯度。 - **KPop** [4]：将固定带替换为基于二元 KL 接受域的自适应掩码区域，避免对低概率探索 token 过度掩码。 - **SAT** [30]：基于自适应滞后分位数仅收缩符号选定的裁剪端点。 - **GSPO / DPPO** [17, 33]：将比率操作移至序列级，或以直接散度估计替代比率裁剪。 #### 2.3 从源头消除失配的方法 与上述事后修正不同，本文 T1 采用与以下工作更近似的**源头对齐**思路： - **Rollout Routing Replay（R3）** [12]：在反向传播中重放采样时的专家选择，恢复训练与推理的路由一致性。 - **Token-In-Token-Out（TITO）** [22]：让训练端精确评分推理引擎实际消费与发出的 token 标识符，消除因对话模板重渲染导致的 re-tokenization 漂移。 本文将 R3 与 TITO 结合，并针对长程多轮终端交互中的边界漂移修复与路由记录跨版本对齐进行了工程化扩展，同时配合 Critic Warm-Up 与密集验证奖励，构成了面向 122B MoE 长程 RL 的完整稳定栈。 --- ### 3. 长程终端基准 论文的评估依托于以下基准： - **Terminal-Bench 2.1** [14]：89 个基于执行验证的终端任务。 - **Long-Horizon Terminal Bench（LHTB）** [9]：46 个高难度、可复现任务，采用连续部分信用评分。 - **Terminal-Bench Hard（TBH）** [8]：100 个独立构建的更难任务分布。

Q3: 论文如何解决这个问题？

论文通过一套面向**大规模稀疏 MoE 模型**的端到端后训练方案，从奖励设计、训练稳定性、数据构造与系统工程四个层面系统性地解决了长程终端任务的强化学习难题。具体方法如下： --- ### 1. 密集验证奖励：将执行结果转化为细粒度学习信号 针对长程任务中二元奖励信号稀疏、部分进度不可见的问题，论文设计了基于**绝对断言通过数**的密集过程奖励。 - **奖励定义**：对于每个任务，令 $P$ 为验证器报告的通过断言数量，奖励为 $$r = \frac{P}{S}, \quad S = 20$$ 其中 $S$ 为跨任务固定的全局尺度（取自 T1-15k 数据集中断言数量的约 90 分位数），而非随任务变化的最大值或比例。这确保了难度更高的任务天然携带更强的梯度信号。 - **信用分配**：标量 $r$ 仅置于轨迹最终响应 token 处，通过 GAE（$\gamma = \lambda = 1$）将信用沿长程交互 horizon 反向传播。由于每任务仅采样一条轨迹，不构造组内基线，也不对奖励做跨任务归一化，从而保留跨任务难度差异。 - **防奖励劫持**：在数据侧通过 LLM 审计（8 维度质量评分）硬拒绝存在隐藏要求、测试泄漏或验证器过弱的任务；在训练侧固定 $S$ 并监控轮次增长，避免模型通过无意义延长交互来获取更多奖励。 --- ### 2. TITO：消除 Token 级别的训练–推理漂移 多轮终端交互中，对话模板对历史消息的重渲染会导致 re-tokenization，使训练端条件化的前缀与推理时实际采样的前缀不一致。论文提出 **TITO（Token-In-Token-Out）** 机制： - **Token-In**：每轮推理时，推理引擎返回的采样 token 标识符 $a_i$ 被直接保存；下一轮输入构造时，历史以这些原始标识符的比特精确前缀形式延续，而非重新编码的文本。 - **Token-Out**：轨迹组装器将多轮交互缝合为单一 token 流 $T = (T_1, \dots, T_N)$，其中损失掩码 $m_j = 1$ 当且仅当位置 $j$ 为采样 token。 - **边界修复**：在轮次边界处，组装器按严格层级（strict → normalized → retokenized → split）检测前缀一致性，并在可审计的有限网格内修复，**绝不**将重新编码的 $\tilde{a}_i$ 注入训练流。经验验证表明，损失区域内的漂移率恰好为 $0.0000\%$。 --- ### 3. R3：对齐 MoE 路由的离散选择 稀疏 MoE 中，推理与训练引擎对路由器分数 $s_j^\ell$ 的数值差异可能导致 $\text{TopK}_k$ 选择翻转，使梯度流向未参与采样的专家子网络。论文引入 **R3（Rollout Routing Replay）**： - **记录**：推理时记录每个预测位置在每层 MoE 的所选专家索引集合： $$I_j^\ell = \text{TopK}_k(s_j^\ell)$$ 形成紧凑整数张量 $R \in [E]^{\rho \times L \times k}$。 - **重放**：训练前向传播中，专家选择直接读取记录 $I_j^\ell$，但门控权重仍由当前策略的路由器 logits 计算： $$g_{j,e}^\ell = \frac{\exp([s_j^\ell(\theta_t)]_e)}{\sum_{e' \in I_j^\ell} \exp([s_j^\ell(\theta_t)]_{e'})}, \quad e \in I_j^\ell$$ 这既保证训练与推理作用于**同一子网络**，又保留路由器梯度的可训练性。 - **多轮对齐**：记录随 token 流一同经历 TITO 的缝合与分片，仅在无梯度的占位位置允许相邻替换，确保每个参与损失计算的位置都满足路由保真度。 结合 TITO 与 R3，训练–推理 log-probability 差异从 $0.021$ 降至 $0.013$，且在损失区域内实现零 token 漂移。 --- ### 4. Critic 热启动与稳定优化 长程轨迹的价值估计极易失稳。论文采用以下策略确保 PPO 的基线可靠： - **Critic Warm-Up**：在策略更新前，先在 TMax-15k 上训练 value 网络一个 epoch，仅保存权重。这使 explained variance (EV) 从冷启动的 $-33.6$ 提升至稳态的 $0.71$–$0.86$，避免早期更新因基线噪声而崩溃。 - **学习率分离**：Critic 学习率设为 $\eta_\phi = 1.5 \times 10^{-5}$，为 actor（$\eta_\theta = 1.0 \times 10^{-6}$）的 30 倍。由于价值目标是监督回归而非策略改进，Critic 可承受更大步长。 - **更新顺序**：每步先更新 Critic，再将其**更新前**的值 $V_{\text{old}}$ 用于 GAE 优势估计与值函数裁剪，形成固定的信任区域锚点。 - **目标简化**：显式禁用 KL 惩罚项（因 frozen reference 的路由选择差异会导致不公平的散度度量）与 MoE 负载均衡损失（因其要求重新分布的路由与 R3 的重放约束冲突）。 --- ### 5. 完全分布外的训练语料（T1-15k） 为避免对 Terminal-Bench 2.1 的过拟合，论文构建了与评估基准不相交的训练池： - **递归合成（RST）**：从隔离种子出发，迭代扩展参考解决方案、对齐环境与验证器，并在沙箱中执行确认后递归重播。T1-15k 从 37,484 个合成任务中精选 15,000 个。 - **多维度审计**：使用 DeepSeek-V4-Pro 对任务按 8 个维度评分（指令/验证器对齐占 20% 权重），硬拒绝存在隐藏要求、测试泄漏、捷径解法或验证器过弱的任务。 - **动态打乱**：任务按质量排序物化，每轮 epoch 必须进行种子置换随机打乱，防止批次依次遍历质量带导致奖励分布单调漂移。 --- ### 6. 长程基础设施：共存 Actor–Critic 与小时级步长 为支撑 122B 参数、300+ 轮交互的 RL 训练，论文设计了专用基础设施： - **容量模型**：建立闭式 per-device 内存 footprint 模型，证明专家优化器状态与分片计划无关，从而确定设备预算的硬约束而非启发式调参，使 actor–critic 对在单设备集上通过强制卸载（forced offload）时间复用。 - **上下文并行**：对循环算子（recurrent operator）原生序列分片，将激活峰值随并行度 $\kappa$ 近似线性降低，使 84k 乃至 128k 的上下文墙在现有设备预算下可行。 - **异步流水线**：推理与训练在不相交加速器上并行，步 $t$ 的训练与步 $t+1$ 的生成重叠；通过发布屏障（publication barrier）保证行为策略版本恰好滞后一步（$\sigma = 1$）。 - **Straggler 尾部管理**：对批次 512 过采样至 560 个 trial，采集最先完成的 512 条轨迹，用 wall-clock 确定性换取对最重尾部任务的轻微选择偏差。 --- 综上，论文通过**密集执行奖励**提供可学习的细粒度信号，通过 **TITO + R3** 消除 MoE 长程交互中的训练–推理失配，通过 **Critic 热启动与调度**确保价值基线稳定，并依托**分布外数据与专用基础设施**，将 Qwen3.5-122B-A10B 从 43.8% 的基线提升至 Terminal-Bench 2.1 上的 64.0%，在 Long-Horizon Terminal Bench 上达到 27.9%。

Q4: 论文做了哪些实验？

论文的实验围绕**长程终端智能体强化学习**展开，涵盖基准评估、训练配置对比、稳定性消融、训练动态监测与行为案例分析。以下按实验类别系统梳理： --- ### 1. 基准测试与评估协议 所有实验均在统一的智能体 harness（Terminus-2）与 Daytona 沙箱后端下执行，保证可比性。评估覆盖三个完全分布外的测试集： | 基准 | 任务数 | 评分方式 | 测试重点 | |------|--------|----------|----------| | **Terminal-Bench 2.1** | 89 | 执行验证后的 resolved rate（%） | 终端智能体综合能力 | | **Long-Horizon Terminal Bench (LHTB)** | 46 | 连续部分信用的 average reward | 长程交互与抗记忆化 | | **Terminal-Bench Hard (TBH)** | 100 | 执行验证后的 resolved rate（%） | 独立构造的更难分布 | 评估配置：温度 $0.1$、top-p $0.95$、top-k $20$、上下文窗口 $96{,}000$ tokens、每任务 $3$ 次尝试、最多 $60$ 轮工具调用、agent wall time $3600\,\text{s}$、verifier wall time $900\,\text{s}$。 --- ### 2. 主实验：不同训练配置的对比 论文对比了三种逐步演进的训练方案，均以 Qwen3.5-122B-A10B（总参 122B，激活 10B）为起点： - **Binary reward on TMax-15k**：从 base model（$43.8\%$）出发，无 Critic Warm-Up，使用仅含二元终端结果的数据集。训练至第 30 步时达到 $47.2\%$，**未超越 SFT 检查点**（$49.4\%$），但为后续提供了预训练 Critic。 - **Dense reward on RST-38k**：加载上述 Critic，以 RST-SFT（$49.4\%$）为初始策略，在未经审计过滤的 37k 合成任务上训练。第 70 步达到 $59.9\%$，验证密集奖励的有效性。 - **Dense reward on T1-15k（生产运行）**：经 Critic Warm-Up（在 TMax-15k 上预热 1 个 epoch）后，在高质量、带 per-assertion 验证的 15k 任务上训练。**第 110 步达到 $64.0\%$**，较 SFT 提升 $14.6$ 个百分点，较 base 提升 $20.2$ 个百分点。 与前沿模型的同 harness 对比如下（Terminal-Bench 2.1）： - **T1**：$64.0\%$ - Claude Opus 4.7：$66.1\%$ - Claude Opus 4.6：$63.8\%$ - Muse Spark：$62.2\%$ - DeepSeek-V4-Flash：$56.9\%$ - GPT-5.4：$54.8\%$ 在 LHTB 上，T1 取得 $27.9$ 的平均奖励，与 Gemini-3.1-Pro 持平（$27.9$），超越 GPT-5.4（$27.2$）与 GLM-5.1（$26.7$）。在 TBH 上，T1 达到 $38.0\%$，超越 DeepSeek-V4-Pro（$36.0\%$）。 --- ### 3. 稳定性消融实验 #### 3.1 Training–Inference Mismatch 的量化 定义逐位置 log-probability 差异： $$\Delta_j = \log \pi_t^t(x_j \mid \cdot) - \log \pi_{t-1}^r(x_j \mid \cdot)$$ 并报告损失区域内掩码加权的平均绝对值 $|\Delta \log p|$。 | 配置 | $|\Delta \log p|$ | |------|-------------------| | 无 TITO 且无 R3 | $0.021$ | | T1（TITO + R3） | $0.013$ | 结合 TITO 与 R3 后，损失区域内 token 漂移率为 $0.0000\%$，路由占位替换率 $<0.003\%$ 且与梯度区域不相交。 #### 3.2 Critic Warm-Up 的效用对比 测量 Critic **explained variance**（EV）： $$\text{EV} = 1 - \frac{\text{Var}_j(\hat{R}_j - V_\phi(s_j))}{\text{Var}_j(\hat{R}_j)}$$ - **Cold-start**（TMax-15k 二元奖励运行）：初始 EV 跌至 $-33.6$，前 30 步中有大量负值，Critic 前 58 步中的 30 步为负。 - **Warm-up**（T1-15k 生产运行）：自第一步起 EV 即稳定在 $0.71$–$0.86$，从未出现负值。 在 27B 路径寻找实验中，进一步验证 Critic 学习率倍率（$10\times$、$20\times$、$30\times$）对 EV 的影响，$30\times$ 设置下 EV 从 $-39$ 提升至 $+0.11$。 --- ### 4. 训练动态监测实验 #### 4.1 奖励曲线 在生产运行的 110 步中，原始 rollout 奖励（未归一化）从约 $0.250$（对应约 5 个通过断言）快速爬升至 $0.345$（约 7 个），随后在第 50–110 步间稳定于 $0.34$–$0.36$ 的带状区域。高频振荡幅度约 $0.02$，被确认为批次构成签名而非不稳定性。 #### 4.2 行为动态（Trajectory Behavior） 监测每轨迹平均工具调用轮次与总序列长度： - **轮次**：从初始 $10.4$ 轮增长至约 $20.7$ 轮后平稳，未出现无界增长（与早期 27B 实验中长度攻击导致的失控增长形成对比）。 - **序列长度**：从 $11.5\text{k}$ tokens 增长至约 $18.3\text{k}$ tokens 后平稳。 #### 4.3 保留集性能随步数变化 每 10 个 rollout 步在 Terminal-Bench 2.1 上评估： - 第 10 步：$56.2\%$（已超越 SFT 初始化） - 第 20–60 步：稳定于 $55.1\%$–$57.3\%$ - 第 70 步：$61.8\%$ - 第 110 步：峰值 $64.0\%$ 两次显著跃升（第 70 步、第 110 步）恰好对应 Critic EV 最高的阶段，表明策略的大幅改进依赖于价值基线的充分校准。 --- ### 5. 失败教训与对比实验 #### 5.1 GRPO vs PPO 的对比 在相同 harness、奖励与设备预算下，于 T1-15k 上训练 GRPO（无 Critic，依赖组内基线）： - 训练奖励曲线无趋势性上升（剧烈波动）。 - 第 10 步与第 20 步的保留集性能均为 $51.7\%$（89 任务中解决 46 个），**零提升**。 论文据此论证：长程任务中组内样本高度同质化（全部失败或全部成功），导致优势退化；且组内最慢样本拖累了整体吞吐量。 #### 5.2 长度塑形（Length Shaping）的放弃 在 27B 实验中观察到测试数奖励引发轮次失控增长，曾尝试多种长度塑形变体。但在 122B 生产运行中，直接监控轮次后发现增长有界，故**禁用长度惩罚**，使用纯测试数奖励。 --- ### 6. 案例研究：详细轨迹分析 选取 Terminal-Bench 2.1 中 T1 解决而 SFT 基线未解决的两个软件工程任务，进行细粒度行为对比： #### 6.1 build-pov-ray（策略切换能力） - **SFT 模型**：正确诊断出官方下载源失效，但持续重试死链，导致 51 次上下文溢出、50 轮被替换为占位符，最终因下载错误版本失败。 - **T1**：做出相同诊断后，立即切换至可用 FTP 镜像，在 65 轮内通过全部 3 项断言，零溢出。 #### 6.2 polyglot-c-py（环境终态意识） - **SFT 模型**：编写出正确的 Python/C 多语言程序并验证 Fibonacci 数值，但将编译产物 `cmain` 留在 `/app/polyglot/` 目录中。验证器要求目录**恰好**包含 `["main.py.c"]`，因此得 $0.0$。 - **T1**：执行相同测试后主动清理编译产物，以 $1.0$ 通过。 这两个案例表明，RL 并非教会了新的领域知识，而是改变了策略对**已得出结论的处置方式**（放弃无效假设、将工作区终态纳入交付考量）。 --- ### 7. 领域与难度分解实验 对 Terminal-Bench 2.1 进行子集分析： - **按领域**：T1 在 debugging（$100.0\%$ vs GPT-5.6 Sol 的 $80.0\%$）与 system administration（$88.9\%$ vs $55.6\%$）上优势最大；在 data science、scientific computing、mathematics 上仍有差距。 - **按难度**： - Easy：三阶段均达 $100\%$。 - Medium：base $56\%$ → SFT $58\%$ → T1 $78\%$，RL 贡献最大。 - Hard：base $20\%$ → SFT $30\%$ → T1 $33\%$，绝对提升有限，仍为主要失败来源。 - **交互成本**：T1 在评估中平均使用 $94.4$ 轮，约为 SFT（$31.5$ 轮）的 3 倍，但 Hard 任务上的收益相对有限，提示存在低效搜索。 --- ### 8. 基础设施验证实验 - **容量模型验证**：通过闭式内存 footprint 模型预判定分片计划，在初始化前拒绝不可行配置，避免小时级训练步中途 OOM。 - **循环算子上下文并行**：在 $\kappa \in \{2,4,8\}$ 下与单秩参考对比，前向 bit-exact，梯度误差 $<1.2\times 10^{-7}$，激活峰值近似线性下降。 - **过采样偏差监测**：在某一步中，561 个提交 trial 里有 48 个因完成过慢被取消，用于量化训练分布与任务难度分布的潜在偏差。

Q5: 有什么可以进一步探索的点？

论文在多个层面留下了明确的开放问题与可扩展方向，可归纳为算法理论、数据与验证、系统与基础设施三个维度。 --- ### 1. 算法与训练理论 **消除剩余的 conditioning 不精确性。** TITO 仅在损失区域内保证了比特精确的 token 保真度，但在 re-tokenized 边界情况下，后续轮次仍可能基于训练端重构的标识符进行条件化，影响约 $2.6\%$ 的 token。完全消除这一残余漂移需要让智能体 harness 以 token 标识符而非文本作为历史记录的真相源（source of truth），这涉及对多轮工具调用协议的底层重构。 **受控的奖励消融实验。** 当前对比二元奖励与密集奖励的证据属于跨运行级别（campaign-level），两个运行同时在奖励形式、数据池、初始化点和路由重放机制上存在差异。未来需要设计控制变量实验：在相同的池、初始化与路由重放条件下，仅改变奖励形式，以严格隔离密集验证奖励的独立贡献。 **Critic 预训练与替代价值目标。** 论文提到两种尚未在当前代码库中实现的方向：一是利用离线轨迹对 Critic 进行预训练，以在 step 0 获得更高的 explained variance；二是采用分类式价值损失（如 HL-Gauss）替代回归，可能改善长程回报分布下的 value 估计。 **长度自适应优势估计（length-adaptive advantage）。** 论文提及该变体的覆盖范围尚不完整，探索如何在超长轨迹中动态调整 GAE 或优势估计的时间尺度，是一个有待充分验证的方向。 **完全异步训练与更大滞后容忍。** 生产循环当前采用 $\sigma = 1$ 的一步异步。论文指出完全异步路径（$\sigma > 1$）已在插件中存在但未用于 122B 运行。已有研究表明在 Qwen3-30B-A3B 上，基线 GRPO/GSPO 在 $\sigma = 8$ 下会崩溃，而组合使用 GSPO + SAT + R3、软掩码或 TIS 可生存。将这些 winning combination 移植到终端智能体场景是下一步计划。 --- ### 2. 数据分布与验证器安全 **扩展数据分布以覆盖薄弱领域。** T1-15k 的任务分布高度集中于命令行工程工作（脚本、软件开发、系统管理占 $67.9\%$），而机器学习、数据科学、科学计算、调试与性能观测等类别覆盖不足（均低于 $4\%$）。评估失败也集中于这些薄弱领域。未来需要构建跨领域更均衡的大规模合成语料，验证能力增益是否可向数据稀缺领域迁移。 **验证器运行时完整性（runtime integrity）。** 当前对验证器的保护完全依赖前置审计过滤，而非沙箱内的运行时防篡改检测。验证器与待测代码执行于同一 agent 可控的沙箱中，存在被修改风险。可直接探索的工程措施包括：只读测试挂载、带校验和的验证器镜像、或在沙箱外独立执行验证。 **难度感知调度与部分 rollout 延续。** 过采样（oversampling）机制为控制步长时间而丢弃最慢 trial，导致 hardest task families 在训练中被系统性欠采样，而评估失败恰好集中在这些超长交互任务（数百轮、超时）。未来可探索： - **部分 rollout 延续**：保留未完成轨迹的状态，在后续步骤中续跑，避免 hardest trials 完全丢失； - **每任务预算尊重**：为不同难度任务分配差异化交互预算； - **难度感知调度**：根据任务历史完成时间或通过率动态调整采样优先级。 --- ### 3. 系统、基础设施与评估 **上下文管理（context management）的深层优化。** 第 9.2 节的教训表明，上下文压缩策略直接决定智能体在长程交互中的有效记忆。当压缩失败时（如摘要生成不匹配导致 $98.3\%$ 回退到短片段），策略被迫在信息缺失下重复工作。未来可探索可学习的、任务自适应的上下文压缩机制，而非固定阈值触发。 **量化并缓解过采样引入的选择偏差。** 第 9.3 节与第 7.4 节指出，按完成时间截断 tail 会在训练分布中引入对快速任务的偏差。需要建立该偏差对最终策略影响的定量分析方法，并设计保留未完成 hard trial 信息的训练协议（如异步价值更新或延迟梯度）。 **工程 bookkeeping 与可移植性。** 论文列出若干待完善的簿记事项：生产运行的最终优化器放置设置、权重同步时机、逐行评估协议标签等。这些虽非理论阻塞，但对结果的可复现性与配方向更大或更小设备预算的迁移至关重要。特别地，第 7.1 节的容量模型指出，actor–critic 对的内存可行性是设备预算的硬函数，验证该模型在跨规模（如从当前规模扩展两倍以上）时的解析可行性具有工程价值。 **跨 harness、跨基准与跨模型的验证。** 当前所有结论均局限于单一模型家族（Qwen3.5-MoE）、单一智能体 harness（Terminus-2）和一套基准组合。真正可迁移的声明是机制本身（TITO、R3、Critic 调度、操作护栏）而非具体数值。未来需要在其他 MoE 架构、其他终端 harness（如 Claude Code、Codex CLI）及更广泛的软件工程基准上验证这些机制的通用性。

Q6: 总结一下论文的主要内容

该论文介绍了 **T1**，一个基于 Qwen3.5-122B-A10B（总参数 122B，激活参数 10B）的终端智能体，通过后训练强化学习（RL）在真实 Linux shell 环境中执行长程任务（最多 300+ 轮工具调用）。研究核心在于解决大规模稀疏混合专家（MoE）模型在长程终端任务 RL 中的两个关键难题：**训练–推理不一致**与**奖励稀疏性**。 ### 核心问题 1. **训练–推理不匹配**：推理（采样）与训练（梯度计算）分属异构系统，数值差异导致 MoE 的离散路由器选择不同专家，使重要性比率（importance ratio）比较的是不同子网络；多轮终端交互中的对话模板重渲染还会引入 re-tokenization 漂移。 2. **稀疏奖励**：传统二元任务成败奖励在长程 rollout 中仅提供 1 bit 信号，导致 RL 训练难以超越监督微调（SFT）基线。 ### 主要方法 论文提出了一套稳定化栈与奖励设计： - **TITO（Token-In-Token-Out）**：强制训练端消费推理引擎实际发出的精确 token 标识符，并在轮次边界通过四级层级（strict → normalized → retokenized → split）修复漂移，使损失区域内 token 漂移率为 $0.0000\%$。 - **R3（Rollout Routing Replay）**：记录推理时每层 MoE 的 TopK 专家选择，在训练前向传播中重放该选择（仅冻结选择，门控仍由当前策略计算），消除路由不一致，将训练–推理 log-probability 差距从 $0.021$ 降至 $0.013$。 - **密集验证奖励**：以验证器通过的断言绝对数量作为奖励，$r = P/S$（固定全局尺度 $S=20$），使部分完成可见， harder tasks 自然携带更强信号；奖励仅置于轨迹最终 token，由 GAE 沿长程 horizon 分配信用。 - **Critic Warm-Up**：在策略更新前先在离线数据上预热价值网络一个 epoch，并以 $30\times$ 于 actor 的学习率训练，使 explained variance 从冷启动的 $-33.6$ 提升至稳态 $0.71$–$0.86$。 - **分布外训练语料（T1-15k）**：通过递归合成（RST）与多维 LLM 审计构建 15,000 个高质量终端任务，确保与 Terminal-Bench 2.1 等评估基准完全不相交，避免过拟合。 ### 基础设施 为支撑小时级训练步长与共存的双 122B 网络，论文设计了专用系统：基于闭式内存模型的 actor–critic 容量规划、循环算子的原生上下文并行、异步一步流水线推理–训练重叠，以及带过采样（oversampling）的 straggler 尾部管理。 ### 实验结果 - **Terminal-Bench 2.1**：从 base 模型 $43.8\%$ → SFT $49.4\%$ → T1 **$64.0\%$**；RL 单独贡献 $14.6$ 个百分点，超过 GPT-5.4（$54.8\%$）、DeepSeek-V4-Flash（$56.9\%$），逼近 Claude Opus 4.7（$66.1\%$）。 - **Long-Horizon Terminal Bench**：T1 达到 **$27.9$**（平均奖励），与 Gemini-3.1-Pro 持平，超越 GPT-5.4。 - **Terminal-Bench Hard**：达到 **$38.0\%$**，超过 DeepSeek-V4-Pro。 ### 教训与开放方向 论文还记录了失败经验：Critic 校准本身不保证策略改进（需配合密集奖励）；上下文管理失败会导致无效重复搜索；GRPO 在长程任务中因组内同质化而失效。未来工作包括消除残余 re-tokenization 漂移、验证器运行时完整性保护、部分 rollout 延续以保留 hard trials、跨 harness 与跨模型的机制验证，以及更均衡的领域数据分布。
