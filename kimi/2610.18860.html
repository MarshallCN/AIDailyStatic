Q1: 这篇论文试图解决什么问题？

这篇论文旨在解决**信息密集型视觉制品（如幻灯片、海报、仪表盘）的代码生成中，内容正确性与视觉美学质量难以兼得**的问题。 具体而言，论文识别出现有方法存在的以下互补性缺陷： - **纯代码模型的局限**：现有的代码生成模型（如基于文本提示生成 HTML/CSS 的模型）无法直接"看见"最终渲染的画布。它们逐行声明布局、层级和颜色，导致输出虽然在结构上可编辑、可验证，但空间规划能力弱，视觉呈现往往显得过时或单调。 - **纯图像生成模型的局限**：图像生成模型擅长视觉设计和构图，能够生成美观的页面，但在渲染密集文本、数字、图表和逻辑关系时经常出现错误（幻觉）。更重要的是，其输出为光栅图像，无法被编辑、验证或结构化修改。 - **现有图像到代码方法的局限**：传统的图像到代码（image-to-code）方法将输入图像视为像素级重建的绝对真值。然而，若参考图像本身是由文本提示生成的，它可能包含事实或结构上的错误。此时，强制代码模型严格复制参考图像会惩罚合理的设计变体，并奖励对幻觉内容的复制。 为此，论文提出了 **AesCode** 框架，其核心解决思路是： - **利用图像生成器作为美学先验**：从同一文本提示生成一张参考图像，将其作为布局和风格的条件输入，为代码模型提供视觉设计灵感，而非强制像素级复现。 - **解耦内容与视觉监督**：通过**设计图（Design Graph）**将目标表示为结构化中间表示，显式分离语义内容（如特定字符串、数据序列）与视觉属性（如边界框、颜色）。基于此，论文构建了**解耦的跨模态奖励机制**： - **确定性验证器**：对可从代码和渲染中解析的属性（如文本正确性、图表数据、边界合规）进行快速、绝对的检查。 - **视觉图评分规则（VGR）**：由 VLM 评判非解析性视觉属性，通过针对特定样本的二元问题评估美学质量，避免不稳定的全局打分。 - **多目标强化学习优化**：采用 **GDPO（Group reward-Decoupled Normalization Policy Optimization）** 对各奖励通道分别进行归一化，防止密集的规则奖励淹没稀疏的美学奖励，从而联合优化空间规划、美学质量和可验证的正确性。 简言之，该论文解决的是**如何在生成结构化、可验证代码的同时，让代码模型学会从带噪声的生成图像中提取并内化高水平视觉设计能力**的问题。

Q2: 有哪些相关研究？

该论文的相关研究主要围绕三个核心领域展开：**视觉设计与代码生成**、**视觉生成的奖励设计**，以及**多目标强化学习**。以下分述各领域的关键工作及其与本文的关系。 --- ### 1. 视觉设计与代码生成 该领域可按生成模态与条件划分为四类： - **图像生成方法**：如 PosterMaker [4]、BizGen [14] 与 COLE [33]，能够生成高质量的产品海报与多层级设计，但在密集文本、数据编码与拼写方面仍易出现错误 [6]，且输出为光栅图像，无法逐元素编辑或验证。 - **文本到代码方法**：如 LIDA [15]、LayoutGPT [34]、PPTAgent [2] 与 SlidesBench [31]，直接从文本生成可视化代码或布局，但模型在生成过程中无法“看见”最终渲染的页面，导致视觉呈现往往较为单调。 - **图像到代码方法**：如 pix2code [7]、Design2Code [8]、WebSight [35]、ChartMimic [16]、Plot2Code [36] 与 StarVector [37]，旨在从现有渲染图重建底层代码。这类方法将输入图像视为绝对真值，优化目标为像素级相似度，因此不适用于参考图像本身包含噪声或幻觉内容的场景。 - **推理时结合图像与代码的方法**（与本文最接近）：PosterVerse [38] 在生成背景上叠加 HTML 排版；DesignAsCode [17] 在反思阶段使用图像编辑模型提出改进渲染；Editable Visual Design [18] 让编码代理将生成图像作为全局构图与配色参考。然而，这些方法仅在**推理时**利用图像，代码模型并未在**训练阶段**学习如何将其作为美学先验来使用。 --- ### 2. 视觉生成的奖励设计 奖励函数的设计直接决定了强化学习在视觉生成任务中的优化方向： - **基于图像相似度的奖励**：在图像到代码任务中，常用视觉度量（如 VisRefiner [10,19]）或 MLLM 评判（如 UI2Code^n [11]、Relook [12]）来衡量生成渲染与输入图像的相似度。这类方法仅在输入图像为精确目标时有效，若参考图像由文本生成且包含内容错误，则相似度指标会惩罚合理的设计变体并奖励复制错误。 - **基于规则的奖励**：如 AeSlides [21] 使用布局指标，能够精确判断元素重叠等属性，但覆盖范围受限于程序可自动解析的内容。 - **基于偏好模型与整体 MLLM 评判的奖励**：ImageReward [39]、Pick-a-Pic [40] 等偏好模型捕捉主观质量，但继承了标注噪声；整体 MLLM 评判（如 MT-bench [22]、MLLM-as-a-Judge [23]、WebGen-R1 [41]）无需训练，但评分随提示措辞波动，作为美学奖励时信号稀疏且不稳定。 - **基于细粒度清单/规则的评判**：TIFA [42] 与 DSG [24] 将文生图评估分解为多个是/否问题；ArtifactsBench [43] 使用每任务清单评估渲染产物；近期工作将指令导出的评分规则（rubrics）直接作为 RL 奖励，应用于语言模型 [25, 44] 与 SVG 生成 [26]。然而，上述方法均仅从**文本**推导问题，无法检查参考图像所提议的特定布局与风格。本文提出的**视觉图评分规则（VGR）**则从**设计图**中派生问题，将视觉属性绑定到具体图元素与关系上。 --- ### 3. 多目标强化学习 后训练强化学习的方法论经历了从 PPO [45, 46] 到无 Critic 的组归一化方法（如 GRPO [27]）的演变，并遵循 DeepSeek-R1 [28] 与 Visual-RFT [29] 所确立的“SFT 冷启动 + RL”范式。 当存在多个奖励通道时，简单加和后进行组归一化会导致尺度、密度与饱和度不同的信号相互淹没。例如，密集且接近饱和的规则奖励可能压制稀疏但关键的美学反馈。对此： - **MO-GRPO** [30] 通过方差对奖励进行重加权； - **GDPO** [13] 则对每个奖励通道分别进行归一化。 本文采用 GDPO 以平衡基于规则的可验证奖励与基于 VGR 的感知奖励，确保各目标通道的梯度信号在策略更新中得以保留。 --- 简言之，现有研究要么无法兼顾结构可编辑性与视觉质量，要么将参考图像视为不可置疑的真值，或在多目标优化中未能有效解耦不同性质的监督信号。AesCode 通过引入设计图表示与解耦的跨模态奖励，试图弥合上述 gaps。

Q3: 论文如何解决这个问题？

该问题通过 **AesCode** 框架解决，其核心在于将代码生成目标表示为**设计图（Design Graph）**，并据此构建**解耦的跨模态奖励**，最终通过**分组奖励解耦归一化策略优化（GDPO）**进行训练。整体方法可分为以下四个层次： --- ### 1. 设计图：解耦内容与视觉监督 为应对参考图像可能包含事实错误或结构噪声的问题，AesCode 将监督目标构建为一个**设计图**而非单一像素级真值： $$G_{tgt} = (V, E, X_V, r) = \Phi(p, I_{ref})$$ 其中： - 节点 $V$ 来自封闭词表，包含**原子元素**（文本、图片、图表、表格、徽章等）和**容器**（区域、卡片、面板、列表、组）； - 边 $E$ 携带关系类型 $\tau$，包括包含（containment）、对齐（alignment）、顺序（order）、相邻（adjacency）和语义连接（semantic connection）； - 属性 $X_V$ 记录内容（如字符串、数据序列）、几何（如边界框）和外观（如颜色）； - 画布根节点 $r$ 保存页面级属性。 这一表示使**提示要求的内容**与**参考图像提供的视觉线索**能够独立约束互补属性。从生成的代码 $c$ 及其渲染 $\hat{I}$ 中，解析器 $\Psi(c, \hat{I})$ 联合提取候选视觉元素构成 $\hat{G}$，进而可与 $G_{tgt}$ 逐属性比较。 --- ### 2. 解耦的跨模态奖励通道 基于设计图的可归因性，属性按其评估方式被分流至两类互补奖励： #### （1）确定性验证器（Deterministic Verifiers） 对于可从代码、DOM 或渲染像素中程序化解构的属性，采用六个快速、绝对的验证器： | 验证器 | 监督目标 | |---|---| | **Execution** ($s_{exec}$) | 渲染成功与否、致命 JavaScript 错误数量 | | **Text** ($s_{text}$) | 必需字符串是否存在，结合 OCR 可见性加权 | | **Boundary** ($s_{bdry}$) | 元素是否溢出自定义画布、宽高比是否匹配 | | **Table/Chart** ($s_{tc}$) | HTML 表格结构与 ECharts 图表类型、系列、数据是否精确匹配 | | **Semantic Layout** ($s_{layout}$) | OCR 文本块在参考与候选渲染间的归一化位置一致性 | | **Whitespace** ($s_{ws}$) | 粗粒度与细粒度非背景 occupancy 网格的余弦相似度 | #### （2）视觉图评分规则（Visual Graph Rubric, VGR） 对于外观与高阶关系等无法程序化解析的属性，从 $G_{tgt}$ 派生**样本特定的二元问题列表** $Q_{train}$。每个问题绑定到特定节点、属性、边或子图，将开放式视觉判断转化为显式标准： $$s_{vgr} = \frac{1}{|Q_{train}|} \sum_{q \in Q_{train}} \mathbb{I}\left[\hat{I} \text{ satisfies } q\right]$$ 参考图像的线索仅通过**固定问题**进入训练，VLM 仅对候选渲染作答，从而避免将奖励退化为图像相似度度量。 --- ### 3. 训练流程：SFT 冷启动与 GDPO #### （1）冷启动监督微调（SFT） 首先使用 3,000 条高质量演示数据进行监督微调。这些演示由 GPT-5.5 基于原始人类设计生成，并经过奖励系统筛选（保留得分高于 0.85 的样本）。此阶段旨在建立可靠的“提示 + 参考图像 → 代码”生成格式。 #### （2）强化学习优化 RL 阶段将原始人类设计替换为由 GPT-Image-2 从提示生成的合成参考图像。对于每个 $(p, I_{ref})$，策略采样 $B=8$ 条代码轨迹，渲染并解析后得到七维奖励向量 $s_i = (s_i^{(v)})_{v=1}^{7} \in [0,1]^7$。 由于各奖励通道在适用性、尺度、密度和饱和度上差异显著，直接求和后进行标量归一化会导致密集的规则奖励淹没稀疏的美学反馈。因此采用 **GDPO**： 对每个适用通道 $v$（由掩码 $m_i^{(v)} \in \{0,1\}$ 指示），在组内计算均值 $\mu_v$ 和标准差 $\sigma_v$，分别归一化优势： $$A_i^{(v)} = \frac{s_i^{(v)} - \mu_v}{\sigma_v + \epsilon}$$ 再将各适用通道的优势取平均： $$A_i = \frac{\sum_v m_i^{(v)} A_i^{(v)}}{\sum_v m_i^{(v)}}$$ 最终优化带裁剪的组内目标： $$\mathcal{L}_{GDPO}(\theta) = \frac{1}{B} \sum_{i=1}^B \min\left(\rho_i(\theta) A_i, \text{clip}\left(\rho_i(\theta), 1-\varepsilon, 1+\varepsilon\right) A_i\right)$$ 其中 $\rho_i(\theta) = \frac{\pi_\theta(c_i \mid p, I_{ref})}{\pi_{old}(c_i \mid p, I_{ref})}$。适用性掩码确保不相关检查被排除，所有有效目标无需先塌缩为标量即可共同贡献于策略更新。 --- ### 4. 评估协议：正确性与视觉质量分离 为准确衡量“严格满足提示内容”与“灵活借鉴参考美学”的双重目标，评估协议同样解耦： - **Rule（规则分数）**：取 Text、Boundary、Table/Chart 的均值，验证可解析的确切内容、画布合规性与结构化数据正确性。 - **Visual（视觉分数）**：基于提示要求（而非参考图像）构建样本特定的检查表 $Q_p$，从候选渲染中评估： - **Content**：必需元素的存在与完整性； - **Layout**：元素组织、关系与碰撞； - **Style**：层级、排版、色彩与组件完成度。 Visual 为上述三维度均值，且检查表经 50 实例开发集冻结后不再更改，确保对所有系统一视同仁。 --- 简言之，AesCode 通过**设计图**实现了内容约束与视觉引导的解耦，通过**确定性验证器与 VGR** 分别处理可解析与感知型属性，再通过 **GDPO** 在多目标间保持梯度平衡，最终使代码模型能够在严格遵循文本提示的同时，内化生成图像中的美学先验。

Q4: 论文做了哪些实验？

论文的实验围绕**自建信息图基准**、**外部基准迁移**、**消融研究**与**人工评估**四个层面展开，系统验证了 AesCode 在可验证正确性与视觉质量上的联合提升。以下按实验模块分述： --- ### 1. 实验设置 - **训练数据**：从约 18,000 份人类设计的幻灯片、海报、仪表盘和网页中，按 CLIP 图像特征聚类并进行分层采样。 - **SFT**：构建 3,000 条演示，使用原始人类设计作为参考图像，由 GPT-5.5 生成代码，保留奖励得分高于 0.85 的样本。 - **RL**：对剩余提示采样 8 条轨迹，保留学习信号充足的提示，并将参考图像替换为由 GPT-Image-2 生成的合成图像，得到约 8,000 条 RL 提示。 - **测试基准**：300 条 held-out 提示，同样使用 GPT-Image-2 生成参考图像。评估指标按第 3.4 节协议，将 **Rule**（Text、Boundary、Table/Chart 均值）与 **Visual**（Content、Layout、Style 均值）分离报告，Overall 为二者均值。 - **基线**：涵盖闭源前沿模型（GPT-5.5、GPT-5.4、GPT-5.1、GPT-4o、Claude Opus 4.8、Gemini 3.1 Pro）与开源 VLM（Qwen3 系列、InternVL3、Kimi-VL、MiniCPM-V、Llama-4 Scout 等），分别在“仅提示”和“提示 + 参考图像”两种条件下测试。 - **实现**：基于 Qwen3-VL-8B 与 Qwen3-VL-32B 骨干网络，SFT 学习率 $10^{-5}$，GDPO 学习率 $5 \times 10^{-6}$；8B 模型训练 400 步，32B 模型训练 520 步。 --- ### 2. 主实验结果 #### 2.1 自建信息图基准（表 1） 主要发现包括： - **参考图像的普适增益**：对所有闭源与开源模型，提供参考图像均显著提升了 Visual 分数，证明生成图像作为美学先验的有效性。 - **闭源模型的不同优势路径**：Claude Opus 4.8 内容保真度极高，借助参考图像主要提升 Layout 与 Style；GPT-5.5 初始 Style 较强，参考图像主要帮助 Content 与 Layout。 - **开源模型的严重失衡**：多数开源模型在 Rule 与 Visual 间严重偏科，或满足代码级约束但视觉薄弱，或两者皆弱。Qwen3.8-27B 在开源模型中平衡性最佳。 - **AesCode 的显著提升**：在同等参考图像条件下： - **AesCode-8B** 的 Visual 达到 **75.80**，较 Qwen3-VL-8B（44.72）提升 **31.1** 个百分点，Overall 从 51.93 提升至 **82.94**。 - **AesCode-32B** 的 Visual 达到 **77.44**，较 Qwen3-VL-32B（55.02）提升 **22.4** 个百分点，Overall 从 61.10 提升至 **85.89**。 - AesCode-32B 的 Rule（**94.33**）显著高于所有闭源模型，Table/Chart 达到 **90.37**；Visual 与 GPT-5.5（76.76）、Claude Opus 4.8（77.23）处于同一水平，且 Content 错误更少。 #### 2.2 案例研究（图 3） 通过定性对比揭示前沿模型在微观执行上的失败： - GPT-5.5 出现标题与首功能区重叠、仅渲染 4 个而非要求的 5 个 logo 槽位、底部消息带遮挡已正确实例化的 ECharts 图表等问题。这些案例表明，即使代码结构正确（Chart 得分完整），渲染可见性与空间关系仍可能失败，而 AesCode-32B 避免了这些缺陷。 #### 2.3 外部基准迁移（表 2） 在三个不同任务与评估协议的外部基准上，AesCode-32B 相比其 Qwen3-VL-32B 骨干在全部 14 项指标上均有提升： - **SlidesBench**：Content、Layout、Color 均有改善； - **GDB/lica**：NIMA、FID、Color Harmony 等设计敏感指标增益最大； - **Design2Code**：因该基准为较早的网页重建任务，相似度指标已接近饱和且与人类美学判断对齐度较低，AesCode 增益较小，但仍体现其优势在于布局与视觉设计而非像素级重建。 --- ### 3. 消融实验 #### 3.1 参考图像在训练与推理中的作用（表 3） | 设置 | 关键发现 | |---|---| | **仅在推理时移除参考** | AesCode-8B 的 Visual 仅下降 **1.00** 点；而作为对比，其骨干 Qwen3-VL-8B 下降 **19.55** 点，GPT-5.5 下降 **10.04** 点。这表明参考条件训练已将多模态视觉规划内化为策略能力。 | | **训练与推理均移除参考** | 即使策略从未见过参考图像，仅通过参考驱动的奖励监督，仍可将 prompt-only Visual 从骨干的 **25.17** 提升至 **69.71**，证明视觉监督可通过奖励间接迁移；但仍比参考条件训练低 **5.09** 点，确认参考作为输入条件的独立价值。 | #### 3.2 训练与奖励设计消融（表 4） 基于 Qwen3-VL-8B 的组件逐一剥离实验表明： - **SFT 与 RL**：RL 贡献主要增益；但在相同 RL 预算下，经过 SFT 冷启动的模型 Overall 从 77.97 提升至 **82.94**。 - **GDPO vs GRPO**：GDPO 通过独立归一化各奖励通道，相比标量聚合的 GRPO 提升 Visual **5.12** 点（70.68 → 75.80），有效避免了密集验证信号对稀疏美学反馈的压制。 - **设计监督机制**： - 无设计监督时 Visual 仅 **66.59**； - 加入 Semantic Layout 与 Whitespace 后提升至 **68.12**； - CLIP 相似度可达 **70.49**，但无法定位具体失败属性； - 整体 VLM 绝对评分仅 **68.91**，信号稀疏且不稳定； - **VGR（视觉图评分规则）**达到最高 **75.80**，且不牺牲 Rule（90.07）。 - Q5: 有什么可以进一步探索的点？

基于论文结论与残余失效分析，以下方向值得进一步探索： --- ### 1. 视觉感知的迭代式几何精化 论文指出，代码生成难以可靠预判最终像素几何，导致罕见的画布溢出与元素裁切。未来可探索**渲染-反馈闭环**：在代码生成后引入基于渲染图的几何校验与自动修正机制，例如让模型直接读取渲染后的边界框坐标，迭代调整 CSS 尺寸与定位，或将像素级布局信息作为附加观察输入到策略网络中。 --- ### 2. 细粒度结构与关系级监督 当前关系结构（如时间线顺序、层级连接、空间依赖）的奖励信号稀疏，且失败时无法定位到具体边。可研究**边级别的密集监督**：将设计图中的边转化为可微或可验证的约束损失，或利用图神经网络（GNN）在策略中显式建模节点间关系，从而将全局布局一致性分解为局部边约束的加和。 --- ### 3. 语义视觉元素的细粒度生成 图标、标识等语义元素常退化为通用形状，因为现有奖励仅监督槽位几何而不监督其绘制内容。未来可引入**语义-图形对齐监督**：例如，通过 CLIP 或专用图标编码器约束 SVG 路径的语义可识别性，或构建“含义→矢量图形”的映射数据集，训练模型生成与文本标签一致的细粒度矢量图标。 --- ### 4. 无参考图像的零样本美学生成 论文表明，经参考条件训练后，模型在推理时移除参考仍能保留大部分视觉能力（Visual 仅下降 1.00 点）。可进一步探索**从文本提示直接推断视觉先验**的方法：例如，训练内部美学风格模型，或将大规模图像生成模型的视觉知识通过知识蒸馏压缩到代码生成策略中，从而在部署时无需调用图像生成器即可输出高质量设计。 --- ### 5. 动态与自适应的多目标优化 虽然 GDPO 通过按通道归一化缓解了奖励淹没问题，但不同奖励通道的学习速率、饱和动态与相关性仍随训练阶段变化。可研究**自适应通道权重**：例如，基于各奖励的近期方差或梯度贡献动态调整其重要性，或在训练过程中逐步引入更复杂的感知奖励课程，从局部属性过渡到全局构成。 --- ### 6. 自动化的设计图构建与扩展 当前设计图依赖封闭词表与手工定义的关系类型。未来可探索**从任意参考图像自动解析开放域设计图**：利用更强的视觉基础模型自动识别原子元素与容器类型，并推断隐式关系（如视觉分组、阅读顺序）。这将使 AesCode 框架更容易扩展到网页、移动应用界面、三维信息板等更广泛的视觉制品。 --- ### 7. 交互式与人机协同编辑 论文强调代码输出的核心优势在于可编辑性。可进一步研究**人在回路中的协同优化**：例如，允许用户对生成的设计图进行节点增删或属性修改，并由模型实时生成对应代码补丁；或利用设计图差异作为指令，实现局部重渲染而非全局重生成，从而提升实用部署中的迭代效率。 --- ### 8. 跨模态内容一致性保障 对于包含复杂数据叙事（如交互式仪表盘、多页幻灯片）的制品，文本、图表数据与视觉布局的一致性要求更高。未来可探索**跨模态事实一致性检查器**：在代码执行前对数据流、文本内容与视觉编码（如颜色映射、坐标轴范围）进行联合验证，防止数值或语义幻觉在渲染后才发现。

Q6: 总结一下论文的主要内容

该工作围绕信息密集型视觉制品（如幻灯片、海报、仪表盘）的代码生成展开，旨在同时实现**可验证的内容正确性**与**高水平的视觉美学质量**。 --- ### 1. 研究背景与核心问题 将视觉制品生成为代码（如 HTML/CSS）具有结构化、可编辑、可验证的优势，但代码模型无法直接观察最终渲染的画布，导致空间规划与美学质量受限。反之，图像生成器擅长视觉设计，却频繁出现文本、数据与逻辑关系的幻觉，且光栅输出不可编辑。现有图像到代码方法将参考图像视为像素级重建的真值，这在参考图像本身带有噪声时，会迫使模型复制错误并惩罚合理的设计变体。 因此，核心挑战在于：**如何让代码模型严格遵循文本提示的内容，同时灵活地从带噪声的生成参考图像中提取布局与风格灵感**。 --- ### 2. AesCode 方法框架 该工作提出 **AesCode**，通过将监督目标表示为**设计图（Design Graph）**并构建**解耦的跨模态奖励**来解决上述问题。 #### 2.1 设计图作为监督目标 目标被建模为图结构： $$G_{tgt} = (V, E, X_V, r) = \Phi(p, I_{ref})$$ 其中，节点 $V$ 表示文本、图表、容器等原子或组合元素；边 $E$ 编码包含、对齐、顺序、相邻与语义连接等关系；属性 $X_V$ 显式分离**内容属性**（如字符串、数据序列）与**视觉属性**（如边界框、颜色）。该表示使提示要求的内容约束与参考图像的视觉线索能够独立作用于互补属性，避免内容被参考图像中的噪声污染。 #### 2.2 解耦的跨模态奖励 基于设计图的可归因性，属性被分流至两类奖励通道： - **确定性验证器**：针对可从代码、DOM 或渲染像素中程序化解构的属性，包括执行成功率、必需文本匹配、画布边界合规、HTML 表格与 ECharts 图表数据结构验证、语义布局位置一致性、以及多尺度空白分布相似度。 - **视觉图评分规则（VGR）**：针对外观与高阶关系等感知型属性，从设计图派生样本特定的二元问题列表 $Q_{train}$，每个问题绑定到具体节点、边或子图。VLM 对候选渲染作答，通过率为： $$s_{vgr} = \frac{1}{|Q_{train}|} \sum_{q \in Q_{train}} \mathbb{I}\left[\hat{I} \text{ satisfies } q\right]$$ 参考图像仅通过固定问题间接进入训练，避免奖励退化为图像相似度度量。 #### 2.3 训练：GDPO 优化 在监督微调（SFT）冷启动后，采用 **Group reward-Decoupled Normalization Policy Optimization (GDPO)** 进行强化学习。对于采样组内的每条轨迹，七个奖励通道分别计算均值 $\mu_v$ 与标准差 $\sigma_v$，独立归一化优势： $$A_i^{(v)} = \frac{s_i^{(v)} - \mu_v}{\sigma_v + \epsilon}, \quad A_i = \frac{\sum_v m_i^{(v)} A_i^{(v)}}{\sum_v m_i^{(v)}}$$ 适用性掩码 $m_i^{(v)}$ 排除不相关检查，确保密集的规则奖励不会淹没稀疏的美学反馈。 #### 2.4 评估协议 最终评估将**可验证正确性（Rule）**与**视觉质量（Visual）**分离报告： - **Rule**：综合文本、边界、图表/表格的程序化验证； - **Visual**：基于提示构建样本特定的检查表，从内容完整性、布局关系与视觉风格三个维度由 VLM 评判。 --- ### 3. 实验结果 #### 3.1 主实验 在包含 300 个实例的信息图基准上，所有模型在获得生成参考图像后视觉质量均有提升。在同等参考条件下： - **AesCode-8B** 的 Visual 达到 **75.80**，较 Qwen3-VL-8B 提升 **31.1** 个百分点，Overall 从 51.93 提升至 **82.94**。 - **AesCode-32B** 的 Visual 达到 **77.44**，较 Qwen3-VL-32B 提升 **22.4** 个百分点，Overall 从 61.10 提升至 **85.89**。 AesCode-32B 的 Rule 达到 **94.33**，显著高于所有测试的闭源模型（如 GPT-5.5 的 85.90、Claude Opus 4.8 的 88.04），同时在 Visual 上与这些前沿模型处于同一水平，且内容错误更少。 #### 3.2 消融实验 - **参考条件训练**：即使在推理时移除参考图像，AesCode-8B 的 Visual 仅下降 1.00 点，远低于其骨干的 19.55 点，表明多模态视觉规划已被内化为策略能力。 - **GDPO 的有效性**：相比标量聚合的 GRPO，GDPO 提升 Visual **5.12** 个百分点，有效平衡了不同密度与尺度的奖励信号。 - **VGR 的有效性**：相比 CLIP 相似度（70.49）与整体 VLM 评分（68.91），VGR 达到最高的 **75.80** Visual，且不牺牲可验证正确性。 #### 3.3 人工评估与迁移 - 人工研究中，Visual 自动评分与人类成对偏好的**一致率为 80.66%**，在分数差距 $\geq 15\%$ 时一致率达 **93.76%**。 - AesCode-32B 在内容满足率（**86.50%**）上优于 GPT-5.5（83.47%），且美学评分与 GPT-5.5 统计等价（差异 95% CI 落在 $[-0.34, 0.03]$）。 - 在 SlidesBench、GDB/lica 与 Design2Code 三个外部基准上，AesCode-32B 较骨干在全部 14 项指标上均有提升，最大增益出现在布局、色彩与美学相关指标。 --- ### 4. 残余局限与未来方向 该工作也识别出三种残余失效模式： - **画布溢出**：代码生成难以预判最终像素几何； - **关系结构丢失**：全局时间线或层级结构需要跨元素联合推理，当前边级监督仍较稀疏； - **语义元素退化**：图标等需精细 SVG 绘制的元素缺乏内容级监督。 --- ### 5. 核心贡献总结 - **新范式**：提出利用图像生成器作为美学先验的代码生成框架，参考图像同时作为模型输入与训练信号来源。 - **设计图与解耦奖励**：通过设计图实现内容与视觉监督的显式分离，结合确定性验证器与样本特定的 VGR，实现可定位、可解释的多目标优化。 - **基准与评估**：发布分离正确性与视觉质量的信息图评估基准，证明开源模型经训练后可在人类对齐的视觉质量上匹配闭源前沿模型，同时保持更高的可验证正确性。
