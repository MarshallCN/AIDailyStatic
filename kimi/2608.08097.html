Q1: 这篇论文试图解决什么问题？

该论文旨在解决大型语言模型（LLM）推理服务中的**内存墙（memory wall）**问题，尤其是解码（decode）阶段由键值（KV）缓存引发的HBM（高带宽内存）容量与带宽瓶颈。具体而言，论文针对以下核心问题与挑战展开： ### 1. HBM容量瓶颈限制批处理规模与吞吐量 随着长上下文（long-context）和长形式推理（long-form reasoning）工作负载的普及，KV缓存在解码阶段占据了绝大部分HBM空间与内存流量。由于HBM容量稀缺且昂贵，完整的KV缓存驻留于GPU HBM会严重限制推理批大小（batch size）和系统吞吐量，使得内存而非计算成为主要瓶颈。 ### 2. 现有稀疏注意力与KV缓存管理方案的局限性 现有技术未能同时解决容量与延迟问题，各自存在明显缺陷： - **稀疏注意力（Sparse Attention）**：虽能减少KV读取量与计算，但**并未降低HBM容量需求**，仍需在HBM中保留完整KV缓存。 - **KV检索（KV Retrieval）**：将完整KV缓存卸载至容量更大、成本更低的主机内存或远程内存，但按需检索将数据传输置于解码关键路径上，直接增加每输出令牌时间（TPOT）。 - **现有KV预取（KV Prefetching）**：试图通过重叠传输隐藏延迟，但缺乏高效的生产级跨层级内存管理系统，受限于CPU-GPU或远程链路带宽，无法支撑大batch、高并发的生产级部署，且**难以支持预填充-解码（PD）分解架构**。 ### 3. PD分解场景下的跨节点KV传输与主机内存压力 在预填充-解码（PD）分解的部署模式下，现有系统通常需在解码节点DRAM中预先存放请求的**完整KV缓存**，这导致两个额外瓶颈： - ** admission延迟（TTFT）增加**：即使前缀缓存命中，仍需通过网络传输完整KV缓存，使传输时间占据TTFT主导部分。 - **解码节点DRAM容量受限**：完整KV缓存的驻留使得主机内存成为新的批处理瓶颈，限制了长上下文服务的并发能力。 ### 4. 预测精度与带宽预算的严格约束 要实现高效的跨层级KV预取，系统必须满足三项紧密耦合的要求，而现有方案往往顾此失彼： - **高精度前瞻预测**：需准确预测下一步需要的KV块，避免预取缺失导致回退到高延迟的按需读取。 - **低开销预测机制**：预测过程本身不能引入显著计算开销或额外的完整前向传播。 - **严格的跨层级流量约束**：每步预取的数据量必须受限于PCIe或网络带宽与解码步长的乘积，否则传输本身将拖慢解码。 ### OasisKV的目标 基于上述问题，论文提出**OasisKV**，其核心目标是： - **将完整KV缓存与HBM解耦**，仅在GPU HBM中保留每步最相关的稀疏KV工作集； - **利用推测解码（Speculative Decoding）生成的lookahead token**作为训练无关（training-free）信号，准确前瞻预测未来重要KV块； - **通过全异步后台流水线**将预测、选择与预取操作与解码前向传播重叠，隐藏跨层级传输延迟； - **将稀疏预取扩展至PD分解场景**，通过远程部分获取（Remote Partial Fetching）减少网络传输量与解码节点DRAM占用，从而在保持接近全注意力精度的同时，显著提升解码吞吐量并降低内存成本。

Q2: 有哪些相关研究？

围绕 OasisKV 所解决的问题，论文在背景与相关工作章节中系统性地回顾了以下五大类研究，并分析了各自的能力边界与局限性： --- ### 1. 稀疏注意力机制（Sparse Attention） 这类方法利用注意力分数的偏斜性，仅对历史 token 的一个子集进行完整注意力计算，以降低每步解码的计算量与 KV 读取量。 - **代表性工作**：NSA [42]、DSA [5]、Quest [31]、MInference [11]、SeerAttention [8]、FlexPrefill [13]、Attention Sinks [37]。 - **核心局限**：它们主要优化计算与 HBM 带宽，但**并未减少 HBM 容量占用**——完整 KV 缓存仍需常驻 GPU 内存，因此无法缓解长上下文下的批处理（batching）瓶颈。 --- ### 2. KV 检索与层级缓存系统（KV Retrieval / Hierarchical KV） 这类系统将完整 KV 缓存卸载到容量更大、成本更低的 CPU DRAM 或 SSD，仅在 GPU HBM 中保留当前步需要的活跃子集。 - **代表性工作**：ArkVale [2]、RetroInfer [3]、HiSparse [45]、ShadowKV [30]、KVDrive [17]。 - **核心局限**：非 resident KV 块的按需检索（on-demand retrieval）被置于解码关键路径上，检索延迟直接增加每输出 token 时间（TPOT）。现有系统通常依靠极小的检索预算或微批流水线来缓解延迟，但难以支撑生产级大 batch 部署。 --- ### 3. KV 预取方法（KV Prefetching） 这类方法试图提前预测下一步需要的 KV 块，并通过与计算重叠来隐藏跨层级传输延迟。论文将其细分为三个子类： | 子类 | 思路 | 代表性工作 | 局限性 | |------|------|------------|--------| | **学习型预测器** | 训练专门的稀疏注意力或前瞻索引模块 | SparDA [7]、FlashMemory-DeepSeek-V4 [34] | 需要模型特定的预测器训练，绑定特定模型架构 | | **架构绑定型** | 复用原生稀疏注意力模型已有的索引器 | ECHO [19] | 不训练独立预取器，但仍受限于特定稀疏注意力架构 | | **无训练（Training-free）** | 利用推理时的运行时信号（如低精度 KV、前层预演、历史查询相似度）进行预测 | SpeCache [12]、InfiniGen [14]、FreeKV [20] | 避免了训练开销，但预测精度有限，常需配合纠正性按需读取，难以在生产引擎中实现高吞吐 | 论文指出，上述预取设计普遍缺乏一个**生产级的跨层级内存管理器**，无法协调 GPU HBM、主机 DRAM 与远程内存之间的稀疏 KV 放置与传输，因而难以支持高吞吐的 PD 分解服务。 --- ### 4. 生产级推理引擎与内存管理（Inference Engines & Memory Management） 现代服务引擎将 KV 内存管理作为核心运行时功能，并提供了一定的卸载机制以扩展有效 KV 工作集。 - **代表性工作**：vLLM（含 KV offloading）[32]、SGLang / HiCache [28]。 - **核心局限**：这些机制主要用于多轮对话中的前缀复用；当上下文较长时，解码关键路径上仍需将请求的**完整 KV 缓存**迁回 GPU HBM，因此单卡最大批大小 $B_{\max}$ 仍受公式 $$B_{\max} = \left\lfloor \frac{M_{\text{HBM}}}{L \cdot N_{\text{layer}} \cdot 2 N_{\text{kv}} d_h \cdot s} \right\rfloor$$ 的线性约束，无法根本突破 HBM 容量墙。 --- ### 5. 预填充-解码（PD）分解与跨节点服务（PD Disaggregation） 为优化吞吐与资源利用，这类研究将预填充（prefill）与解码（decode）阶段拆分到不同节点。 - **代表性工作**：Splitwise [24]、DistServe [46]、Mooncake [26]、DualPath [36]。 - **核心局限**：在分解架构下，现有系统通常需在解码节点的主机 DRAM 中**预存请求的完整 KV 缓存**。这导致： - **Admission 延迟（TTFT）增加**：即使前缀缓存命中，仍需通过网络突发传输完整 KV； - **主机内存瓶颈**：完整缓存的驻留使 DRAM 成为新的并发瓶颈，限制了长上下文服务的可扩展性。 --- ### 6. 推测解码与多 Token 预测（Speculative Decoding） OasisKV 直接复用了这一方向的技术作为**前瞻信号来源**。 - **代表性工作**：标准 Speculative Decoding [15]、EAGLE-3 [16]、AngelSpec [21]。 - **与 OasisKV 的关系**：这些技术通过 draft 模型或小号预测头一次性生成多个未来 token。OasisKV 利用这些 draft token 作为**免训练的、高准确度的前瞻信号**，预测未来 KV 访问模式，从而驱动异步稀疏预取，而无需额外训练专门的预测器。

Q3: 论文如何解决这个问题？

OasisKV 将问题拆解为**准确前瞻预测**、**高并发稀疏服务**、**跨网络稀疏 staging**三个层面，通过以下机制联合求解： --- ## 1. 核心设计思想 OasisKV 将完整 KV 缓存卸载至容量更大、成本更低的 CPU DRAM（单节点）或远程内存（PD 分解），仅在 GPU HBM 中维持一个**固定大小的稀疏工作集**（例如 2,048 tokens）。为了在不阻塞解码的前提下，提前知道下一步需要哪些 KV 块，系统复用推测解码（Speculative Decoding, SD）已生成的 **draft token** 作为免费的前瞻信号，通过轻量级注意力计算预测未来访问模式，并在后台异步预取缺失块。 --- ## 2. Look-ahead Attention：准确且低开销的前瞻预测 ### 2.1 利用 Draft Token 作为训练无关信号 现有方法要么需要训练专用预测器，要么用历史 query 做代理导致精度不足。OasisKV 观察到：将 SD 产生的 draft token 送入当前层的** resident sparse KV**，其预测出的 top-$K$ 重要块与真实下一步 query 的 top-$K$ 集合在层间平均 agreement 超过 $98.74\%$（图 6）。因此，draft token 提供了一个**无需额外训练**、**高准确度**的未来访问信号。 ### 2.2 压缩键摘要支持全局排序 为了对**非 resident** 的块进行排序而不取回完整键，OasisKV 为每个逻辑块维护压缩摘要（例如 Quest 风格的 coordinate-wise min/max pooling）。每块仅需 2 个向量，仅占完整 KV 的 $1/16$ 容量。Draft query 扫描这些摘要即可完成全局 top-$K$ 排名，无需恢复任何被忽略的键。 ### 2.3 前景共享执行，零额外前向传播 在每个 Transformer 层，正常 token $q_t$ 与 draft token $q_{t+1}$ 的 QKV 投影合并计算；Attention kernel 一次性接收堆叠的 query $\{q_t^l; q_{t+1}^l\}$，在相同的 resident sparse KV 上完成注意力，并同时输出两个结果。Draft query 随后驱动 top-$K$ 预测，整个前景过程**不增加第二次前向传播**，权重读取和 KV 读取均为共享。 --- ## 3. 全异步后台预取流水线：隐藏跨层级延迟 预测结果必须转化为物理传输，并与极短的生产级解码步长重叠。OasisKV 设计了层间解耦的三阶段流水线： $$ \text{Top-}K\text{ 预测} \rightarrow \text{KV 选择} \rightarrow \text{KV 传输} $$ - **层间并发**：各层状态独立，允许层 $l+1$ 的预测、层 $l$ 的选择、层 $l-1$ 的传输**同时执行**。 - **流隔离与事件同步**：Top-$K$ 预测、KV 选择、KV 传输分别跑在独立后台 CUDA stream 上；前景 Attention/FFN 跑在默认 stream。CUDA event 仅保证**同层内**三阶段的顺序依赖。 - **局部同步**：在 $t+1$ 步执行层 $l$ 的 attention 前，前景只需等待该层在 $t$ 步发出的 KV 传输完成，无需等待其他层。这让早期层可以“先跑起来”，最大化与后台传输的重叠。 流水线填充后的稳态间隔由最慢阶段决定： $$ T_{\text{pipe}} = \max\{T_{\text{pred}}^l, T_{\text{select}}^l, T_{\text{transfer}}^l\} \le \Delta_{\text{prefetch}} $$ --- ## 4. Delta Selection 与 Capped Eviction：严格约束每步流量 PCIe 或网络带宽远低于 HBM 带宽，无限制地传输所有新预测的块会迅速突破解码步长的字节预算 $C_{\text{token}} = B_{\text{link}} \cdot T_{\text{decode}}$。OasisKV 在 KV 选择阶段实施**有上限的淘汰策略**： 1. **Delta 交集**：预测集与当前 resident 集取交集，已驻留块不产生任何传输。 2. **LRU 淘汰**：对 resident 但未被预测命中的块，按最近被选择的步数排序，淘汰最久未使用的块。 3. **每步准入上限**：对每个 KV head，每步最多准入 $C$ 个新块（或通过 fetch ratio 限制），其余预测块留待后续步骤。这保证了每步传输量被硬上限约束，即使 top-$K$ 集合发生较大漂移，也不会压垮慢速链路。 该机制将稀疏预取从“带宽不可控”转化为“带宽有界”，使得系统可在生产引擎的大 batch 下稳定运行。 --- ## 5. Head-wise KV 管理与统一调度 生产引擎（如 vLLM）的 PagedAttention 假设每页包含所有 KV head 的同一连续 token 区间，而稀疏注意力要求**不同 head 保留不同的历史块**。OasisKV 在不修改原有页表的前提下，增加一层 **head-wise logical-to-logical 映射**： - GPU 与 CPU 各自保留原有的 logical-to-physical 页表。 - 对每个 KV head，新增映射表记录每个 GPU 逻辑块对应哪个 CPU 逻辑块。 - 更新 top-$K$ 时，只需修改映射表项和 GPU 物理页内容；不同 GPU（张量并行下）独立更新本地 head，无需跨 GPU 同步。 此外，被选中的 key/value 块在内存中保持与 dense attention 兼容的 **Head-Token-Dimension** 布局，因此 FlashAttention 等高度优化的 kernel 可直接处理稀疏工作集，无需专用稀疏 kernel 路径。 请求生命周期分为两阶段： - **Dense 阶段**：上下文较小时，按标准 PagedAttention 增长。 - **Sparse 阶段**：超过阈值后，完整 KV 拷贝至 CPU，GPU 仅保留选中历史块与局部窗口，通过 head-wise 映射接入统一 batch。 --- ## 6. Remote Partial Fetching：将稀疏预取扩展至 PD 分解 在预填充-解码（PD）分解架构下，传统做法需将**完整 KV 缓存**通过网络搬至解码节点 DRAM，既拖慢 TTFT，又使主机内存成为新瓶颈。OasisKV 将 look-ahead 机制延伸至跨网络场景： ### 6.1 Partial Transfer（准入阶段稀疏传输） Prefill 节点在常规 prefill 后**额外执行一步解码**，得到首生成 token 的 query，据此选出首步 top-$K$ 块。跨网络传输的内容仅为： - 首步各 head 选中 KV 块的并集； - 压缩键缓存； - Draft token 的 KV 状态。 这避免了完整 KV 的突发传输。例如 24K 上下文中，每请求传输量从 3.37 GiB 降至 0.52 GiB，减少约 $6.5\times$。 ### 6.2 Network Prefetch at Decode（解码时网络预取） 随着解码进行，top-$K$ 漂移可能导致解码节点缺失某些块。OasisKV 将其视为缓存缺失，通过后台流水线从 prefill 节点的 staging pool 远程读取到解码节点 DRAM，再 gather 入 GPU HBM： - 远程读取与前景 attention 重叠； - 同 batch 内跨请求的缺失块按层聚合，摊销网络开销； - 解码节点 resident 集**单调增长**，每个块最多跨网络一次；从未被选中的块永不传输。 这使得网络流量被分散到整个解码过程中，而非集中在准入瞬间。结合 fetch cap（如 0.05 ratio），总传输量可比 full transfer 再降低 $1.9\times$–$2.2\times$，同时解码节点 DRAM 占用降低 $2.2\times$–$2.6\times$。 --- ## 7. 设计需求与解决方案的对应关系 | 设计需求 | OasisKV 的解决机制 | |---------|------------------| | **准确前瞻，脱离关键路径** | 复用 SD draft token 做 look-ahead attention；压缩键摘要全局排序；共享 QKV/Attention 执行，零额外前向传播 | | **生产级稀疏服务** | Head-wise 映射兼容 PagedAttention；Delta Selection + Capped Eviction 硬约束 PCIe 流量；全异步三阶段流水线隐藏延迟 | | **跨网络稀疏 staging** | Partial Transfer 仅送首步工作集；Network Prefetch 按需拉取后续块，流量分散且单调有界；显著降低 TTFT 与解码节点 DRAM | 通过上述机制，OasisKV 将 KV 缓存的存储与计算解耦，把“稀疏注意力节省的 HBM 容量”真正转化为“更大的 batch 和更高的吞吐”，同时在

Q4: 论文做了哪些实验？

论文在第 5 章进行了系统的实验评估，涵盖实现细节、实验设置、系统性能、准确率对比以及消融研究。具体实验内容如下： --- ### 1. 实验设置 #### 1.1 测试平台 - **单节点**：配备 8 张 NVIDIA H100 80 GB HBM3 GPU，双路 Intel Xeon Platinum 8480C（共 112 核），2 TB 主机内存；GPU 间通过 NVLink/NVSwitch 互联，每张 GPU 经 PCIe Gen5 ×16 连接本地 CPU socket。 - **PD 分解场景**：使用两台相同规格的服务器，通过 NVIDIA ConnectX-7 400 Gbps RoCE 网络互联。 #### 1.2 模型与 Draft 模型 - **Qwen3-8B**、**Qwen3-235B-A22B（MoE）**、**Llama-3.1-8B-Instruct**。 - 对应 EAGLE-3 draft 模型分别采用公开版本。 - Qwen3 使用思考模式（temperature=0.6, top-$p$=0.95, top-$k$=20），其余使用贪心解码。 #### 1.3 工作负载 - **准确率评测**： - 数学推理：AIME24、AIME25； - 科学推理：GPQA-Diamond； - 长上下文理解：LongBench v2（分 short/medium/long 三个子集）。 - **性能评测**：合成负载（扫描输入长度与并发度）以及真实 AIME24 请求端到端测试。 #### 1.4 基线与配置 - **系统性能基线**：Dense vLLM（FlashAttention-3）、ShadowKV、InfiniGen、FreeKV。 - Q5: 有什么可以进一步探索的点？

基于论文的设计选择与实验结果，以下是可以进一步探索的研究与工程方向： --- ### 1. 将 Lookahead 预取与投机解码（SD）完全融合 当前 OasisKV 仅将 draft token 作为**预取信号**使用，并在前景中**强制拒绝**该 draft。论文明确指出，未来的关键一步是允许 draft token 被**正式接受**，从而将预取开销与投机加速的收益叠加。这涉及： - 联合优化 draft model 的接受率与预取预测精度； - 设计接受-拒绝机制与预取流水线之间的状态一致性协议，避免已预取但 draft 被拒绝的 KV 块造成内存碎片。 --- ### 2. 向更多层级的存储体系扩展 原型将完整 KV 缓存保留在 prefill 节点的 host DRAM 中直到请求结束。论文提到，这一 staging pool 可进一步扩展至**远程内存服务器**或 **SSD/存储级内存**。可探索的方向包括： - 结合 NVMe-oF、CXL 或 RDMA 内存池，构建真正的内存分解架构； - 设计基于访问频率的分层淘汰策略，将冷 KV 块下沉到更低速存储，而热块保留在本地 DRAM 或 HBM； - 在极长上下文（如 100K+）场景下，评估 SSD 作为 backing store 时的尾延迟与带宽模型。 --- ### 3. 模型-系统协同设计的稀疏注意力 论文结论指出 OasisKV 开启了 KV-cache 稀疏性、长上下文能力与内存硬件协同设计的新空间。未来可探索： - **可学习的稀疏模式**：在训练阶段引入稀疏性目标，使模型天然产生更稳定、更易预测的块级访问模式，从而降低预取缺失率； - **层自适应预算**：当前每层的 $K$ 值大致固定，但不同层对上下文的依赖强度不同。可探索按层动态分配 KV 预算（如浅层保留更多全局上下文，深层聚焦局部推理），在不增加总 HBM 占用的前提下提升精度； - **多模态与 MoE 扩展**：将 lookahead 稀疏预取推广到多模态序列（图像、视频 token）以及专家并行（EP）场景，处理非均匀 KV 访问。 --- ### 4. 与 KV 量化、低秩压缩正交结合 OasisKV 目前通过**稀疏化**减少容量与带宽，尚未与量化（INT8/INT4）、低秩近似（如 ShadowKV 的 low-rank key）或值共享结合。两者是正交的： - 对预取到的块采用低精度存储，可进一步压缩 PCIe/网络传输量； - 在压缩键摘要（compressed key）上使用更激进的量化，以极小的精度代价换取更大的摘要容量或更快的扫描速度； - 研究量化后的稀疏注意力内核联合优化，降低计算与内存带宽的双重压力。 --- ### 5. 前缀缓存（Prefix Caching）与远程部分获取的联合优化 论文在分析（图 15）中展示了 RPF 在高前缀缓存命中率下对 TTFT 的显著加速潜力，但原型尚未集成该功能。后续工作可探索： - 在 PD 分解架构下，前缀命中的请求仅需传输未缓存的后缀 KV，RPF 的准入传输量可进一步降低； - 设计跨请求的**全局 KV 块去重**，使多个请求共享前缀块的网络传输与解码节点 DRAM 驻留； - 针对 Agent 工作流中反复出现的工具调用、系统提示等长前缀，构建持久的跨请求 resident KV 工作集。 --- ### 6. 异构内存与 CXL 硬件的利用 随着 CXL 等内存扩展技术的成熟，CPU-GPU 内存层次正在模糊。可探索： - 利用 CXL 内存池替代传统 PCIe+DRAM 作为 KV 缓存的 backing store，测试其实际带宽与延迟对预取窗口的影响； - 在 CXL 2.0/3.0 的内存共享语义下，实现 prefill 与 decode 节点对同一物理内存的直接访问，消除显式网络预取； - 评估 GPU 直连 CXL 内存（而非通过 CPU）对 look-ahead attention 摘要扫描与 KV 传输的加速效果。 --- ### 7. 更智能的缓存淘汰与准入策略 当前采用基于 LRU 的 capped eviction，未来可研究： - **注意力感知的淘汰**：利用历史注意力分数的衰减规律，预测当前 resident 块在未来多步内的复用概率，替代简单的最近使用假设； - **请求级服务质量（QoS）感知**：对延迟敏感的小 batch 请求保留更完整的 KV，而对吞吐优先的大 batch 请求采用更激进的稀疏策略； - **预取预算的动态反馈控制**：根据实时 PCIe/网络带宽利用率与流水线 backpressure，在线调整 fetch ratio，而非固定配置。 --- ### 8. 大规模分布式与多租户调度 论文的多 GPU 实验集中于张量并行（TP）。在更大规模的流水线并行（PP）或专家并行（EP）部署中： - 跨节点的 KV 预取需要与 PP 的 micro-batch 调度协同，避免预取与计算争用网络带宽； - 在多租户场景下，不同请求的上下文长度、稀疏预算与 draft 开销差异巨大，需要新的调度算法来 pack 请求，最大化全局 GPU 利用率与内存复用。

Q6: 总结一下论文的主要内容

该论文提出了 **OasisKV**，一种面向生产环境的内存中心式 LLM 推理系统，通过**前瞻稀疏预取（lookahead sparse prefetching）**将解码（decode）阶段的完整 KV 缓存从昂贵的 GPU HBM 解耦到更大容量的 CPU 或远程内存，从而在保持精度的同时显著提升吞吐量并降低内存占用。 --- ### 1. 研究背景与问题 现代 LLM 推理的瓶颈已从计算转向内存。在自回归解码阶段，每个生成步都需要访问所有历史 token 的 KV 缓存，其存储开销随序列长度线性增长： $$M_{\text{KV}}(B, L) = B \cdot L \cdot N_{\text{layer}} \cdot 2N_{\text{kv}}d_h \cdot s$$ 这导致单卡最大批大小被 HBM 容量严格限制： $$B_{\max} = \left\lfloor \frac{M_{\text{HBM}}}{L \cdot N_{\text{layer}} \cdot 2N_{\text{kv}}d_h \cdot s} \right\rfloor$$ 现有三类方法均存在关键缺陷： - **稀疏注意力**：减少计算与 HBM 带宽，但**不减少 HBM 容量**占用； - **KV 检索**：将完整 KV 卸载到 CPU/远程内存，但按需读取位于解码关键路径，直接增加 TPOT； - **KV 预取**：试图重叠传输与计算，但缺乏生产级跨层级内存管理，难以支撑大 batch 与 PD 分解。 此外，在**预填充-解码（PD）分解**架构下，将完整 KV 缓存传输到解码节点会大幅增加首 token 时间（TTFT）并耗尽解码端主机内存。 --- ### 2. 核心设计思想 OasisKV 的关键洞察是：**推测解码（Speculative Decoding, SD）生成的 draft token 可作为高质量、免训练的前瞻信号**。具体而言： 1. **利用 draft token 预测未来**：将 draft token 送入当前层的稀疏 KV 工作集，可高精度（平均 $98.74\%$）预测下一步真正需要的 top-$K$ KV 块； 2. **异步重叠传输**：在后台流水线中完成 top-$K$ 预测、块选择与跨层级传输，与前景解码计算完全重叠； 3. **带宽有界操作**：通过每步准入上限（capped eviction）将 PCIe/网络流量硬约束在解码步长可隐藏的字节预算内： $$C_{\text{token}} = B_{\text{link}} \cdot T_{\text{decode}}$$ --- ### 3. 关键技术机制 #### 3.1 Look-ahead Attention - **共享前景执行**：正常 token $q_t$ 与 draft token $q_{t+1}$ 的 QKV 投影与注意力核函数合并计算，不增加额外前向传播； - **压缩键摘要**：为每个逻辑块维护轻量级 min/max pooling 摘要（仅占完整 KV 的 $1/16$），使 draft query 能对**全局长上下文**进行块级排序，无需取回非驻留键。 #### 3.2 全异步后台预取流水线 将预测-选择-传输三阶段按层解耦到独立 CUDA 流，通过层间并发与 CUDA 事件同步实现： - 层 $l+1$ 的预测、层 $l$ 的选择、层 $l-1$ 的传输同时执行； - 前景仅等待同层上一个 step 的传输完成即可开始该层注意力，最大化重叠。 稳态流水线间隔由最慢阶段决定： $$T_{\text{pipe}} = \max\{T_{\text{pred}}^l, T_{\text{select}}^l, T_{\text{transfer}}^l\} \le \Delta_{\text{prefetch}}$$ #### 3.3 Delta Selection 与 Capped Eviction - **Delta 交集**：已驻留块无需传输； - **LRU 淘汰**：对未被预测命中的驻留块按最近选择步数淘汰； - **每步准入上限**：每 head 每步最多准入 $C$ 个新块（或通过 fetch ratio 限制），确保慢速链路带宽不被压垮。 #### 3.4 Head-wise KV 管理 在 vLLM PagedAttention 之上增加一层 **head-wise logical-to-logical 映射**，使不同 KV head 可保留不同的稀疏块集合，而无需修改底层页表，天然兼容张量并行。 #### 3.5 Remote Partial Fetching（RPF） 针对 PD 分解： - **Partial Transfer**：prefill 节点额外执行一步解码，计算首 token query 并仅传输首步 top-$K$ 块的并集、压缩键缓存及 draft KV 状态，避免完整 KV 突发传输； - **Decode-time Network Prefetch**：后续漂移缺失的块通过后台流水线从 prefill 节点按需拉取，流量分散到整个解码过程，且每个块最多跨网络一次。 --- ### 4. 实验结果 实验在 8×H100 集群上进行，覆盖 Qwen3-8B、Qwen3-235B-A22B（MoE）及 Llama-3.1-8B，对比 Dense vLLM、ShadowKV、InfiniGen、FreeKV 等基线。 #### 4.1 系统性能 - **单 GPU**：在 16K/32K 上下文、并发度 128 时，OasisKV 相比 dense vLLM 分别实现 **2.1×** 与 **2.4×** 的解码吞吐提升；并发容纳能力从约 22 提升至 90–95。 - **多 GPU（TP8）**：Qwen3-235B 在 16K/32K 时最高提升 **1.9×** 与 **2.1×**。 - **PD 分解**：吞吐达到 dense 的 **2.1–2.3×**；解码节点主机内存降低 **2.2–2.6×**；准入阶段 KV 传输量降低 **6.5–9.7×**。 #### 4.2 准确率 在 2,048-token KV 预算约束下： - 长上下文（LongBench v2）：精度损失通常在 **0.4–0.6** 个百分点； - 长输出推理（AIME24/25、GPQA-Diamond）：平均 pass@$k$ 损失 **0.66** 个百分点，avg@$k$ 损失 **0.35** 个百分点，显著优于 Quest 与 FreeKV。 #### 4.3 消融研究 - **Fetch Cap**：Qwen3-8B 上 fetch ratio=0.05 时，以仅 0.1 个百分点的精度损失换取 **2.5×** 于无 cap 配置的吞吐（2,083 vs. 824 tok/s），是最优操作点； - **RPF 流量分布**：将网络突发传输转化为平滑的持续流量，显著降低峰值带宽压力。 --- ### 5. 主要贡献 - **框架设计**：提出首个将前瞻稀疏预取、推测解码与生产级跨层级内存管理统一的系统，把稀疏注意力节省的 HBM 容量真正转化为吞吐增益； - **系统实现**：基于 vLLM 实现原型，支持多 GPU 张量并行与 PD 分解，兼容现有推测解码生态； - **广泛验证**：在单 GPU、多 GPU、PD 分解及真实推理负载上验证，证明在 0.7 个百分点以内的精度损失下，可实现最高 **2.4×** 的解码吞吐提升，并将解码节点内存占用降低 **2.6×**。
