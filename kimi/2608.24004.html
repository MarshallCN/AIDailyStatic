Q1: 这篇论文试图解决什么问题？

这篇论文旨在解决**大批量（batch inference）场景下，基于大语言模型（LLM）的Agent应用在使用投机解码（Speculative Decoding）时加速效果严重退化**的问题。 具体而言，现有投机解码方法虽然在单机单请求（小批量）场景下能够显著降低解码延迟，但在现代LLM服务引擎普遍采用的大批量推理模式下，其加速比会急剧下降，甚至退化为比标准自回归解码更慢。针对这一核心问题，论文通过系统性分析识别出导致性能退化的两个关键瓶颈： - **投机Token拒绝率过高**：现有方法在面向Agent工作负载时，生成的草稿Token被目标模型拒绝的比例极高（例如部分基线方法拒绝率超过50%甚至85%）。随着Batch Size增大，验证这些被拒绝Token带来的计算开销迅速膨胀，直接抵消了接受Token所节省的时间，导致整体收益为负。论文将单步执行时间节省建模为： $$\Delta T(b) \approx D(b) \left[(1-\rho(b))t_A - t_V(b)\right]$$ 其中高拒绝率 $\rho(b)$ 使得 $(1-\rho(b))t_A$ 显著降低，是性能退化的首要因素。 - **动态Token预算利用不足**：随着Batch Size $b$ 增加，FFN层延迟线性增长，可用的投机Token预算 $M(b)$ 动态收缩。然而，现有方法或采用均匀分配，或基于全局接受率进行粗粒度预算控制，无法根据各请求的历史生成特征精确分配草稿长度，导致大量动态空闲预算未被有效利用，进一步限制了加速空间。 为应对上述挑战，论文提出了 **AgentSpec**，一种专为LLM Agent大批量推理设计的无草稿模型（draft-model-free）投机解码算法，通过**结构隔离草拟（Structure-Isolated Drafting）**与**冗余感知预算分配（Redundancy-Aware Budget Allocation）**两个核心机制，实现极低的Token拒绝率与高效的动态预算利用。

Q2: 有哪些相关研究？

根据论文第2节，相关研究主要集中在以下两个方向： ### 1. LLM Agent 效率优化 为缓解 LLM Agent 因多步推理、工具调用和环境交互带来的高推理成本，现有研究主要从两个层面展开： - **减少模型调用次数** - **LEAP** (Verma and Bharadwaj, 2025)：采用前瞻规划（look-ahead planning）以避免执行无效动作，从而减少不必要的模型调用。 - **Efficient Agents** (Wang et al., 2025)：通过优化任务分解与动作选择策略，以更少的执行步数完成任务。 - **缓存与重用中间结果** - **APC** (Zhang et al., 2025)：在语义相似的任务之间复用高层计划，以摊销规划开销。 这些 Agent 级优化方法虽能显著降低开销，但可能牺牲生成质量，而论文关注的投机解码属于**无损加速**技术。 ### 2. 投机解码（Speculative Decoding） 投机解码通过草稿 Token 的投机生成与目标模型验证来降低解码延迟，相关方法可分为三类： - **基于草稿模型的方法** - **EAGLE-3** (Li et al., 2025)：训练轻量级草稿模型提出投机 Token。 - **多 Token 预测（MTP）** (Xia et al., 2025; DeepSeek-AI, 2024)：在预训练阶段联合训练 MTP 模块作为草稿模型。 - **无草稿模型方法（基于历史检索）** - **NGram** (Saxena, 2023)：通过匹配 n-gram 模式从历史生成中构造草稿续写。 - **SuffixDecoding** (Oliaro et al., 2025)：基于后缀匹配检索候选 Token，消除草稿模型推理开销。 - **系统级优化** - **SpecInfer** (Miao et al., 2023)：结合投机推理与 Token 树验证。 - **AdaSpec** (Huang et al., 2026)：建模投机低效性以满足 SLO 约束。 - **SPIRe** (Neelam et al., 2025)：根据在线性能反馈自适应调整投机解码策略。 - **MagicDec** (Sadhukhan et al., 2025)：针对长上下文场景提升吞吐。 - **TETRIS** (Wu et al., 2025)：针对批次投机解码的最优草稿 Token 选择。 现有工作的主要局限在于：大多只在小批量（small-batch）场景下取得显著加速，忽视了批次级接受率的方差，或依赖全局接受统计，导致在大批量（large-batch）推理场景下加速效果严重退化甚至劣于标准自回归解码。

Q3: 论文如何解决这个问题？

论文提出 **AgentSpec**，一种面向 LLM Agent 大批量推理的无草稿模型（draft-model-free）投机解码算法。该方案通过两个核心组件协同解决前述瓶颈： --- ### 1. 总体架构 AgentSpec 要求 Agent 应用在提交生成请求时，额外提供**语义结构标识符**（semantic structure identifier），使服务系统能够按 Agent 特定的执行结构组织与检索历史上下文。其核心流程如下： - **草拟阶段**：仅在与当前请求属于同一语义分组的历史片段中检索草稿候选，避免跨结构不匹配上下文的投机。 - **验证前阶段**：结合局部草稿信息与全局生成历史，为批次内每个请求计算综合冗余值，并据此分配投机 Token 预算。 --- ### 2. 结构隔离草拟（Structure-Isolated Drafting） #### 动机 LLM Agent 工作负载的一个关键特征是：单条用户查询往往跨越多个语义块（semantic blocks），例如推理、工具调用、结果解释等。论文对 Qwen-3-8B 在 Reflexion 代码生成 Agent 上的轨迹分析表明，重复 Token 片段**绝大多数发生在同一查询的同一语义块内部**，而跨块或跨查询的重复极为稀少。现有方法（如 NGram 和 SuffixDecoding）从全局生成历史中检索草稿，无视语义边界，导致大量草稿因语义偏移而被拒绝。 #### 关键设计 AgentSpec 要求每个生成请求 $r_i$ 携带语义结构标识符： $$S_i = \{a_i, q_i, B_i\}$$ 其中 $a_i$ 为 Agent 应用标识，$q_i$ 为触发当前请求的用户查询索引，$B_i = [b_i^1, b_i^2, \dots, b_i^n]$ 为由起始/结束字符串标签定义的语义块列表。 由于子词分词导致 Token 边界与字符串边界不对齐，直接转换开销较高。为此，AgentSpec 维护一个缓存的 **Token-to-String 映射** $M$，并基于该映射为每个 $(a_i, q_i)$ 维护一个轻量级的基于字符串的**下推自动机（PDA）** $P$。新生成的 Token 经 $M$ 转换后增量输入 $P(a_i, q_i)$，实时追踪当前所处的语义块 $b_i^k$。系统随后仅在对应的结构隔离缓存 $H(a_i, q_i, b_i^k)$ 中检索草稿候选，从而避免向不相关语义路径投机。 #### 效果 如论文表1所示，该机制将拒绝率降至 **26.4%**，较现有基线（EAGLE-3 为 53.3%，NGram 为 88.7%，SuffixDecoding 为 65.9%）降低超过 **50%**。 --- ### 3. 冗余感知预算分配（Redundancy-Aware Budget Allocation） #### 动机 在大批量推理中，可用于投机的动态 Token 预算随 Batch Size 增加而收缩。现有方法要么均匀分配预算，要么基于粗粒度的全局接受率进行分配，导致预算利用低效。论文观察到，Agent 工作负载中不同请求的生成历史冗余度差异显著，而冗余度与草稿接受率之间存在强正相关：历史模式重复度越高的请求，其草稿越可能被接受。 #### 关键设计 AgentSpec 引入**冗余分数** $g$ 来估计每份草稿的接受似然： $$g(c, n) = \frac{c}{n \cdot p(n)}$$ 其中 $n$ 为从同语义块、同用户查询历史中检索到的候选续写数量，$c$ 为与最频繁前缀达成一致的续写数量。饱和项 $p(n)$ 定义为： $$p(n) = g_{\min} + (1 - g_{\min})(1 - e^{1-n})$$ 该函数在 $n$ 较小时压低置信度，防止不可靠估计主导分配；$g_{\min}$ 控制低支持度场景下的最小置信度。 基于冗余分数，批次级总投机预算设为： $$B_t = \left\lfloor \frac{\alpha}{b_z} \right\rfloor$$ 其中 $b_z$ 为当前 Batch Size，$\alpha$ 为全局预算系数。 对于每个请求 $r_i$，设其最频繁续写前缀为 $C_{T_i}^*$，对应冗余分数为 $g_i$，则其草稿长度分配为： $$L_i = \max\left(|C_{T_i}^*|, B_t \cdot \frac{g_i}{\sum_j g_j}\right)$$ 该公式优先向高冗余请求倾斜预算，同时保证每个请求至少能草拟其最自信的前缀长度。 #### 效果 如图3所示，AgentSpec 的总草稿 Token 数始终低于可用最大预算 $M(b)$，且随 Batch Size 增大逐渐逼近该预算上限，表明动态预算被高效利用；而现有方法（包括基于接受率的 AdaSpec 策略）则严重偏离预算曲线，利用率低下。 --- ### 4. 协同效应 通过**结构隔离草拟**将拒绝率降至极低水平，AgentSpec 大幅削减了大批量场景下的验证开销；通过**冗余感知预算分配**，系统进一步将有限的动态 Token 预算精准分配给高接受潜力的请求。两者结合使 AgentSpec 在 Batch Size 高达 256 乃至更大时，仍能保持对标准自回归解码的加速，最高可达 **2.02×** 加速比，而现有方法在此场景下普遍发生速度退化甚至劣于基线。

Q4: 论文做了哪些实验？

论文围绕 AgentSpec 开展了系统性的实验评估，涵盖端到端效率对比、多工作负载泛化性分析、消融实验及延迟拆解等多个维度。具体实验内容如下： --- ### 1. 实验设置 **对比基线** - **基于草稿模型的投机解码**：EAGLE-3、MTP（Multi-Token Prediction） - **无草稿模型的投机解码**：NGram、SuffixDecoding - **标准自回归解码**（Normal） **模型** 覆盖 4 个不同 LLM 家族的 4 个模型： - Qwen-3-8B - GPT-OSS-20B - DeepSeek-R1-Distill-Llama-8B（简称 DSK-Distill-8B） - MiMo-7B **工作负载与数据集** - **基于工作流的 Agent 工作负载** - Code Generation Agent：基于 Reflexion 框架，在 USACO 数据集（含 Bronze、Silver、Gold、Platinum 四个难度子集）上评估 - Deep Research Agent：基于 LangChain DeepResearch 框架，在 DeepResearch-Bench 上评估 - **基于模型的 Agent 基准** - GAIA（在 OpenHands 平台上运行） - SWE-Bench-Lite - **非 Agent 工作负载** - Spec-Bench（用于验证在通用场景下的有效性） **评测指标** - **Goodput**：总生成 Token 数除以整个工作负载的执行时间（tokens/sec） - **Speedup**：相对于标准自回归解码的 Goodput 加速比 - **Latency**：从用户查询进入 Agent 环境到最终响应返回的端到端执行时间 **实现环境** - 在 vLLM v0.12.0 V1 引擎中实现 - NVIDIA A100 80G GPU（附录补充了 H100 结果） - 默认最大 Batch Size 为 256 --- ### 2. 端到端效率对比（5.2） 在 4 个 Agent 工作负载（Deep Research、Code Generation、GAIA、SWE-Bench）和 3 个模型（Qwen-3-8B、GPT-OSS-20B、DSK-Distill-8B）上进行全面对比。结果显示： - AgentSpec 在所有配置下均持续优于所有投机解码基线，Goodput 最高提升 **104%**（GPT-OSS-20B 上的 Code Generation Agent）。 - 大多数基线方法在 Agent 工作负载中的 Goodput 甚至低于标准自回归解码，而 AgentSpec 始终实现正向加速，最高达到 **2.02×** 加速比（GPT-OSS-20B 上的 Code Generation Agent）。 --- ### 3. 不同执行模式与难度泛化性（5.3） 在 USACO 数据集的 Bronze 至 Platinum 四个难度子集上评估 Code Generation Agent，覆盖三种模型。结果表明： - AgentSpec 在所有难度子集和所有模型上均一致地优于其他投机解码方法。 - AgentSpec 在所有子集上均优于标准自回归解码，最高实现约 **2.2×** 加速。 --- ### 4. 非 Agent 工作负载验证（5.4） 在 Spec-Bench 上使用 Qwen-3-8B 评估，涵盖机器翻译、对话、问答、摘要、翻译、数学推理、检索增强等子任务。结果显示： - 即使在没有显式语义结构、历史重复模式较少的非 Agent 场景中，AgentSpec 依然在所有子集及整体上优于投机解码基线和标准自回归解码。 --- ### 5. 与多 Token 预测（MTP）对比（5.5） 使用 MiMo-7B（自带官方 MTP 模块）在 USACO 的 Code Generation Agent 上对比。结果显示： - MTP 在批量 Agent 推理中收益有限，甚至部分子集出现减速。 - AgentSpec 在所有难度子集上均优于 MTP，并在整体（All）上实现 **1.29×** 加速，相对 MTP 提升 **77%**。 --- ### 6. 延迟分析（5.6） - **尾延迟（Tailed Latency）**：在 Code Generation Agent 上测量端到端延迟的 CDF。AgentSpec 在 P90 和 P99 分位点分别将尾延迟降低至自回归解码的 **1/1.47** 和 **1/1.39**。 - **执行时间拆解**：将总时间拆分为 Draft 和 Verification 两部分。AgentSpec 的 Verification 时间相比基线最高降低 **21%**，尽管 Draft 时间因维护 PDA 和计算冗余分数而略有增加（仍低于 2ms），但整体执行时间相比基线降低 **19%**。 --- ### 7. 消融实验（5.7） - **模块敏感性研究**： - **AgentSpec (S)**：仅启用结构隔离草拟 - **AgentSpec (R)**：仅启用冗余感知预算分配（基于 SuffixDecoding） - **AgentSpec (N)**：不依赖显式语义结构输入的降级版本 - **完整 AgentSpec**：两者结合 结果表明两个模块均带来独立收益，结构隔离草拟的贡献更为显著；即使没有显式语义结构，AgentSpec (N) 仍优于所有基线。 - **不同最大 Batch Size**：在 Code Generation Agent 上测试 Batch Size 从 32 到 256 的配置。现有方法（如 SuffixDecoding）在小批量时可能优于自回归解码，但随着 Batch Size 增大加速比退化甚至低于基线；AgentSpec 在所有 Batch Size 下均保持稳定优势。 - **不同思考模式（Thinking Mode）**：在 Qwen-3-8B 上对比 `w/ think` 和 `w/o think` 模式。AgentSpec 在两种模式下均表现优异，在 `w/o think` 模式下加速比超过 **2.5×**。 --- ### 8. 附录补充实验 - **不同 GPU 架构**：在 H100 上测试 GPT-OSS-20B，AgentSpec 在 H100 上获得比 A100 更高的加速比（如 CodeGen 从 2.02× 提升至 2.28×），证明结论跨硬件代际泛化。 - **理论复杂度分析**：证明 AgentSpec 在时间和空间复杂度上与 NGram 等基线处于同一大类，仅引入极轻量的常数级开销。

Q5: 有什么可以进一步探索的点？

基于论文内容，以下方向具有进一步探索的潜力： - **自动化语义结构识别与动态划分** 当前结构隔离草拟依赖 Agent 应用显式提供语义块边界标识（如 `structure` 字段），且论文指出在无显式结构时性能对历史重复模式的依赖会增强。未来可探索**无需人工标注的自动语义边界检测机制**，例如利用 LLM 隐藏状态（hidden states）或注意力模式（attention patterns）动态识别语义转换点，或训练轻量级分类器在线预测块边界。这将降低 AgentSpec 的部署门槛，并提升其在结构模糊或开放式对话 Agent 中的适用性。 - **跨请求与跨会话的草稿共享机制** AgentSpec 当前将检索范围严格限制在同一查询（`query-id`）与同一语义块内，有效降低了拒绝率，但也隔离了跨查询的潜在共性。未来可研究**在隐私保护与访问控制前提下，跨用户请求或跨会话的草稿缓存与共享策略**。例如，通过差分隐私或语义哈希（semantic hashing）识别相似任务模式，在全局层面构建结构化的公共草稿库，从而进一步提升高并发场景下的预算利用率。 - **结构隔离与草稿模型方法的深度融合** 论文主要将 AgentSpec 作为无草稿模型（draft-model-free）方案与 EAGLE-3、MTP 等对比，但并未探索将结构隔离机制与轻量草稿模型结合的可能性。未来可研究**将语义块感知引入草稿模型的训练或推理过程**——例如，为不同语义块训练专门的草稿头（draft heads），或在草稿模型的注意力掩码中注入块边界信息，从而同时降低拒绝率并提高大批量场景下的草稿质量。 - **极端动态负载下的自适应预算控制** AgentSpec 的预算分配依赖于静态超参数 $\alpha$ 和 $g_{\min}$，以及当前批次内的局部冗余统计。在真实在线服务中，请求到达率、长度分布和语义块转移概率均高度动态。未来可引入**在线控制理论或强化学习框架**，根据实时测量的验证开销与接受率动态调整 $\alpha$ 和预算分配策略，从而在满足尾部延迟 SLO 的同时最大化吞吐。 - **与 KV Cache 及长上下文优化的协同设计** 论文专注于解码阶段的 Token 生成效率，未涉及与 KV Cache 管理、Prefix Caching 或长上下文 Prefill 优化的交互。对于具有长工具返回结果或长历史轨迹的 Agent，KV Cache 的存储与计算本身成为瓶颈。未来可探索**投机解码与 KV Cache 压缩、重计算（recomputation）及卸载（offloading）的联合优化**，例如利用被接受草稿的 KV Cache 复用潜力，或根据语义块边界实施分层 Cache 驱逐策略。 - **多模态 Agent 的跨模态投机解码** 论文的评估聚焦于文本 Agent（代码生成、深度研究等）。然而，现代 Agent 越来越多地涉及图像、代码执行截图、音频等多模态输入输出。未来需要定义**多模态语义块**（如“图像描述块”、“代码渲染块”），并研究如何基于视觉-语言模型的跨模态表示进行结构隔离草拟，以及如何处理非文本 Token 的冗余度量与预算分配问题。 - **拒绝率的理论建模与最优草稿长度界** 论文给出了基于拒绝率 $\rho(b)$ 和验证开销 $t_V(b)$ 的启发式效率模型，但未对 $\rho(b)$ 随 Batch Size、语义块转移概率及草稿长度的变化进行严格数学刻画。未来可基于**随机过程或信息论**，建立 $\rho(b)$ 与历史序列熵、块内转移概率之间的解析关系，进而推导在动态预算约束 $M(b)$ 下的最优草稿长度 $L_i^*$ 的理论下界或近似最优解。 - **与 Agent 级推理优化的联合设计** 论文提及 Agent 级优化（如 LEAP 的规划剪枝、APC 的计划缓存）可能牺牲生成质量，而 AgentSpec 作为无损加速与之正交。未来可探索**将投机解码与 Agent 级执行优化进行联合设计**：例如，在 Reflexion 类工作流中，利用结构隔离草拟快速生成试探性动作（thought / action），结合早期拒绝信号决定是否触发规划剪枝或工具调用，从而在保持输出分布不变的前提下，进一步减少不必要的环境交互与模型调用次数。

Q6: 总结一下论文的主要内容

本文对 **AgentSpec: Speculative Decoding for Batch Inference of LLM Agents** 的核心内容总结如下。 --- ### 1. 研究背景与动机 基于大语言模型（LLM）的 Agent 应用通常需要多步推理、工具调用与环境交互，导致推理延迟高、成本大。投机解码（Speculative Decoding）作为一种**无损**加速技术，在小批量（small batch）场景下效果显著，但在现代 LLM 服务引擎普遍采用的大批量（large batch）推理模式下，现有方法的加速比会急剧退化，甚至**慢于标准自回归解码**。因此，如何使投机解码在 LLM Agent 的大批量推理中保持高效，成为亟待解决的关键问题。 --- ### 2. 核心瓶颈分析 论文通过系统性分析识别出大批量场景下投机解码退化的两个主导因素： - **高拒绝率（High Rejection Rate）**：现有方法在 Agent 工作负载上的草稿 Token 拒绝率极高（部分基线超过 50%–85%）。随着 Batch Size $b$ 增大，验证被拒绝 Token 的开销迅速膨胀，直接抵消了被接受 Token 的收益。论文将单步执行时间节省建模为： $$\Delta T(b) \approx D(b) \left[(1-\rho(b))t_A - t_V(b)\right]$$ 其中 $D(b)$ 为草拟 Token 数，$\rho(b)$ 为拒绝率，$t_A$ 为接受单 Token 节省的时间，$t_V(b)$ 为验证开销。高 $\rho(b)$ 使得 $\Delta T(b)$ 迅速趋负。 - **动态 Token 预算利用不足（Under-utilization of Dynamic Token Budgets）**：随着 Batch Size 增加，FFN 层延迟线性增长，可用投机预算 $M(b)$ 动态收缩。现有方法采用均匀或粗粒度分配策略，无法高效利用动态变化的 Token 预算，进一步限制了加速空间。 --- ### 3. 方法：AgentSpec 为应对上述挑战，论文提出了 **AgentSpec**，一种专为 LLM Agent 大批量推理设计的**无草稿模型（draft-model-free）**投机解码算法，包含两个核心组件： #### (1) 结构隔离草拟（Structure-Isolated Drafting） AgentSpec 要求 Agent 应用为每个请求提供语义结构标识符 $S_i = \{a_i, q_i, B_i\}$，其中 $a_i$ 为 Agent 标识，$q_i$ 为用户查询索引，$B_i$ 为语义块列表。系统通过维护轻量级的**下推自动机（PDA）**实时追踪当前所处的语义块，并仅在**同一块内**的历史生成中检索草稿候选。 这一设计基于关键观察：Agent 工作负载中的历史重复模式高度集中于**同一查询的同一语义块内部**，跨块或跨查询的重复极少。通过将检索范围严格隔离在语义一致的片段内，AgentSpec 避免了向不相关语义路径投机，将拒绝率从基线的 50%–88% **降低至 26.4%**。 #### (2) 冗余感知预算分配（Redundancy-Aware Budget Allocation） AgentSpec 引入**冗余分数** $g$ 来衡量每份草稿的接受潜力： $$g(c, n) = \frac{c}{n \cdot p(n)}, \quad p(n) = g_{\min}+(1-g_{\min})(1-e^{1-n})$$ 其中 $n$ 为检索到的历史候选续写数，$c$ 为与最频繁前缀达成一致的候选数。饱和项 $p(n)$ 防止低支持度估计不可靠。 基于该分数，系统动态计算批次级预算 $B_t = \left\lfloor \alpha / b_z \right\rfloor$（$b_z$ 为当前 Batch Size），并为每个请求分配草稿长度： $$L_i = \max\left(|C_{T_i}^*|, B_t \cdot \frac{g_i}{\sum_j g_j}\right)$$ 该策略优先向高冗余请求倾斜预算，同时保证每个请求至少草拟其最自信的前缀，从而显著提升动态预算利用率。 --- ### 4. 实验评估 论文在 vLLM 中对 AgentSpec 进行了全面评估，覆盖 **4 个不同 LLM 家族的模型**（Qwen-3-8B、GPT-OSS-20B、DeepSeek-R1-Distill-8B、MiMo-7B）与 **4 类 Agent 工作负载**（Code Generation、Deep Research、GAIA、SWE-Bench），以及非 Agent 的 Spec-Bench 基准。核心实验结果包括： - **端到端效率**：AgentSpec 在所有 Agent 工作负载和模型上均持续优于所有基线（包括 EAGLE-3、NGram、SuffixDecoding 和 MTP），最高实现 **2.02×** 的 Goodput 加速，而多数基线在大批量下已劣于自回归解码。 - **难度泛化性**：在 USACO 从 Bronze 到 Platinum 的不同难度子集上，AgentSpec 均保持稳定加速，最高约 **2.2×**。 - **非 Agent 场景**：即使在没有显式语义结构的 Spec-Bench 上，AgentSpec 依然优于所有基线，整体加速 **1.14×**，部分子任务达 **1.40×**。 - **与 MTP 对比**：在 MiMo-7B 上，AgentSpec 优于官方 MTP 模块，整体加速 **1.29×**，相对 MTP 提升 **77%**。 - **延迟与拆解**：AgentSpec 在 P90/P99 尾延迟上分别降低 **1.47×/1.39×**；验证开销相比基线最高降低 **21%**。 - **消融与扩展**：结构隔离草拟和冗余感知预算分配均贡献独立收益；即使没有显式语义结构输入，降级版 AgentSpec 仍优于基线；在不同 Batch Size 和不同思考模式（w/ think vs. w/o think）下均表现稳健。 --- ### 5. 主要结论 AgentSpec 通过**结构隔离草拟**实现了极低的草稿拒绝率，并通过**冗余感知预算分配**高效利用了大批量推理中动态变化的 Token 预算。两者协同使 AgentSpec 在 LLM Agent 的大批量推理场景下，突破了现有投机解码方法的扩展性瓶颈，实现了稳定且显著的推理加速，且无需修改模型参数或影响生成质量。
