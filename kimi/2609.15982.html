Q1: 这篇论文试图解决什么问题？

这篇论文旨在解决**大规模技能库中的技能路由（skill routing）问题**，即如何让LLM智能体在拥有成千上万条技能（skills）的库中，精准地选择当前任务所需的正确技能，同时避免现有范式下的关键缺陷。 具体而言，论文试图克服当前两种主流方法的根本局限： - **渐进式披露（Progressive Disclosure）的上下文瓶颈** 现有部署系统（如Claude Code、Codex）将所有已安装技能的元数据（名称与描述）预加载到系统提示中，由智能体自行选择。这导致： - 元数据与任务争夺有限的上下文窗口，分散智能体注意力； - 技能库规模被人为封顶（例如Codex限制技能元数据仅占上下文窗口的2%）； - 随着技能数量增加，路由精度对数衰减。 - **检索-重排序（Retrieve-and-Rerank）的能力脱节** 为减轻上下文负担，近期研究将选择任务交给外部的嵌入模型与重排序器。这虽然清空了上下文，但也带来了新问题： - 独立的外部检索器擅长文本匹配，却远不如智能体本体理解任务需求； - 检索器无法感知智能体在 roll-out 过程中动态变化的执行状态，尤其在多轮、嘈杂的交互中； - 外部模型不会随智能体本体能力的提升而自动提升。 为此，论文提出核心问题：**能否在不向上下文注入任何技能文本的前提下，直接利用冻结的Agent LLM自身的前向传播来完成技能选择？** 论文给出的答案是 **Gavel (Glance And Verdict from a frozen LLM)**，其试图实现的目标包括： 1. **任务纯净的上下文（Task-only context）** 在选择完成前，上下文中不出现任何技能文本，避免注意力分散。 2. **无独立外部模型（No standalone model）** 不依赖额外的嵌入或重排序模型，仅通过两个可训练的线性投影（共7.9M参数）从冻结LLM的中间层状态中读取路由信号，使路由能力与智能体本体同步进化。 3. **安装时即时索引（Installation-time indexing）** 新技能只需一次前向传播即可构建索引，无需为新增技能重新训练模型。 简言之，这篇论文试图证明：**冻结的Agent LLM已经内蕴了足够的路由信号，关键在于如何以极低代价将其“引出”——既保留智能体自身对任务与技能的深层理解，又彻底摆脱上下文拥挤与外部模型脱节的双重困境。**

Q2: 有哪些相关研究？

根据论文第2节及相关论述，相关研究主要分布在以下两大领域： ## 1. 技能与工具选择（Skill and Tool Selection） **渐进式披露（Progressive Disclosure）** 现有部署系统（如 Claude Code、Codex）采用此范式：将全部已安装技能的元数据（名称与描述）预加载至系统提示中，由智能体自行决定读取哪一项技能的完整文档（Anthropic, 2025; OpenAI, 2026a）。该方法的固有代价是元数据随库规模增长而挤占上下文，导致智能体注意力分散（Liu et al., 2024; Modarressi et al., 2025），且路由精度随技能数量对数衰减（Chen et al., 2026a）。 **检索-重排序流水线（Retrieve-and-Rerank Pipelines）** 为解除上下文负担，近期研究将选择任务外置。此类系统通常以嵌入模型筛选候选，再以重排序器精排，随后将选定技能注入上下文。相关工作涵盖基于 API 池的检索（Qin et al., 2024a）、在 roll-out 中途调用工具（Fei et al., 2025; Lumer et al., 2025），以及基于完整技能文档训练的专用路由模型（Zheng et al., 2026; Wang et al., 2026）。然而，这些外部模型与智能体能力脱节，既无法感知动态执行状态，也不随 Agent 主干能力的提升而进化（Shi et al., 2025; Kang et al., 2026）。 **基于 Token 的工具选择（ToolkenGPT）** ToolkenGPT（Hao et al., 2023）尝试让冻结 LLM 以生成 token 的方式直接发出工具标识，但需为每个工具训练独立嵌入，新增工具必须重新训练。与之相对，Gavel 无需为单个技能更新参数，仅通过可复用的线性投影即可读取路由信号。 ## 2. 从 LLM 中读出信息（Reading Information out of an LLM） **探测与表示学习（Probing and Representation Learning）** 大量研究表明，LLM 的隐藏状态承载的信息远超下一个 token 预测所需（Alain & Bengio, 2017; Belinkov, 2022）。后续工作在此基础上探索如何将这些表示转化为可用的嵌入或评分信号。 **基于 LLM 的文本嵌入与统一表示** - **微调方法**：通过微调将解码器 LLM 转化为强编码器（Wang et al., 2024; BehnamGhader et al., 2024）。 - **免微调方法**：仅通过重复提示策略即可提取高质量嵌入（Springer et al., 2025）。 - **生成-表示统一**：GRIT（Muennighoff et al., 2025）在单一模型中统一嵌入与生成，但需微调整个主干。Gavel 则保持主干冻结，仅训练两个轻量级线性投影。 **判别式重排序（Discriminative Reranking）** 重排序信号通常来自两类读取：一是基于查询似然的生成式评分，即文档对查询的预测概率（Sachan et al., 2022; Zhuang et al., 2023）；二是模型自身的判别式判断，如通过 yes/no 提示获取的相关性对数几率（Nogueira et al., 2020; Sun et al., 2023）。Gavel 将这两类读出方式（生成式与判别式）与对比式 glance 信号融合，统一视为对同一后验 $\log p(s \mid x)$ 的不同估计，并以专家乘积（product of experts）形式聚合（Hinton, 2002）。

Q3: 论文如何解决这个问题？

论文提出 **Gavel (Glance And Verdict from a frozen LLM)**，通过仅训练两个线性投影，从冻结 Agent LLM 的前向传播中直接“引出”原生路由信号，实现既在智能体能力之内、又完全在上下文之外的路由决策。其解决思路可分解为以下核心环节： --- ### 1. 问题建模与设计原则 将技能路由定义为：给定冻结 LLM $M$、任务上下文 $x$（可能是用户请求或 roll-out 中的执行状态），以及技能库 $S = \{s_1, \dots, s_N\}$，选择最应加载的技能 $s \in S$。设计需同时满足三项原则： - **任务纯净上下文**：选择完成前，上下文中不得出现任何技能文本； - **无独立外部模型**：选择能力应继承自 Agent LLM 本身，且随其能力成长； - **安装时即时索引**：新技能仅通过一次前向传播即可加入库中，无需重新训练。 --- ### 2. 第一阶段：Glance（扫视全库） Glance 的目标是以极低代价对完整技能库进行初筛，仅依赖任务解码过程中已计算的中间层状态。 #### 2.1 读出层的选择 选取中间层 $\ell^*$（通常位于模型深度的约 $70\%$ 处，由矩阵熵的“压缩谷底”确定）。该层已压缩输入语义，且尚未过度纠缠于下一 token 预测。 #### 2.2 因子化注意力头 在冻结模型上嫁接一个新的注意力头，包含两个可训练的线性映射： - **Query 映射** $W_q$：将任务 token 在层 $\ell^*$ 的隐藏状态 $h_{\ell^*}(x)_i$ 投影为单元查询向量 $q_i \propto W_q h_{\ell^*}(x)_i$； - **Key 映射** $W_s$：将技能文档在层 $\ell^*$ 的隐藏状态投影为单元键向量 $d_s^j \propto W_s h_{\ell^*}(r(s))_j$。 安装新技能 $s$ 时，使用固定提示模板 $r(s)$ 渲染该技能，执行一次前向传播，缓存其所有 token 的 key 向量 $\{d_s^j\}_j$ 构成该技能的 key bank。 #### 2.3 Token 级投票机制 路由时，每个任务 token 对每项技能执行“硬注意力”，保留其最强匹配分数： $$ m_i(s) = \max_j \langle q_i, d_s^j \rangle $$ 为避免长序列中大量无关 token 淹没少数关键 token，Gavel 不采用全局平均，而是让每个 token 仅向它的 top-$k$ 技能投票： $$ g(s \mid x) = \frac{1}{\sum_i w_i} \sum_{i: s \in \mathbf{T}_i} w_i \, m_i(s), \quad \mathbf{T}_i = \text{top-}k \text{ skills under } m_i $$ 其中 $w_i$ 为可调的时序衰减权重（在 roll-out 中 favor 近期 token）。 #### 2.4 对比训练与银行压缩 $W_q$ 与 $W_s$ 通过多正例 InfoNCE 损失一次性训练： $$ \mathcal{L} = -\log \frac{\sum_{s \in S^+} e^{\tau \bar{m}(s)}}{\sum_{s \in S^+ \cup S^-} e^{\tau \bar{m}(s)}} $$ 其中 $\bar{m}(s) = \text{mean}_i \, m_i(s)$，$\tau$ 为温度系数，梯度在隐藏状态处截断。 为控制存储成本，安装时对 key bank 进行 **$\varepsilon$-cover 压缩**：通过最远点遍历，仅保留彼此间距不小于 $\varepsilon$ 的代表性 key，确保任意被丢弃的 key 与某个保留 key 的距离不超过 $\varepsilon$。这保证了查询分数的失真上界： $$ \max_{d \in D_s} \langle q, d \rangle - \varepsilon \leq \max_{c \in C_s} \langle q, c \rangle \leq \max_{d \in D_s} \langle q, d \rangle $$ 压缩后 $W_q$ 进行一次短微调以适应粗粒度几何。 --- ### 3. 第二阶段：Verdict（裁决短名单） Glance 的因子化结构牺牲了部分深层语义推断能力。为此，Verdict 对 Glance 截取的短名单（约前 9 名候选）投入更高计算，允许冻结模型在任务与技能之间执行完整自注意力。 对候选技能 $s$，将其安装时的渲染前缀 $r(s)$ 与任务 $x$ 拼接，执行一次因果前向传播，提取两类原生信号： #### 3.1 生成式信号：任务似然 衡量该技能在多大程度上“预期”任务内容： $$ L(s \mid x) = \frac{1}{|x|} \sum_{i=1}^{|x|} \log p_M(x_i \mid r(s), x_{<i}) $$ #### 3.2 判别式信号：模型自判断 在拼接序列末尾附加固定问题 $u$（“该技能是否满足任务需求？”），读取模型对 yes/no 的 log-odds： $$ V(s \mid x) = \log \sum_{t \in \mathcal{Y}} p_M(t \mid r(s), x, u) - \log \sum_{t \in \mathcal{N}} p_M(t \mid r(s), x, u) $$ 其中 $\mathcal{Y}$ 与 $\mathcal{N}$ 分别为 yes/no 的各种拼写变体。 由于问题 $u$ 置于任务之后，因果掩码不干扰任务位置的计算，单次前向传播即可同时获得 $L$ 与 $V$。 --- ### 4. 最终裁决：Product of Experts（专家乘积） Glance 分数 $g$、生成式似然 $L$、判别式判断 $V$ 本质上分别是从对比、生成、判别三个视角对同一对数后验 $\log p(s \mid x)$ 的估计。因此，Gavel 以专家乘积形式融合： $$ S(s \mid x) = g(s \mid x) + \alpha L(s \mid x) + \gamma V(s \mid x) $$ 其中 $\alpha$ 与 $\gamma$ 为将各信号转换到同一尺度的兑换率与温度系数。任一专家均可否决其他专家仅勉强接受的候选。得分最高者即为最终加载的技能。 --- ### 5. 端到端集成：触发门控（Gate） 在真实部署中，还需决定“何时尝试加载技能”。Gavel 训练一个轻量门控分类器，基于当前 token 的 glance 累积分数与最终层状态进行判断。当门控连续两个 token 保持“开启”时，Gavel 尝试执行一次路由；若 Verdict 对最优候选的判别式信号 $V < 0$（即模型认为该技能不适用），则选择不加载任何技能。 --- ### 6. 总结 Gavel 的解决路径可概括为： | 传统瓶颈 | Gavel 的解法 | |---|---| | 元数据挤占上下文 | 选择过程完全在上下文外完成，技能文本仅在选定后注入 | | 外部模型能力脱节 | 所有信号读取自冻结 Agent LLM 的前向传播，随主干能力提升而提升 | | 新技能需重训练 | 安装时仅执行一次前向传播构建 key bank，无需训练 | | 粗粒度语义匹配不足 | 两阶段架构：轻量 token 级扫视全库 + 完整注意力深度裁决短名单 | | 多源信号难以融合 | 统一视为对数后验的不同估计，以专家乘积融合 |

Q4: 论文做了哪些实验？

论文在第 4 节开展了系统的实验验证，涵盖**静态书面任务路由**、**动态 roll-out 中途路由**、**端到端真实部署**以及**主干模型扩展性**四个层面。 --- ### 1. 实验设置 - **主干模型**：冻结的 Qwen3-32B，在块 45（约 70% 深度）读取中间层状态。 - **可训练参数**：两个线性投影 $W_q$ 与 $W_s$，共 7.9M 参数。 - **训练数据**：SkillRet 训练集的 51,104 条查询，对比损失温度 $\tau = 40$。 - **超参数**：压缩半径 $\varepsilon = 0.83$（压缩比约 8.5×），兑换率 $(\alpha, \gamma) = (1.0, 0.025)$，修剪阈值 $\Delta = 0.133$（平均约 9 个候选进入 Verdict）。 - **评估协议**：所有跨基准测试的评估均为**零样本（zero-shot）**，即除上述参数外不在目标基准上微调。 --- ### 2. 基于书面任务的路由（Routing from Written Tasks） 在三个公开基准上评估单一技能选择的准确性： | 基准 | 特点 | 规模 | |---|---|---| | **SkillRet test** | Claude 撰写的查询，面向代理的 SKILL.md 技能 | 4,997 查询 / 6,660 技能 | | **SRA-Bench** | 来自 6 个推理与编码基准的任务，技能多为网络抓取 | 861 任务 / 26,262 技能 | | **Eval-Core** | 真实 task.md 查询，分 easy（78K 文档）与 hard（+780 对抗干扰项）两池 | 75 查询 / 78K+ 文档 | 由于完整人工标注不可行，采用 **GPT-5.6 Sol 裁决的 Hit@1** 作为主要指标：模型比较提交技能与每条金标技能，若提交技能在成对比较中至少持平则判为命中。 #### 2.1 与现有范式的对比 对比基线包括： - **BM25**（词汇基线） - **SKILLRET-Emb-0.6B**（在 SkillRet 上训练的专用嵌入模型） - **Qwen3-Emb-8B + Progressive Disclosure**（通用嵌入模型检索前 20 名，再由智能体从元数据菜单中挑选） - **SkillRouter-Emb-0.6B + RR-0.6B**（SkillRouter 自带的嵌入+重排序器，共 1.2B 参数） - **Qwen3-Emb-8B + Qwen3-RR-8B**（通用嵌入+通用重排序器，共 16B 参数） **结果**：Gavel 在全库 Hit@1 上全面领先。完整流水线相对最强的检索-重排序流水线提升 **3.8 点（SkillRet）**、**13.4 点（SRA-Bench）** 与 **1.3–2.7 点（Eval-Core）**。Glance 单独作为检索阶段在 SRA-Bench 与 Eval-Core 上已是最强检索器，在 SkillRet 上与最佳嵌入器差距在 1 点以内。 #### 2.2 消融实验 逐一替换 Gavel 的关键设计，保持其余模块固定： - **Glance → Jina-ColBERT-v2**：替换为同粒度（token 级 late-interaction）的外部检索器，即使保留 Verdict 仍显著落后，证明优势来自 Agent LLM 的表示压缩，而非比较粒度。 - **Product of experts → Pointwise rerank**：仅保留判别式信号 $V$ 决定短名单，丢弃 $g$ 与 $L$，因自报告判断校准差而导致性能崩溃。 - **Verdict → skill body in generation**：将技能置于任务之后，以技能正文似然替代查询似然。这会引入“技能与模型自身写作风格相似度”的偏差，全面落后。 - **Verdict → progressive disclosure**：将 Glance 的短名单交给智能体从元数据菜单中自选。在 Eval-Core（描述精炼）上接近，但在 SRA-Bench（需要正文细节）上大幅落后。 --- ### 3. Roll-out 中途路由（Routing Mid-Rollout） 现有基准均为单一轮次的干净任务，而真实代理常在多轮交互中、在嘈杂上下文里才浮现技能需求。为此论文构建了新基准 **SkillTraj**： - **372 条模拟代理轨迹**，每条为多轮对话（含工具调用），标记了技能需求浮现的确切位置。 - **四种触发场景**： 1. **User request**（116 条）：用户直接提出需要； 2. **Tool evidence**（106 条）：工具返回结果揭示了需求； 3. **Agent plan**（105 条）：代理自身起草的计划中显式声明了子任务； 4. **Wrong-skill recovery**（45 条）：代理已加载错误技能并失败后，需重新路由。 **对比方式**：检索-重排序流水线分别测试“喂入完整多轮上下文”与“仅喂入最后一条消息”两种输入；渐进式披露受限于解码菜单索引。 **结果**：Gavel 在所有四种场景均领先最强对手 **8.6 至 21.9 点**。外部检索器无法有效处理完整噪声上下文（full context 表现极差），而仅取最后消息又可能丢失关键证据；Gavel 因直接读取 Agent 正在进行的解码状态，天然适应动态上下文。 --- ### 4. 端到端部署（End-to-End Deployment） 将 Gavel 集成至 **mini-swe-agent**（最小化 bash-agent 框架），在 **Skill-Use** 基准（177 项可执行任务，79 项精选技能）上测试： - **门控（Gate）**：基于 Glance 累积分数与当前最终层状态，判断是否触发技能调用。若连续两个 token 激活且 Verdict 的 $V < 0$（判断无合适技能），则选择不加载。 - **对比**： - 同一 Qwen3-32B 在渐进式披露下正确触发率仅 **0.011**（几乎从不读取技能）； - 集成 Gavel 后，同一冻结模型的正确触发率达 **0.909**； - 超过 Codex 中运行的更大规模前沿模型（GLM-5.1: 0.706、MiniMax-M3: 0.864、Qwen3.6-Max: 0.684、DeepSeek-V4-Pro: 0.650），也超过检索-重排序流水线（Qwen3-Emb-8B + RR-8B: 0.897；SkillRouter: 0.800）。 --- ### 5. 随主干能力扩展（Scaling with Backbone Capability） 在 **SRA-Bench** 上测试不同规模与代际的 Qwen 主干： - **尺寸扩展**：0.6B → 1.7B → 4B → 8B → 32B，Glance 阶段与完整 Gavel 的准确率均单调上升。 - **代际扩展**：Qwen1.5-32B → Qwen2.5-32B → Qwen3-32B，同样持续提升。 - **关键发现**：即使仅在 0.6B 模型上，Gavel 已击败 32B 模型在渐进式披露下的表现；在 Qwen3.8-27B（多项基准接近前沿模型能力）上，渐进式披露仍落后 Gavel **12.2 点**。 这表明 Gavel 的路由信号与 Agent LLM 的本体能力深度绑定，主干越强，路由越准，而渐进式披露即使在强主干上仍受限于上下文菜单的信息瓶颈。 --- ### 6. 附录中的补充实验 论文附录还包含： - **附录 E**：在 Gemma-4-31B（不同架构家族）上重建完整流水线，验证方法跨家族泛化性； - **附录 F**：补充消融，包括“将 20 个完整技能正文放入渐进式披露菜单”、“逐一移除 Verdict 单信号”、“以 Qwen3-Emb-8B 替代 Glance”等； - **附录 H**：裁决机制与人类标注的一致性验证（86% 一致率）、候选池召回率分析、SkillTraj 构造细节与示例。

Q5: 有什么可以进一步探索的点？

基于论文的局限性与讨论部分，以下方向值得进一步探索： --- ### 1. 向其他路由对象泛化 论文结论明确指出，同一读出机制是否适用于**工具（tools）**、**记忆（memories）**或 **MCP 服务器**的路由仍属开放问题。这些模态的文档结构、调用频率与语义粒度与 SKILL.md 存在差异，其 key bank 的构建方式与 $\varepsilon$-cover 的适用边界有待验证。 ### 2. 更精细的门控机制（Gate） 当前门控为基于单点状态的浅层分类器（附录 K）。两个改进路径尤为直接： - **序列化门控**：在 glance 分数的历史序列上建立序列模型，追踪需求随 token 位置的累积与演化，而非孤立判断每一位置； - **原生技能调用 Token**：对主干进行轻微微调，使其在解码过程中自发产出专门的“技能调用”token，将触发决策彻底内化为生成过程的一部分，从而消除外部门控的延迟。 ### 3. 学习化的上下文聚合策略 Glance 当前采用手工设计的时序衰减 $w_i$ 进行 token 投票聚合（附录 A）。未来可探索**基于数据驱动的注意力聚合机制**，使模型自动学习在多变上下文（如 buried mid-history 的触发信号 vs. 近期噪声）中选择性聚焦关键 token。这需要在包含选择性奖励的信号上进行训练。 ### 4. 多技能联合选择与组合推理 现有工作聚焦于单技能路由（Hit@1）。复杂任务常需**多个技能按序或组合调用**。扩展 verdict 阶段以评估技能子集的互补性，或引入迭代式“加载-评估-再路由”循环，是值得探索的架构升级。 ### 5. 动态与增量式技能库维护 论文强调技能库规模庞大且持续变化（公共库可达数万条目）。当前每次新增技能需重新执行一次安装前向传播，但**增量式 bank 更新**（如仅局部调整 $\varepsilon$-cover）、**在线技能淘汰**以及**版本化管理**的工程与算法细节尚未展开。 ### 6. 更激进的延迟-精度权衡 Verdict 阶段需对短名单执行约 9 次独立因果前向传播。可探索： - **批处理与 KV-cache 复用**的进一步优化； - **自适应剪枝**：根据 glance 分数的置信度动态调整进入 verdict 的候选数量，而非固定阈值 $\Delta$； - **一次性多候选编码**：在单个前缀树（prefix trie）中并行评估多项技能的可行性。 ### 7. 理论化读出机制 论文以实证为主，揭示了中间层 $\ell^*$ 的矩阵熵谷底与路由性能的相关性。可对以下问题建立理论分析： - 为何压缩层（compression valley）的原生 key/query 空间经过线性投影后即可编码“能力需求-能力供给”的匹配关系； - Product of Experts 融合在何种条件下保证后验近似的 consistency； - $\varepsilon$-cover 在覆盖数（covering number）与精度损失之间的信息论下界。 ### 8. 跨模态与多语言场景 当前实验以英文/中文技能文档为主。在**多语言技能库**或**跨模态工具文档**（如含代码片段、图表、结构化 API 定义）中，mid-layer 状态的语义对齐特性是否依然成立，以及 $\varepsilon$-cover 的距离度量是否需要模态自适应，均待检验。 ### 9. 端到端强化学习训练 当前路由器的训练信号为静态的对比损失。若将 Gavel 嵌入完整的 agent roll-out，以**任务最终完成度**作为延迟奖励，通过强化学习 jointly fine-tune 投影 $W_q, W_s$ 与门控参数，可能使路由策略从“文档相关性”演进为“执行效用最大化”。 ### 10. 大规模人类标注与更复杂轨迹基准 SkillTraj 覆盖四种触发场景共 372 条轨迹。可扩展至： - **长 horizon 错误恢复**：在多轮错误累积后重新路由； - **隐性需求推断**：用户未明确请求、工具未直接返回，仅靠环境状态变化推断； - **人机协作中的中断与切换**：在对话流中实时检测话题漂移并切换技能。

Q6: 总结一下论文的主要内容

这篇论文围绕**大语言模型（LLM）智能体的技能路由（skill routing）**问题展开，提出了一种从冻结的 Agent LLM 自身前向传播中直接提取路由信号的新方法，核心内容可概括如下： --- ### 1. 研究背景与问题 扩展 LLM 智能体能力的主流方式是“技能”（skills），即封装了指令、脚本和参考文档的 SKILL.md 文件。从大规模技能库中选出正确的一项至关重要，但现有两种范式存在根本缺陷： - **渐进式披露（Progressive Disclosure）**：将所有技能的元数据预加载到系统提示中，由智能体自选。这严重挤占上下文窗口，分散注意力，且技能数量受限（如 Codex 限制元数据仅占上下文的 2%）。 - **检索-重排序（Retrieve-and-Rerank）**：使用外部嵌入/重排序模型进行筛选，虽清空了上下文，但选择能力与 Agent 本体脱节，无法感知动态执行状态，且不随 Agent 能力提升而进化。 **核心问题**：能否在不向上下文注入任何技能文本、不添加庞大外部模型的前提下，直接利用冻结 Agent LLM 自身的能力完成技能选择？ --- ### 2. 方法：Gavel 论文提出 **Gavel（Glance And Verdict from a frozen LLM）**，仅训练两个线性投影（共 7.9M 参数），从冻结 LLM 的中间层状态中读取路由信号。整体流程分为两阶段： #### 2.1 Glance（扫视全库） - **读出层**：选取 LLM 中间层 $\ell^*$（约 70% 深度，矩阵熵谷底），该层语义压缩充分。 - **投影与缓存**： - $W_q$ 将任务 token 的状态投影为查询向量 $q_i$； - $W_s$ 将技能 token 的状态投影为键向量 $d_s^j$，安装时通过一次前向传播缓存为技能银行（skill bank）。 - **Token 级投票**：每个任务 token 只向与其最匹配的 top-$k$ 技能投票，避免无关 token 淹没关键信号： $$ g(s \mid x) = \frac{1}{\sum_i w_i} \sum_{i: s \in \mathbf{T}_i} w_i \max_j \langle q_i, d_s^j \rangle $$ - **$\varepsilon$-cover 压缩**：安装时对技能银行进行最远点遍历压缩，仅保留 $\varepsilon$-分离的代表性键，保证查询分数失真不超过 $\varepsilon$。 #### 2.2 Verdict（裁决短名单） Glance 高效但受限于因子化结构。对于进入短名单（约 9 个）的候选，恢复其完整前向传播，在任务与技能之间执行全注意力，提取两类原生信号： - **生成式信号 $L$**：任务在技能前缀下的平均对数似然，衡量技能对任务的预期程度； $$ L(s \mid x) = \frac{1}{|x|} \sum_{i=1}^{|x|} \log p_M(x_i \mid r(s), x_{<i}) $$ - **判别式信号 $V$**：模型对问题“该技能是否满足任务需求？”的 yes/no 对数几率回答。 $$ V(s \mid x) = \log p_M(\text{yes} \mid \cdots) - \log p_M(\text{no} \mid \cdots) $$ #### 2.3 信号融合与门控 - **Product of Experts**：三个信号被统一视为对同一后验 $\log p(s \mid x)$ 的估计，以对数域相加融合： $$ S(s \mid x) = g(s \mid x) + \alpha L(s \mid x) + \gamma V(s \mid x) $$ - **触发门控（Gate）**：在真实 roll-out 中，基于 glance 累积分数与当前最终层状态判断是否触发路由，避免不必要的技能加载。 --- ### 3. 实验验证 论文在四个层面进行了系统验证： - **公开书面任务基准**：SkillRet、SRA-Bench、Eval-Core。Gavel 在 Hit@1 上超越渐进式披露和参数量达 1.2B–16B 的检索-重排序流水线，最高领先 **13.4 点**（SRA-Bench）。 - **动态 roll-out 路由**：构建新基准 **SkillTraj**（372 条模拟轨迹，涵盖用户请求、工具证据、代理计划、错误恢复四种场景）。Gavel 领先最强基线 **8.6–21.9 点**。 - **端到端部署**：集成至 mini-swe-agent，在 Skill-Use 上 Qwen3-32B 的正确技能触发率达 **0.909**，超过 Codex 中运行的更大规模前沿模型。 - **扩展性分析**：路由准确率随主干模型规模（0.6B→32B）与代际提升而单调增长，而渐进式披露即使在 32B 模型上仍受困于信息瓶颈。 消融实验表明，Glance 的优势源于 Agent LLM 的深层语义压缩而非比较粒度；Verdict 通过读取完整技能正文弥补了元数据的概括性损失；三类信号的组合优于任何单一信号。 --- ### 4. 主要贡献 - **Gavel**：首个无需外部模型、无需技能文本进上下文的路由器，仅通过两个线性投影从冻结 LLM 中引出原生路由能力。 - **技术细节**：提出 token 级 mid-layer 读出、$\varepsilon$-cover 银行压缩、以及生成-判别-对比三信号的 Product of Experts 融合。 - **SkillTraj**：构建了评估 roll-out 中途路由的新基准，覆盖四种真实触发场景。 - **实证结论**：证明冻结 Agent LLM 已内蕴足够的路由信号，轻量读出即可超越庞大外部流水线，且该能力随主干进化而同步提升。
