Q1: 这篇论文试图解决什么问题？

该论文试图解决的核心问题是：**如何让冻结的大语言模型（LLM）高效地利用不断累积的外部知识（如历史对话、长文档、智能体过往经验），同时避免将大量原始文本直接填入上下文窗口所导致的性能下降与效率损失。** 具体而言，论文针对现有记忆系统的以下局限性展开： - **文本检索与压缩方法的局限**：传统的检索增强生成（RAG）及基于摘要的系统（如 Mem0、MemoRAG）只能将筛选出的原始文本片段放入模型上下文。当相关信息分散在大量文档中、且与查询词汇重叠度低时，这类方法难以有效检索并组合所需证据，且上下文长度随文档量增长。 - **查询无关的潜在压缩局限**：现有的潜在压缩方法（如 ICAE、AutoCompressors）将文档编码为固定软 token，但这些表示在编码时不考虑具体查询，无法针对不同问题动态调整所强调的信息。 - **模型绑定记忆的局限**：依赖特定模型隐藏状态或键值缓存的方法（如 LongMem、MemoryLLM）将记忆与单一模型架构强耦合，需要训练 LLM 或附加网络，缺乏跨模型的可移植性。 为此，论文提出 **MEMORILLA**，其解决思路可概括为： 1. **一次性编码与持久存储**：使用冻结的嵌入模型将文档（如用户对话、书籍章节）编码为可重用的持久化嵌入，避免重复处理原始文本。 2. **查询条件的记忆读出**：通过可训练的记忆模块，针对每个查询从全部文档嵌入中进行条件化的交叉注意力读取，生成固定数量（如 $K=16$）的查询依赖“记忆 token”。 3. **直接注入冻结 LLM 的输入空间**：将这些记忆 token 投影到冻结 LLM 的输入嵌入空间，使 LLM 无需处理长文本即可在生成时直接利用这些紧凑的潜在语义表示。 通过这一设计，MEMORILLA 在个性化问答、长文档理解与知识密集型任务中，仅用极少的记忆 token（如 16 个）即可达到甚至超越完整上下文基线的性能，同时支持智能体在交互过程中的持续学习与经验积累。

Q2: 有哪些相关研究？

论文将相关研究划分为三大主线，分别为**文本记忆**、**潜在压缩**与**模型记忆**，此外还包括提示压缩等辅助技术。各主线的代表性工作及其与 MEMORILLA 的关系如下： ### 1. 文本记忆（Textual Memory） 此类方法保留原始文本记录，通过检索将相关片段送入 LLM 上下文，但受限于“选择即丢弃”的瓶颈。 - **RAG** 与 **REALM**：基于稠密检索从文档索引中召回段落，作为 LLM 的上下文（Lewis et al., 2020; Guu et al., 2020）。 - **MemGPT**：在上下文层级间迁移信息，模拟操作系统式的内存管理（Packer et al., 2023）。 - **MemoryBank**：以会话与摘要形式存储长期对话记忆（Zhong et al., 2024）。 - **Mem0** 与 **A-MEM**：维护结构化记忆记录，支持跨会话更新与检索（Chhikara et al., 2025; Xu et al., 2025）。 - **MemoRAG**：利用全局压缩记忆生成检索线索，但最终生成器仍读取选中的文本段落（Qian et al., 2025）。 - **In-Context RALM**：发现在问答场景中，绝大多数性能增益仅来自前两篇检索文档（Ram et al., 2023）。 此类方法的优势在于保留文本出处与精确细节，但 LLM 只能对被选入上下文的文档进行推理，跨文档分布的隐含信号难以被利用。 ### 2. 潜在压缩（Latent Compression） 此类方法将长上下文替换为紧凑的连续向量，但大多在压缩时不考虑查询，导致同一表示需服务于所有问题。 - **ICAE** 与 **IC-Former**：将长输入编码为可重用的潜在向量，供冻结的目标 LLM 消费（Ge et al., 2024; Wang et al., 2024a）。 - **AutoCompressors**：通过微调 LLM 本身来生成并消费递归式摘要向量（Chevalier et al., 2023）。 - **Gist tokens** 与 **500xCompressor**：利用层特定的键值状态进行压缩，而非标准输入嵌入（Mu et al., 2023; Li et al., 2025）。 - **xRAG**：先通过检索选择单篇文档，再将其嵌入映射为单个软 token，保留了“文档选择”作为访问机制（Cheng et al., 2024）。 - **PISCO**、**COCOM** 与 **CLaRa**：联合优化压缩器与生成器，或先学习可复用的文档向量再训练查询推理模块（Louis et al., 2025; Rau et al., 2024; He et al., 2025）。 - **ComMer**、**USER-LLM** 与 **Embedding-to-Prefix**：针对用户历史构建潜在状态，实现个性化生成（Zeldes et al., 2025; Ning et al., 2025; Huber et al., 2025）。 - **TokMem**：为每个特定程序优化独立 token（Wu et al., 2026）。 与上述方法相比，MEMORILLA 的关键差异在于：其记忆存储与查询无关（可一次性持久化），但读出的潜在表示是**查询条件化**的，且直接映射到**冻结 LLM 的输入嵌入空间**，无需改动生成模型。 ### 3. 模型记忆（Model Memory） 此类方法将信息存储在模型架构特定的内部状态中，支持查询条件的召回，但与特定模型强耦合。 - **MemoryLLM**：维护自更新的潜在记忆池（Wang et al., 2024b）。 - **M+**：利用当前隐藏状态从长期存储中检索（Wang et al., 2025）。 - **LongMem**：通过训练好的旁路网络检索缓存的键值状态（Wang et al., 2023）。 - **LM2**：在自回归推理过程中更新门控记忆矩阵（Kang et al., 2025）。 - **Titans**：结合固定任务级参数与在处理序列时动态更新的上下文神经记忆（Behrouz et al., 2025）。 - **MELODI** 与 **Activation Beacon**：在上下文窗口与 Transformer 层之间压缩状态，以扩展长序列处理能力（Chen et al., 2025; Zhang et al., 2025）。 - **Cartridges**：使模型特定的键值缓存可复用、可组合，但需针对每个新语料进行离线优化（Eyuboglu et al., 2026）。 这些方法证明了持久潜在状态的价值，但其架构特定的接口限制了跨模型与跨语料的复用。MEMORILLA 则保持记忆外置，以输入嵌入的形式供给冻结 LLM，实现了存储与解码器的解耦。 ### 4. 其他辅助技术 - **LLMLingua-2**：基于 token 分类器的硬提示压缩方法，通过删除而非替换 token 来缩短上下文（Pan et al., 2024）。该方法与 MEMORILLA 在效率上可比，但属于文本级压缩，无法像潜在记忆那样跨文档整合语义关系。

Q3: 论文如何解决这个问题？

论文提出 **MEMORILLA**，通过将**持久化知识存储**与**查询相关上下文**解耦，使冻结的 LLM 能够利用固定数量的可学习“记忆 token”来访问整个文档集合。其解决方案包含架构设计、训练策略与推理机制三个层面，具体如下： --- ### 1. 整体架构：编码—存储—检索三步流程 MEMORILLA 的 pipeline 由三个连续操作构成： - **编码（Encoding）**：冻结的文档编码器将每个文档块编码为嵌入向量； - **存储（Storage）**：这些向量构成持久化的记忆库，一次性计算后长期复用； - **检索（Retrieval）**：针对每个查询，可训练的记忆模块从整个记忆库中读取信息，生成 $K$ 个查询条件的软记忆 token，直接注入冻结 LLM 的输入嵌入空间。 --- ### 2. 编码与持久存储 给定 $N$ 个文档块 $\mathcal{D} = \{d_1, \ldots, d_N\}$，冻结的文档编码器 $f_d^{\text{enc}}$ 将每个块映射为嵌入： $$z_i = f_d^{\text{enc}}(d_i) \in \mathbb{R}^{h_e}$$ 所有文档嵌入堆叠成与查询无关的持久记忆库： $$Z_D = [f_d^{\text{enc}}(d_1), \ldots, f_d^{\text{enc}}(d_N)] \in \mathbb{R}^{N \times h_e} \tag{1}$$ 由于 $Z_D$ 不依赖查询，只需编码一次即可持久保存；新增或修改文档时仅增量更新对应嵌入。查询 $q$ 则通过冻结的查询编码器 $f_q^{\text{enc}}$ 映射为 $z_q = f_q^{\text{enc}}(q) \in \mathbb{R}^{h_e}$，仅对当前查询计算，不进入长期存储。 --- ### 3. 查询条件检索模块 $f_{\text{mem}}$ 这是 MEMORILLA 的核心创新。该模块以 $(Z_D, z_q)$ 为输入，输出记忆矩阵 $M \in \mathbb{R}^{K \times h_L}$（$h_L$ 为冻结 LLM 的输入嵌入维度），包含四个阶段： **阶段一：记忆槽初始化** 初始化 $K$ 个可学习的记忆槽 $Q_0 \in \mathbb{R}^{K \times h_e}$，在所有集合与查询间共享。不同的初始值确保各槽位具备不同身份标识，同时维持固定的输出预算。 **阶段二：查询条件化** 记忆槽通过交叉注意力与查询嵌入交互，实现查询条件化： $$Q_c = \text{LayerNorm}\left(Q_0 + \text{CrossAttn}(Q=Q_0, K=z_q, V=z_q)\right) \tag{3}$$ 由于查询由单向量表示，该操作为所有槽提供共享更新；残差连接则保留槽位间的差异性。 **阶段三：文档检索** 条件化后的槽位通过 $L_{\text{ref}}$ 层交叉注意力块，在全部文档嵌入上进行连续读取（遵循 Perceiver 的潜在数组设计）。令 $\tilde{Z}_D = \text{LayerNorm}(Z_D)$，$R_0 = Q_c$，则第 $\ell$ 层为： $$\tilde{R}_{\ell} = R_{\ell-1} + \text{CrossAttn}\left(Q=\text{LayerNorm}(R_{\ell-1}), K=\tilde{Z}_D, V=\tilde{Z}_D\right),$$ $$R_{\ell} = \tilde{R}_{\ell} + \text{FFN}\left(\text{LayerNorm}(\tilde{R}_{\ell})\right) \tag{4}$$ 其中 FFN 为带 GELU 激活的两层前馈网络。每个槽位可 attending 到全部 $N$ 个存储文档，实现**连续的、查询条件的全局读取**，而非离散地选取 top-$k$ 文档。 **阶段四：投影到 LLM 嵌入空间** 通过可学习的投影矩阵将精炼后的槽位从编码器维度 $h_e$ 映射到 LLM 输入维度 $h_L$： $$M = \text{LayerNorm}(R_{L_{\text{ref}}}) W_{\text{proj}}, \quad W_{\text{proj}} \in \mathbb{R}^{h_e \times h_L} \tag{5}$$ 所得 $M = [m_1; \ldots; m_K]$ 的每一行 $m_k \in \mathbb{R}^{h_L}$ 即为一个软记忆 token。 --- ### 4. 向冻结 LLM 注入记忆 LLM 的输入嵌入层将查询文本映射为 $P_q$，最终输入序列为文本 token 与记忆 token 的拼接： $$X_{\text{LLM}} = [\underbrace{m_1, \ldots, m_K}_{\text{soft memory tokens}}; P_q] \tag{6}$$ 由于 $m_k$ 与文本 token 嵌入维度相同，冻结 LLM 无需任何架构修改即可在统一序列中处理记忆与文本。标准 RoPE（旋转位置编码）直接应用于拼接后的序列，LLM 通过其自注意力层自然地 attending 到这些记忆 token。 --- ### 5. 监督训练目标 冻结 LLM 自回归生成目标答案 $Y_{\text{out}} = (y_1, \ldots, y_L)$，训练仅优化记忆模块参数 $\theta_{\text{mem}}$，最小化答案 token 的负对数似然： $$\mathcal{L}_{\text{sup}} = -\sum_{i=1}^{L} \log P(y_i \mid y_{<i}, X_{\text{LLM}}; \theta_{\text{mem}}) \tag{7}$$ 损失仅作用于答案位置，不覆盖提示或记忆位置。 --- ### 6. 渐进式三阶段训练课程 为使记忆模块先习得通用内容保留能力，再适应多样化下游任务，论文采用三阶段课程： - **第一阶段（通用预训练）**：在 198 万条英文 Wikipedia 复述重构数据上训练。文档被切分为块，模块需在固定记忆预算内保留足够信息，使冻结 LLM 能生成复述。此阶段提供任务无关的初始化。 - **第二阶段（多任务预热）**：在 134 万条混合数据上继续训练，覆盖阅读理解、开放域问答与摘要等 10 个数据集。多样的源结构与答案格式教导模块从同类型存储表示中召回不同信息。 - **第三阶段（下游多任务微调）**：在 8 个评估基准的训练集混合数据上统一微调。对于大多数基准，直接使用该多任务检查点；对于 PersonaMem-v2 与 PersonalizationV4，因验证损失需要更多轮次才收敛，额外进行基准专属微调。 --- ### 7. 关键设计实例化 在具体实现中，论文默认采用： - $K = 16$ 个记忆 token； - 冻结编码器：Qwen3Embedding-4B； - 冻结解码器：Qwen3-8B； - 可训练参数量：约 1.94 亿（仅记忆模块）。 这一设计使得文档无需以原始文本形式进入上下文，单个查询的端到端延迟在处理 512 篇文档时比完整上下文推理降低约 27 倍，同时实现超过 4000 倍的上下文压缩比。

Q4: 论文做了哪些实验？

论文围绕 MEMORILLA 的有效性、效率与机制展开了一系列实验，涵盖监督学习下的记忆压缩、持续学习场景中的智能体记忆，以及多维度的消融与计算分析。主要实验内容可归纳如下： --- ### 1. 监督基准测试与基线对比 实验在 8 个基准上评估 MEMORILLA，覆盖三大任务类别，并与多种基线进行系统对比。 **评估基准** - **个性化（Personalization）**：要求整合分散在用户历史对话或写作中的信息 - PersonaMem-v2 (PMv2, $n=5{,}000$) - PersonalizationV4 (PV4, $n=4{,}237$，本文合成) - LaMP-4 ($n=1{,}925$，个性化标题生成) - LaMP-7 ($n=1{,}500$，个性化推文改写) - **长文档问答（Long-document QA）**：测试将完整长文档压缩为可用表示的能力 - NarrativeQA (NQA, $n=10{,}557$) - TriviaQA ($n=500$ 验证子集) - **知识密集型问答（Knowledge-intensive QA）**：测试基于结构化或半结构化证据的事实推理 - FactKG ($n=9{,}041$，知识图谱事实验证) - PubMedQA ($n=100$) **对比基线** 所有基线均使用冻结的 Qwen3-Embedding-4B 编码器与 Qwen3-8B 解码器（除非特别说明）： - **Closed-book**：无外部文档，仅依赖参数知识 - **RAG-$k$**：基于余弦相似度检索 top-$k$ 文档块放入上下文（$k \in \{1, 5, 50\}$） - **Full Context**：将全部文档块按存储顺序放入上下文 - **LLMLingua-2**：硬提示压缩，通过 token 删除缩短文本 - **xRAG**：将单篇检索文档的嵌入映射为 1 个软 token - **Mem0** 与 **MemoRAG**：代表性智能体/记忆系统 - **ComMer**：基于报告结果的个性化生成对比（LaMP-4/7） **核心结果** - **平均性能**：MEMORILLA（$K=16$）取得最高平均分，且在所有基准上均位于帕累托前沿。相比 Full Context、RAG-50 与 MemoRAG，分别少用 $394\times$、$113\times$ 与 $49\times$ 的文档 token（几何平均）。 - **FactKG**：准确率 $84.33\%$，超过 Full Context 的 $80.43\%$（少用 $108\times$ token），表明压缩后的潜在记忆在关系推理上优于原始文本。 - **TriviaQA**：精确匹配 $57.00$，超过 MemoRAG 的 $56.60$ 与 Full Context 的 $52.60$（少用 $743\times$ token）。 - **PMv2**：短问答准确率 $44.60\%$，显著优于次优基线 xRAG 的 $30.90\%$；Full Context 在此基准上接近闭卷水平（$27.92\%$）。 - **LaMP-4**：ROUGE-L $18.15$，优于 Full Context 的 $14.21$（少用 $474\times$ token）。 - **PubMedQA**：因文档极短（平均 324 token），压缩收益有限，MEMORILLA（$59.00\%$）略低于部分基线。 --- ### 2. 记忆机制分析 为理解 MEMORILLA 学习到了何种表示，论文进行了细粒度的问题分解： - **概念推理 vs. 事实召回**（NarrativeQA）：在需要叙事结构与因果推理的 “Why”/“How” 问题上，MEMORILLA 分别领先 RAG-50 达 $+4.91$ 与 $+7.02$ ROUGE-L；而在可字面定位实体的 “Who”/“Which” 问题上，RAG-50 更优。这表明潜在记忆保留了全局结构，但可能丢失精确的表面词元。 - **多实体关系推理**（FactKG）：随着实体数量从 1 增至 4+，MEMORILLA 相对于 RAG-50 的优势从 $+4.23$ 个百分点扩大至 $+7.59$ 个百分点；当组合事实深度增加时，RAG-50 性能显著下降，而 MEMORILLA 保持稳定。 - **互补性分析**：在 FactKG 上，$15.9\%$ 的问题仅被 MEMORILLA 答对，$10.0\%$ 仅被 RAG-50 答对；两者并集的 oracle 上界显著优于任一单独方法，提示未来混合系统的潜力。 --- ### 3. 消融实验与架构分析 论文系统检验了设计选择对性能的影响： - **记忆架构消融**（表 13）：在 PMv2 上对比了多种槽位构造方式： - 全局/分段 mean-pool、参数匹配的分段/cosine top-16 硬选择； - **Documents only**（无查询条件化的 Q-Former 变体）：仅 $34.72\%$； - **Q-Former**（查询条件化 + 自注意力）：$43.34\%$； - **MEMORILLA**（查询条件化 + 交叉注意力，无自注意力）：$44.04\%$。 结果表明，**先条件化再读取**是关键，而非单独的文档交互或查询交互。 - **训练时记忆容量**（图 9）：对比 $K=16$ 与 $K=128$ 从头训练，发现增加 8 倍容量并未提升性能，在 PMv2 与 PV4 上反而下降，因此选择 $K=16$。 - Q5: 有什么可以进一步探索的点？

基于论文讨论与实验分析，以下方向值得进一步探索： ### 1. 混合记忆架构：潜在记忆与文本检索的融合 MEMORILLA 在捕获跨文档的全局关系与概念结构上表现优异，但在恢复精确的表面实体（如特定名称、日期）时可能弱于字面检索。实验表明，MEMORILLA 与 RAG 在答对的问题集合上具有显著互补性（例如在 FactKG 上两者并集的 oracle 上界显著优于各自单独使用）。未来可设计**将潜在记忆 token 与检索到的文本片段共同注入冻结 LLM** 的混合接口，兼顾语义整合与细粒度事实精准度。 ### 2. 面向记忆压缩的编码器专项训练 当前文档编码器（Qwen3-Embedding-4B）并非为记忆压缩任务专门设计，这可能是 MEMORILLA 在部分需要精确细节的基准上存在差距的原因之一。未来工作可探索**预训练或微调编码器以优化其信息保留密度**，使嵌入在极端压缩比下仍能保留更多细粒度事实，从而缩小与完整上下文或文本检索在实体级任务上的性能差异。 ### 3. 跨模型家族的迁移性验证 论文中编码器与解码器均来自 Qwen 系列，记忆模块的投影与槽位初始化均针对特定嵌入维度设计。尚不清楚该记忆机制在**跨模型家族**（如使用 Mistral 编码器与 Llama 解码器，或不同维度的组合）时的迁移与对齐难度。验证并提升跨架构的泛化能力，将显著增强该方法的实用性与部署灵活性。 ### 4. 向多模态记忆接口扩展 由于持久记忆库存储的是通用嵌入而非原始文本，理论上只要替换为多模态编码器，即可将图像、音频、视频等用户经验纳入同一记忆框架。未来可探索**将 MEMORILLA 扩展至多模态个人助手场景**，使模型能够回忆用户“看到过什么”或“听到过什么”，而非仅限于文本交互历史。 ### 5. 动态与自适应的记忆 token 预算 论文默认采用固定数量 $K=16$ 的记忆 token，且实验显示不同任务对容量需求各异（如个性化任务在 $K \ge 8$ 后才显著提升，而事实型任务随 $K$ 增加单调上升）。未来可研究**查询依赖的动态记忆预算分配机制**：例如让模型根据查询复杂度或文档集合规模，自适应地选择 $K$ 的大小，而非对所有查询使用固定压缩率。 ### 6. 在更多领域与复杂智能体任务中的验证 当前评估主要覆盖个性化问答、长文档理解与知识密集型问答。MEMORILLA 在**代码理解、数学推理、科学发现**等领域的适用性尚未验证。此外，TextWorld 实验仅涉及部分可观察的文本冒险游戏，未来可在**更长程、多步骤的真实世界智能体任务**（如软件工程、实验设计）中检验其持续学习能力。 ### 7. 隐私保护与设备端部署优化 论文指出每个用户的记忆是独立存储的嵌入矩阵，易于物理隔离或删除。未来可深入探索**端侧记忆管理**：如何在资源受限设备上高效维护与更新用户专属的持久存储，以及如何对嵌入进行加密或差分隐私处理，防止从存储的向量中反推敏感信息。 ### 8. 多智能体或跨 LLM 尺度的共享记忆基础设施 当前记忆模块与特定解码器维度耦合。未来可探索**统一的持久记忆存储池**，同时服务于不同规模（如 4B、8B、70B）的冻结 LLM，或为多个智能体提供共享的世界知识与经验存储，避免为每个模型或每个智能体单独维护冗余的文档索引与缓存。 ### 9. 解释性与记忆内容的可视化 尽管 MEMORILLA 展示了强大的检索与压缩能力，但 $K$ 个记忆 token 具体编码了哪些信息、如何随查询变化，仍缺乏系统性的可解释分析。未来可借助**探测分类器、注意力可视化或概念激活向量（CAV）**等方法，解析记忆槽位的专业化分工与信息聚合模式。 ### 10. 监督学习与强化学习的联合优化 论文在监督任务和 TextWorld RL 场景中分别训练了记忆模块。未来可研究**混合目标函数**：在拥有部分标注数据的同时，利用环境反馈或人类偏好强化学习（RLHF）进一步微调记忆读出策略，使潜在记忆既保持事实准确性，又优化下游决策质量。

Q6: 总结一下论文的主要内容

该论文提出 **MEMORILLA**，一种面向冻结大语言模型的潜在语义记忆系统，使其能够通过少量查询依赖的软记忆 token 高效利用大规模、持续增长的文档集合。以下是论文的主要内容总结： --- ### 1. 研究背景与核心挑战 大语言模型（LLM）在实际应用中需要利用参数之外的外部知识，如用户长期对话历史、超长文档或智能体的过往交互。对于冻结的 LLM，这些知识只能通过上下文窗口注入。现有方法存在明显局限： - **文本检索方法**（如 RAG、Mem0、MemoRAG）仅将筛选出的原始文本片段放入上下文，难以处理信息分散、与查询词汇重叠度低的场景，且上下文长度随文档量增长； - **查询无关的潜在压缩**（如 ICAE、AutoCompressors）将文档编码为固定软 token，无法针对不同问题动态调整； - **模型绑定记忆**（如 LongMem、MemoryLLM）将状态存储于模型内部表示，导致记忆与特定模型强耦合，缺乏可移植性。 核心挑战在于：如何为冻结 LLM 提供**查询相关的、来自整个文档集合**的信息，同时保持**极短的上下文长度**。 --- ### 2. MEMORILLA 方法概述 MEMORILLA 通过三步流程解决上述问题： 1. **编码（Encoding）**：冻结的嵌入模型将每个文档块（如用户对话、书章）一次性编码为向量； 2. **存储（Storage）**：这些向量构成持久化的记忆库，可被后续所有查询复用； 3. **检索（Retrieval）**：针对每个查询，一个轻量的可训练记忆模块从整个记忆库中读取信息，生成固定数量 $K$（默认 16）个**查询条件的软记忆 token**，直接注入冻结 LLM 的输入嵌入空间。 关键特性在于：文档无需以文本形式进入 LLM 上下文，LLM 本身无需任何微调或架构修改。 --- ### 3. 架构与训练细节 **持久记忆库构建** 给定 $N$ 个文档块 $\mathcal{D} = \{d_1, \ldots, d_N\}$，冻结文档编码器 $f_d^{\text{enc}}$ 生成： $$Z_D = [f_d^{\text{enc}}(d_1), \ldots, f_d^{\text{enc}}(d_N)] \in \mathbb{R}^{N \times h_e} \tag{1}$$ 该矩阵计算一次后持久保存。查询 $q$ 由冻结查询编码器映射为 $z_q = f_q^{\text{enc}}(q) \in \mathbb{R}^{h_e}$。 **查询条件检索模块 $f_{\text{mem}}$** 模块包含四个阶段： - **记忆槽初始化**：$K$ 个可学习向量 $Q_0 \in \mathbb{R}^{K \times h_e}$； - **查询条件化**：通过交叉注意力将 $Q_0$ 与 $z_q$ 交互： $$Q_c = \text{LayerNorm}\left(Q_0 + \text{CrossAttn}(Q=Q_0, K=z_q, V=z_q)\right) \tag{3}$$ - **文档检索**：条件化槽位通过 $L_{\text{ref}}$ 层交叉注意力在全部文档嵌入上连续读取（Perceiver 风格），实现全局、连续的查询相关 readout； - **投影**：通过 $W_{\text{proj}} \in \mathbb{R}^{h_e \times h_L}$ 映射到 LLM 输入维度，输出 $M = [m_1; \ldots; m_K] \in \mathbb{R}^{K \times h_L}$。 **注入冻结 LLM** 最终输入序列为记忆 token 与查询文本嵌入的拼接： $$X_{\text{LLM}} = [\underbrace{m_1, \ldots, m_K}_{\text{soft memory tokens}}; P_q] \tag{6}$$ LLM 通过自注意力直接处理这些记忆 token。 **训练** 仅优化记忆模块参数 $\theta_{\text{mem}}$，目标为答案 token 的负对数似然： $$\mathcal{L}_{\text{sup}} = -\sum_{i=1}^{L} \log P(y_i \mid y_{<i}, X_{\text{LLM}}; \theta_{\text{mem}}) \tag{7}$$ 采用三阶段课程：Wikipedia 复述重构预训练 → 10 个数据集的多任务混合训练 → 8 个评估基准的下游多任务微调。 --- ### 4. 实验结果 **监督基准测试**（8 个基准，3 类任务） - **个性化**：PMv2、PV4、LaMP-4、LaMP-7 - **长文档 QA**：NarrativeQA、TriviaQA - **知识密集型 QA**：FactKG、PubMedQA **核心性能** - MEMORILLA 在平均性能上领先所有基线，且在每个基准上均处于**帕累托前沿**。 - 相比 Full Context、RAG-50、MemoRAG，分别使用 $394\times$、$113\times$、$49\times$ 更少的文档 token（几何平均）。 - **FactKG**：准确率 $84.33\%$，超越 Full Context 的 $80.43\%$（少用 $108\times$ token）； - **TriviaQA**：精确匹配 $57.00$，超越 MemoRAG 的 $56.60$（少用 $743\times$ token）； - **LaMP-4**：ROUGE-L $18.15$，超越 Full Context 的 $14.21$（少用 $474\times$ token）； - **PMv2**：短问答准确率 $44.60\%$，显著优于次优基线 xRAG 的 $30.90\%$。 **TextWorld 持续学习实验** 在部分可观察的文本游戏环境中，智能体每回合将交互历史存入记忆库。通过 GRPO 仅训练记忆模块： - 相比完整历史上下文的 ICL 基线，avg@3 从 $18.6\%$ 提升至 $24.2\%$，pass@3 从 $25.0\%$ 提升至 $37.5\%$； - 有效减少智能体在已探索房间间的循环导航，帮助执行关键动作序列。 --- ### 5. 关键发现与分析 - **概念推理 vs. 事实召回**：MEMORILLA 在需要叙事结构与因果推理的 “Why”/“How” 问题上显著优于 RAG，但在可字面定位的 “Who”/“Which” 问题上稍弱，两者具有高度互补性。 - **多实体关系推理**：在 FactKG 上，随着实体数量与组合事实深度增加，MEMORILLA 优势扩大（从 $+4.23$pp 到 $+7.59$pp），而 RAG 性能显著下降。 - **消融验证**：查询条件化是性能关键；固定 $K=16$ 在训练与推理中取得良好效率-性能平衡；相比同等参数量的 LoRA 适配器，MEMORILLA 的增益来源于对存储证据的有效读取，而非仅对解码器的通用适应。 - **计算效率**：处理 512 篇文档时，MEMORILLA 端到端延迟约 $0.74\,\text{s}$，而 Full Context 达 $19.9\,\text{s}$；文档嵌入存储仅为对应 KV 缓存大小的 $1/7266$。 --- ### 6. 结论与展望 MEMORILLA 证明了冻结 LLM 可以通过一个学习的、查询依赖的潜在记忆接口来有效利用累积知识，无需依赖检索文本或不断扩展的提示。其在个性化、长文档问答和知识密集型任务上展示了领先的压缩与推理能力，并支持智能体在强化学习环境中持续学习。 未来工作可探索：潜在记忆与文本检索的混合架构、面向压缩优化的专项编码器训练、跨模型家族的迁移性、多模态记忆扩展，以及更长程复杂智能体任务中的验证。
