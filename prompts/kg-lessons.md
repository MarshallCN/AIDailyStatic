# KG 抽取经验库

这个文件由 Hermes 在每日审计后维护，内容会被自动注入 `kg-extract.md` 的「已积累的抽取经验」小节。
它是知识图谱质量的长期记忆：昨天被扣分的地方，今天变成硬规则。

维护规则：

- 每条经验写成**可执行的指令**，不要写感想。能写进审计器的规则就去改 `scripts/kg_audit.py`，写不进的才放这里。
- 条目格式：`- [YYYY-MM-DD] 指令。（触发原因：某次审计的具体扣分项）`
- 上限 25 条。超出时合并同类项、删掉已经连续 5 天不再复现的条目，保持 prompt 精简。
- 高频实体、易错命名、反复出现的主体写进「实体规范名对照」小节，这是跨文章连通的关键。

## 通用经验

- [2026-10-14] 多个模型横向互锁定价/同价这类核心论点应抽成实体间的 comparable_price（或 comparable）关系，不要只写进事件 summary 而让文章缺边。
- [2026-10-15] 不要把编辑性观察/why_it_matters 评论包装成带参与方的事件；事件必须是新闻中实际发生的动作（发布、融资、起诉、执法、披露），分析性总结一律放回 why_it_matters。
- [2026-10-15] evidence 只能采用本条新闻明确指出、在本篇可验证的事实；引用『上一轮/此前报道』或既往记忆里的数字（如市场份额、产业份额）不得作为本条 evidence，如需借用须标注为外部引用或删除精确数字。
- [2026-10-15] 同一类法律关系跨文章必须统一关系类型：诉讼用 sues/countersues，不要用语义模糊的 targets 兜底；捐赠/资助与股权投资的 invests_in 要严格区分。
- [2026-10-16] 关系边的 evidence 必须直接支撑该断言；'与某指南/报告相呼应'之类的提及不能作为两机构存在合作伙伴关系的证据。
- [2026-10-16] 当文章表述某结果'呼应/印证了 X 早前的观点'时，方向是事件印证 X 的观点，不要抽成某方 --responds_to--> X。
- [2026-10-16] 同一篇里性质不同的多个动作（产品预览、安全悬赏、访问权赠予、奖学金等）应各自成事件，不要压成一个 trend 事件。
- [2026-10-17] 跨文章引用同一硬件/模型时必须统一规范名并在 aliases 里并入其他写法（如 MI350P、Gemma 4 31B 的 it 变体），否则图谱无法跨文章连通。
- [2026-10-17] 破产/IP 处置新闻中，竞标方仅以 stalking horse 身份购买部分知识产权时不要用整体 acquires 关系，应按实际买入内容（如 buys_ip_from / licenses_to）并写明范围。
- [2026-10-17] 事件类型 open_source 仅用于真正开源权重或代码；面向所有用户开放按次计费的商业 API 属于 launch，不要误标。
- [2026-10-18] 融资/债务/贷款类新闻中不要用 licenses_to 描述借款、贷款转售或债券抛售等行为；licenses_to 仅用于真正的许可/授权关系，融资行为应表达为与其语义相符的关系或作为事件处理。
- [2026-10-18] 遇到高信息量但关系严重不足的文章时，应逐个检查被点名主体是否存在可验证的实体边，为孤立实体（尤其出现在标题或正文多次的主体）补一条有证据支撑的关系，或明确删除，而不是让无边实体残留在图谱里。
- [2026-10-18] 当一篇新闻用泛称指代模型/产品家族（如 Muse）而同日另有具体型号（Muse Spark Open、Muse Code）时，应在 aliases 或证据中注明泛称的确切所指，避免跨文章实体被误合并或误判为无关实体。
- [2026-10-19] 模型退役/关停类新闻中，每个被关停的具名模型（尤其标题点名的旗舰如 gpt-4、o1）都要抽成 type=model 实体并作为关停事件的 object 参与方、补 deprecates 关系，不能只让公司主体出现在事件里。
- [2026-10-19] affiliated_with 表示当前隶属关系；原文明确写"前员工/前工程师"（former）时不要用 affiliated_with 表达历史雇佣，应改用历史隶属类型或在证据中标注 former。
- [2026-10-19] 子组件/平台是父产品的一部分时（如"XX 的中控平台"），用 component_of/part_of 而非 developed_by；developed_by 只用于独立产品与其开发者/出品方。
- [2026-10-20] 法案/提案尚未生效时，其中的监管机制不得抽成现存 regulates 关系，应把机制挂到草稿本体或用 proposal 类关系表达，否则图谱会陈述不存在的现状。
- [2026-10-20] 动作型关系类型（targets、regulates、supplies）只能用于真实发生的行动；"某公司把某对象定性/警示为威胁"这类分析性表述应改用描述类关系，不要照搬动词。
- [2026-10-20] competes_with 需要直接竞争依据（如市场份额、正面竞标/对标）；单纯的业绩担忧、增速对比或估值下修不构成竞争关系，不要用旁证推断。
- [2026-10-21] 事件 summary 里的数量与基数（厂商数、金额、百分比）必须逐字对回原文（如三/四大云提供商、十/二十余家），凭印象近似或照抄记忆都会造成与原文直接冲突的事实错误。
- [2026-10-21] 一篇含多组独立实测/演示的新闻（节水、电网调峰、各厂商吞吐基准）按每次测量拆成独立事件，每个事件的 evidence 只放支撑自身断言的句子，不要把甲演示的数字挂到乙事件的摘要里。
- [2026-10-21] 事件 summary 与关系不得把「正在洽谈/计划/拟」升级为已发生动作（参投、发布、达成），原文未敲定的动作保持未定语气并如实写进证据。
- [2026-10-22] 公司内部的 AI 分部（如"某公司的 AI 部门"）应标注为分部/子组织类型，不要一律标成 company。
- [2026-10-22] 收购完成后的"能力并入某产品"事件不要用 partnership 类型，应归为 acquisition 或 integration。
- [2026-10-22] compared_with 只用于有性能/指标对比的证据；"两家做法或策略不同"不是性能比较，不应建 compared_with 边。
