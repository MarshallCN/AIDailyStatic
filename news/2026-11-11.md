## AlphaGenome 2：从粗组织走向单细胞，预测罕见病相关遗传变异，识别因果变异近乎翻倍
- source: Google DeepMind
- date: 2026-11-11
- category: 应用/产业
- url: https://deepmind.google/blog/alphagenome-2-deciphering-how-cells-read-dna-to-better-understand-disease/
- summary: Google DeepMind 发布下一代 DNA 序列模型 AlphaGenome 2，把预测从粗组织平均缩放至数百种人类细胞类型与状态，识别到的因果变异数量接近翻倍，并支持跨模态填补与输入自身单细胞实验。
- detail: |
    Google DeepMind 于 11 月 11 日发布 AlphaGenome 2，新一代模型预测 DNA 序列及其变异如何影响特定的细胞类型与细胞状态，为寻找疾病细胞层面驱动因素提供新工具。与上一代的“固定平行输出组织与细胞系”不同，AlphaGenome 2 改为条件式模型：每次只预测一个“条件”（组织、细胞类型或状态），把目标生物条件作为输入贯穿整个架构，从而学会相同 DNA 在不同细胞类型里如何被“读出”差异。

    训练数据超过 1.07 亿个单细胞谱、覆盖 68 种组织。条件式设计带来跨模态填补：输入单个测量（如单细胞基因活性），模型即可预测未测量属性（如染色质可及性），帮助科学家优先安排后续实验。在 TenK10K 单细胞数据上，AlphaGenome 2 识别的因果变异数量（30% vs 16%）与定向基因效应（43% vs 23%）约较前代翻倍。

    在真实生物学验证中，模型重现了此前已知的 IBD 致病机制——一个位于远端调控开关的变异通过在肠道巨噬细胞里过度激活 ETS2 基因致病，AlphaGenome 2 能单单锁定该因果变异而几乎不影响其他细胞与基因。模型今日起面向非商用研究通过 AlphaGenome API 开放，并进入商用研究私测；后续还将作为 AlphaGenome 2 Skills 出现在 Antigravity。

## 论文：什么时候该让 agent “记住”？基于证伪门控的自进化（arXiv:2611.14326）
- source: arXiv
- date: 2026-11-11
- category: 论文
- url: https://arxiv.org/abs/2611.14326
- summary: 新论文提出“证伪门控”（falsification-gated）的自进化机制，回答“LLM agent 何时该更新记忆”，只在对既有认知构成威胁的反例出现时才把经验沉淀为记忆。
- detail: |
    arXiv 论文《When Should Agents Remember? Falsification-Gated Self-Evolution for LLM Agents》聚焦自进化 agent 的一个基础问题：什么时候应当把一次经验“记住”（固化为可复用的记忆/技能）。毫无门槛地吸收经验会累积噪声，而过早固化又可能把错误规则焊死。

    作者提出“证伪门控”机制：为候选记忆设置一道以证伪为核心的检查，只有当经验/结论能够经受住反例检验、对既有认知构成真正的挑战时才被采纳写入记忆，否则被暂缓或丢弃，从而让 agent 的记忆保持精简且可靠。

    该工作呼应近期对“自进化 LLM agent 会被任务投毒植入后门”的担忧（见 2611.10542）：记忆既是能力来源也是攻击面，如何审慎地决定“何时更新记忆”正成为自进化系统安全与可控性的关键。对记忆管理做门控，是把防线前置到数据吸收这一层。

## 论文：ReTrace——把会调用工具的 agent 蒸馏成“无需规划器”的确定性工作流
- source: arXiv
- date: 2026-11-11
- category: 论文
- url: https://arxiv.org/abs/2611.14492
- summary: 新研究 ReTrace 把一份 SOP 与几条已记录的 agent 运行轨迹蒸馏成可复用的确定性工作流，让“代码而非 LLM”来决定下一步，大幅降低规模化执行的延迟与成本。
- detail: |
    arXiv 论文《ReTrace: Distilling Tool-Using Agents into Planner-Free Workflows》解决的是业务流程自动化的一个现实痛点：LLM agent 能按自然语言写成的 SOP 逐句执行，但每一步都要调用 LLM 做决策，规模化后延迟与成本可观。

    ReTrace 把一份 SOP 和几条已记录的 agent 运行日志转化为可复用工作流，在其中由“代码而不是 LLM”来选择下一步。它利用 agent 在每个工具调用时写下的解释（reasoning）——这些解释往往说明了它为何采取某动作，而仅凭工具调用看不到——提取出每个步骤背后的触发条件，跨多次运行合并为一份紧凑的规则文档，并生成可执行的流水线。

    结果是把“每步都用 LLM 想”的通用但昂贵模式，蒸馏成“条件明确、代码执行”的高效确定性工作流，同时保留 SOP 的语义。对大规模、重复性的企业流程自动化（如运维 SOP、数据处理流水线）是直接的成本与延迟优化方向。

## Google 为 MaxText 加入长上下文训练：原生序列长度最高扩到 1400 万 token
- source: Google Developers
- date: 2026-11-11
- category: 基础设施
- url: https://developers.googleblog.com/announcing-long-context-training-on-tpus-with-maxtext-context-parallelism
- summary: Google 在 JAX 训练框架 MaxText 中加入上下文并行（context parallelism），把 Cloud TPU 上的原生序列长度从约 20 万扩展到最高 1400 万 token，配四种并行策略。
- detail: |
    Google Cloud 宣布在 MaxText（其开源 JAX LLM 训练框架）中加入长上下文训练能力，通过四种上下文并行（context parallelism）策略把 Cloud TPU 上的原生序列长度扩展到最高 1400 万 token，全部运行在开源 Tokamax Splash Attention 内核上以绕过内存瓶颈、避免 OOM。

    四种策略针对不同场景：All-gather（当激活能放得进片上内存时的标准基线）、A2A、P2P（Ring Attention，超长上下文的“主力引擎”）、以及 A2A+P2P 混合的 Unified Sequence Parallelism（USP）。评测数据：Llama 3.1 8B 在 TPU v5p 上 400 万 token 内达到 70% MFU；TPU 7（Ironwood）在 600 万 token 以下维持 50% MFU，并可持续到 1400 万 token。

    MaxText v0.2.4 已发布，支持 TPU 7 与 v5p 样例配方。随着预训练/后训练走向需要整库代码库或长视频的 agentic 任务，能原生训练超长上下文正成为训练框架的关键差异化能力。

## Fireworks AI 第二次遭入侵：账单数据、不完整模型权重与 Notion AI 对话外泄扩大
- source: The Register
- date: 2026-11-11
- category: 安全
- url: https://theregister.com/cyber-crime/2026/11/10/fireworks-ai-gets-burned-twice-as-customer-data-exposure-widens/5308722
- summary: Fireworks AI 披露又一起网络攻击，客户数据暴露面扩大至账单记录、数据集与部分不完整模型权重，且波及 Notion AI 聊天记录；调查指向从事 LLMJacking 的网络犯罪团伙。
- detail: |
    Fireworks AI 披露其 10 月安全事件调查范围再度扩大。攻击者在 10 月 23 日攻破一家托管 Fireworks 研发机器的第三方云厂商，次日借该访问进入 Fireworks 开发系统并运行未授权负载，导致更多客户数据受影响，涉及资源元数据、账单信息（地址、发票记录、余额与用量），以及部分客户的一小部分不完整模型权重与数据集。Fireworks 不存储支付卡号，故未受波及。

    事件波及面延伸到下游用户：Notion AI 的部分聊天记录（用于 Insights 功能）被外泄，Render 等客户收到警告；Fireworks 还正与 Cursor、Harvey 等客户共同评估影响。公司在 10 月 9 日首次披露过一次入侵（内部凭据被滥用、评估任务中的 API 密钥与 token 泄露），数周内遭遇第二起。

    调查线索指向一个以牟利为目的的网络犯罪团伙，其手法是把 LLM 的未授权访问 token 转售给非法路由网关，即所谓“LLMJacking”。Fireworks 已与 Palo Alto Networks 的 Unit 42 协作整改（轮换凭据、隔离受影响系统、收紧存储访问）。对依赖第三方推理/训练基础设施的公司，这是一次供应链风险的现实提醒。

## 观察：agent 大战聚焦“知识工人”，AI 巨头从一个入口抢到办公的每一个动作
- source: Fortune
- date: 2026-11-11
- category: 观察
- url: https://fortune.com/2026/11/10/anthropic-launches-office-knowledge-worker-product-launch-ahead-of-ipo/
- summary: 从 Anthropic 把 Claude 塞进会议与表格、Databricks 让 agent “永不下线”，到 OpenAI 关闭旧语音、收购旅行 agent，AI 公司正围绕“知识工人”发起全面进攻，并都指向 agent 时代的入口之争。
- detail: |
    本周三（11 月 11 日）前后，几乎每天都有巨头官宣面向“打工人”的 agent 功能，构成了一幅清晰的产业拼图：Anthropic 发布 Claude Meetings（实时加入 Google Meet 干活）、Claude Sheets、Whiteboards 与 Data；Databricks 推出“永不睡觉”、后台陪跑的 Genie agent 与扫描全组织的 Ontology；OpenAI 一边把语音收拢到 GPT-Live、一边通过收购 Odessia 押注“ChatGPT 帮人规划旅行”。一天之内，三家公司从不同入口争夺同一批用户——每天坐在办公桌前用工具干活的人。

    驱动这一切的是一组数字：Anthropic 在招股书中估算 2025 年全球知识工人创造的经济价值超过 40 万亿美元，并断言前沿 AI 能“显著提升其生产力”。这意味着知识工人是比程序员大几个数量级的付费市场，也是本轮 AI 商业化从“写代码”走向“做办公室工作”的主战场。

    竞争正变得结构化：赢家拼的是能否把 agent 真正嵌进每天的工作流（会议、表格、数据、消息），而非单点模型能力。Databricks 手里握着企业数据，Anthropic 与 OpenAI 握着前端对话入口与顶尖模型：谁能同时拿到“数据 + 入口 + 模型”的任两端，谁就可能在 agent 时代掌握办公室的数字核心。这场战争的终局，将决定 AI 是从“工具”变成下一代“办公操作系统”，还是继续停留在辅助插件的层面。
