## Phronix（arXiv 2610.31789）：让 agent 的“外围工具链”从自身执行中积累可复用能力，便宜模型 SWE-bench 解决率从 29%/27% 拉到 91%/87%
- source: arXiv
- date: 2026-10-26
- category: 论文
- url: https://arxiv.org/abs/2610.31789
- summary: 新论文提出 Phronix——一种“以能力为中心”的 agent 学习范式：让 agent 的工具链（MCP 工具、skills、记忆）通过预测器—验证器—纠正器循环，从自身的真实执行中获取、验证并打磨可复用能力，而不是依赖人工编写的 skill。结果显示：学到的能力让重复任务首次尝试成功率到 93-95%，两个便宜模型在 SWE-bench 上的解决率从 29% 和 27% 分别提到 91% 和 87%，追平最贵评估模型。
- detail: |
    核心机制：科学计算越来越依赖 LLM agent 做插桩、分析与工作流移植，但 agent 的有效性被“外围 harness”卡住——skills 靠手写、记忆靠整理，agent 每趟都重新发明轮子。Phronix 让 harness 从执行历史里蒸馏能力（capability store），遇到失败任务会“研究”它而不是放弃：每次工具执行都被验证并回写能力库，后续任务直接复用。论文在 1000 Genomes Pegasus 工作流上（生产应用 IO 性能分析插桩）11/11 通过正确性检查（基线 harness 为 6/11）。

    数字与意义：学到能力后，跨模型重复任务首次尝试成功率 93-95%（显著降低方案不确定性）；每个任务能在无用户指令下沉淀 7.6-30.8 个持久能力、所需能力已存在时降到 2 个以下；热启动每任务仅耗 0.38-0.40M token，比单次基线尝试低 3-4 倍。最有信号的是“能力迁移”：两个便宜模型在 SWE-bench 上从 29%/27% 提到 91%/87%，追平最贵评估模型——暗示“harness 中沉淀的组织知识”比“模型参数量”更能决定 agent 实际表现，也让“把工具链做成可积累资产”成为一个可量化的研究方向。

## “基准其实很吃压缩”（arXiv 2610.31778）：三模型三长程基准实测——compaction 丢弃的约束可能比模型能力更影响分数
- source: arXiv
- date: 2026-10-26
- category: 论文
- url: https://arxiv.org/abs/2610.31778
- summary: 图宾根团队（Salle、Bhatnagar、Bethge）的新论文在三个前沿模型、三个长程 agent 基准（PaperBench、ProgramBench、PostTrainBench）上、用统一 OpenCode 脚手架实现五种压缩策略，发现当前 agent 基准对上下文压缩“异常友好”：固定目标 + 持久文件系统让被压缩掉的内容大多可恢复，1M 上下文模型性能几乎不受压缩阈值影响；但压缩会悄悄删掉任务约束——ProgramBench 上第一次压缩平均就丢掉三分之一的反作弊规则，且会随压缩次数累积。
- detail: |
    两个方向的结果：一方面，由于基准目标固定、无人介入、agent 有持久文件系统，被 compaction 丢弃的信息大多可以从任务本身重建，因此三个模型在长程基准上的分数对压缩并不敏感（两个 1M 上下文模型尤甚）——这意味着“把 agent 上下文压掉一半还能拿同样分数”未必说明模型强，而是基准设计给了免费重建路径。另一方面，压缩会静默损坏约束：ProgramBench 第一次压缩平均丢掉约 1/3 的反作弊规则（禁止抄参考、禁止联网等），丢得越多叠加越严重、且模型间差异很大；真实用户会话里压缩保留约 81% 的用户约束，但“怎么做、别做什么”类指令被丢弃的概率约为“做什么”类规格的 6 倍。

    为什么重要：这篇论文正好戳中本周基准悬案的方法论要害——ARC Prize 上周披露 GPT-6 Astra 在同一模型上标准 harness 62.7%、Provider Adapter harness 99.9%（两者差在“跨请求保留隐藏推理状态 + 压缩”），OpenAI 宣传口径用 99.9%，黄仁勋据此宣称“AGI 已至”。压缩友好性研究给出第三条路径的证据：harness 的上下文管理（保留什么、压掉什么）正在成为比模型权重更影响分数的变量；agent 评测的“脚手架公平性”与“约束可审计性”，会像当年的数据泄露一样，成为基准可信度的新战场。
