- source: Semianalysis
- date: 2026-10-06
- category: 观察
- url: internal:semianalysis/2026-10-05__anthropic-subscriptions-offer-5x__member-visible
- summary: SemiAnalysis 用实验「极限测试」了 Anthropic、OpenAI、Meta、SpaceXAI、MiniMax、Moonshot、Z.ai、Cursor、Cognition 等主流 AI 订阅计划的限额，发现同等价位下 Anthropic 的 API 等价价值普遍比 OpenAI 高出约 5 倍。
- detail: |
    SemiAnalysis 发布了一份对各大 AI 订阅计划的系统性「限额压力测试」。作者的核心方法是通过精心设计的实验，只让请求命中某一种 token 类型（未缓存输入、缓存写入、缓存读取、输出），然后观察各平台上「用量表」移动的幅度，逐步反推出每个 (计划、模型、token 类型) 组合的实际计价率。由于大多数请求根本不会让计量表移动，他们用「累计多少 token 才推动计量表前进一格」的方式统计，并把误差控制在 ±5% 以内。

    结论相当惊人：在终端用户最常使用的「日常主力模型」档位——OpenAI 的 GPT-6.1 Sol 对比 Anthropic 的 Opus 5.5——Anthropic 提供的 API 等价价值全面高出约 5 倍。即便退一步只比较可获得的 token 数量，这一差距也依然巨大。报告强调，订阅额度高度补贴，仅占 OpenAI/Anthropic 营收约 10%，却可能消耗超过 40% 的推理算力，并把每 MW 的混合收入拉低约 3600 万美元，因此「订阅限额」是准确建模实验室财务的关键变量。

    报告还还原了 OpenAI 上周的大动作：其 $200/月计划 API 等价价值被整体腰斩，并新推出 $500 档；新 $500 档的 Astra 用量只比旧 $200 档多 21%，Sol 类模型的价值甚至因 6.1 Sol 的缓存降价反而下降。而 Anthropic 选择了更「含蓄」的路径：通过为更高级模型（尤其 Fable 5.1）保留更低的隐含额度来逐步削减补贴，而非一夜砍平。对第三方包装商（Cursor、Cognition）而言，Anthropic 自家计划哪怕是 9 倍更慷慨的限额，其订阅毛利反而更高——这正是「自持模型」相对「包裹他人 API」的结构性优势。

## 论文：用 LLM 做编译器优化，但用形式化验证把「正确性」设为外部控制层
- source: arXiv
- date: 2026-10-06
- category: 论文
- url: https://arxiv.org/abs/2609.27214
- summary: 一篇 arXiv 新论文探索「验证式学习」框架：微调代码大模型生成 LLVM lazification 变换，但用 Alive2 做形式等价性检查，只在语义不变时才接受每次改写。
- detail: |
    这篇论文研究 LLM 能否以「由验证器把关」的方式参与编译器优化，而不是把正确性交给模型隐式学习。以 LLVM IR 中的 lazification（把求值转为惰性按需语义）为例：系统先用 Wyvern 优化器生成已验证的训练样例，微调一个代码中心 LLM 来学习这类变换模式，再在推理阶段用 Alive2（形式等价性验证器）对每个候选改写做符号验证——只有证明语义保持的改写才被接受，失败的改写会带着诊断信息触发重新生成。

    关键设计是「生成与正确性分离」：正确性不是模型学会的，而是由验证器在运行时作为外部控制层强制施加。在 LLVM 测试集上，微调模型复现了核心优化行为且整体应用更少的变换；虽然 Wyvern 在多数基准上仍更快，但在 9.8% 的样例中该学习系统达到或超越其运行时，且未观察到任何语义违规。验证开销有界、收敛稳定。

    它的意义是给出一个「把自适应生成集成进关键基础设施」的可复用模式——用确定性验证 + 受控反馈环，让生成式组件在保证可靠性的前提下进入编译器流水线。这与本周 OpenAI 强调「人类监督 + 模型校验」的计算机使用路线、以及 Rust 生态用形式验证（如 Aeneas + Lean）支撑 AI 生成代码的趋势同向：生成负责广度，验证负责边界。
