## 论文：Galahad-KV——把 KV 缓存落盘复用，50M token「长期记忆」比重算快 2.8–4.3 倍、省 8.8–12.3 倍能耗

- summary: Corbenic AI 的预印本展示一个公开包 galahad-kv：把模型为每个约 16k token 块算出的 KV 注意力状态写入加密 NVMe，之后可字节级精确恢复、零重算、GPU 内存恒定。在 vLLM 单卡 H100 上对 5000 万 token 语料测试，Gemma 4 12B/31B 的 100/100 个探测块全部免重算恢复，恢复比重算快 2.8–4.3 倍、省 8.8–12.3 倍 GPU 能耗；回答数百万 token 前埋下的事实，12B 答对 82/100、31B 答对 98/100，零幻觉。
- detail: |
    常规的 Transformer 服务是无状态的：每次请求都会重算 prompt 的 KV 注意力状态。这篇论文把「已算过的状态」变成可复用资产——galahad-kv 层把每个约 16k token 块的 KV 以 AES-256-GCM 加密写入本地 NVMe，后续请求需要某块时直接从磁盘「嫁接」回来，模型继续前向就像刚算过一样，权重完全不变。因为采用滑动窗口注意力，12B 的 50M token 存储约 1.86TB（36.4 KiB/token），31B FP8 约 6.25TB。

    测量结果的核心不是「缓存」而是「成本结构改变」：恢复一块的中位耗时 0.27–0.35 秒，而重算同样内容要 0.76–1.48 秒；能耗从 521–976 J 降到 59–80 J。关键是深度无关——50M token 之前的块与第一个块恢复同样快，VRAM 全程持平。防作弊协议（负对照组 0/20 编造）与单卡复现脚本让结论可独立验证。

    这不是把注意力窗口加宽，而是「状态持久化」：一次写入、无限次便宜复用。若这类方案在 vLLM/SGLang 生态扩散，影响是结构性的——长上下文与「长期记忆」的边际成本从「每次重算」变成「一次落盘」，推理的能源账单和延迟曲线都会被改写。作者也坦白局限：一次只驻留一块、恢复不是真正的注意力扩展、正确性取决于模型本身；这更像给「推理无状态」这条默认假设装上了一个可验证的反例。

    推理模型受益于测试时缩放，但想太久会从「有效推理」滑向「有害推理」——这就是过度思考（overthinking）。以往评估只比较「全量思考 vs 无思考」的准确率与 token 用量，缺少对「过度思考有多严重」和「终止策略理论上能挽回多少」的参照系。这篇论文给出了一套可复现的度量：STP 沿同一条采样轨迹的多个保留前缀反复生成，把每条轨迹上最早达到最大经验准确率的位置当作参照，之后多花的思考 token 占比即「过度思考率」，从参照点到全量思考的精度损失即「精度退化」。

    在此基础上，作者把动态路由、固定预算、动态早停统一进一个框架，用完整的 STP 测量在统一思考 token 预算下构造每种策略的 token-精度帕累托前沿，回答「哪种终止策略最划算」。作为副产物，OTBench 基准由 STP 过程直接构建，累计产出 70.5B 推理 token 及相应探针测量，覆盖 6 个模型、4 组基准，全部测量公开可复用。

    这篇论文的价值在于把「别想太久」从一个工程直觉变成一套带参考系的指标：有了「过度思考率」和帕累托前沿，模型厂商就能在发布前量化地选择终止策略，而不是靠拍脑袋截断。它与上周「AI 数学规模 vs 验证裂」的讨论同频——当推理 token 成本与「想过头反而答错」同时成为瓶颈，度量过度思考本身就成了基础设施级的竞争力。
