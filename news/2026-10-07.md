## 论文：EESD——按「证据强度」自适应加权的自蒸馏，提升编程 agent 的自我纠正
- source: arXiv
- date: 2026-10-07
- category: 论文
- url: https://arxiv.org/abs/2610.08514
- summary: 论文提出 Effective-Evidence Self-Distillation（EESD），把执行反馈的支持度与证据质量分开表示，用一个带不确定性惩罚的 Dirichlet 伪计数对抗训练的自蒸馏权重，让编码 agent 从自身纠正中学得更稳。
- detail: |
    执行反馈能让编码 agent 修改程序并从自己的修正里学习，但一条纠正确实该背多重的学习权重，取决于它被多少条执行路径支持、以及这些证据有多可靠。EESD 把这两者分开建模：用归一化的执行相关性刻画对转移的相对支持，用一个有效的伪计数质量刻画证据量，再经 Dirichlet 后验得到一个带不确定性惩罚的权重，用于 KL 锚定的纠正学习。

    实验显示，在四组「模型 + 领域」历史扫描中，把可见观测从 1 条加到 8 条，未来结果的 NLL 下降 55.0%–59.3%；八条观测下有效质量在四个对比里全部优于固定质量。在主推的 DeepSeek/RunBugRun 配对研究中，argmax 预测在全部 3000 个例子上一致，而一轮纠正学习后 DeepSeek/CodeARC 的 all-tests Pass@1 从 15.0% 提升到 20.4%（95% 置信区间 [+2.8, +8.0] 个百分点）。

    横跨 12 组设置的下游评测界定了这一更新的适用范围。它的价值在于：剥离「证据支持」与「证据质量」之后，纠正学习的概率估计变得更可控，也给「agent 该从自己错误里学多少」提供了一个此前缺位的量化杠杆。

## 论文：ParanoiaEval——衡量 agentic 编码里「不必要的防御性工作」的新基准
- source: arXiv
- date: 2026-10-07
- category: 论文
- url: https://arxiv.org/abs/2610.08662
- summary: 新基准 ParanoiaEval 首次系统评估编码 agent 的风险处置能力，发现即便面对明确证据，仍有 11.2%–58.7% 的运行发生不必要的防御性工作，且更强的任务能力并不保证更恰当的风险处理。
- detail: |
    随着编码 agent 自主承担越来越多真实工作，如何判断它对风险的「处理是否合理」变得重要——过度防御会拖慢开发、完全无视风险又会出问题。ParanoiaEval 把软件工程里成熟的风险处置框架（规避–转移–缓解–接受，Avoidance-Transfer-Mitigation-Acceptance）落到编码 agent 场景，构造了 200 个证据受控的成对仓库级任务，每对只在界定处置的证据上有差异，并配了专门的风险处置违规度量与（人类校准的）agentic 评判。

    在 8 个代表性模型上的大规模实验揭示三点：其一，即便有明确证据，11.2%–58.7% 的运行仍出现不必要的风险处置，且随 agent 配置剧烈波动；其二，更强的任务能力并不保证更恰当的风险处理，而处置违规会显著损害开发者体验——所以「对风险的处理是否得当」是一条独立的能力维度；其三，agent 呈现的规律与人类风险管理研究高度一致，说明可以在既有工程实践里找到诊断与改进这类能力的抓手。

## 论文：更大更新但不更安全？LLM 生成代码「功能-安全缺口」的纵向研究
- source: arXiv
- date: 2026-10-07
- category: 安全
- url: https://arxiv.org/abs/2610.08240
- summary: 一项对 LLM 生成代码的纵向研究指出，随着模型迭代，功能与安全表现之间的「缺口」并不必然收窄，个别模型（如 Gemini 3.7 Flash）反而是例外——功能强不代表安全跟上。
- detail: |

    对关注 agent 化开发的读者而言，它呼应了一个正在被反复印证的事实：强任务能力与恰当的安全行为是两回事——与 ParanoiaEval 的结论互为镜像。安全的评估不该是功能达标的副产品，而应是系统设计时的硬约束与显式输入。

## 观察：AI 数学的「规模」与「验证」正在裂开——一次 722 篇之后
- source: 观察
- date: 2026-10-07
- category: 观察
- url: https://www.newscientist.com/article/2591679-arxiv-might-not-survive-ai-slop-onslaught-warn-mathematicians/
- summary: OpenAI 一次性放出 722 项数学发现，而数学家提醒其中多数尚未形式化验证、仅个位数让人印象深刻；同一周 arXiv 宣布限制上传——「AI 产出的规模」与「人类+机器验证的容量」之间的缺口成了核心议题。
- detail: |
    七百多篇论文是一次信号转弱为量变的时刻：模型已经从「解决一个难题」演进到「批量扫射开放问题」，并且是在 GitHub 上发布、而不是走学术评审通道。帝国理工的 Buzzard 给出了冷静的拆解——与其领域相关的 30 篇里只有 7 篇让他觉得出色、仅 1 篇有 Lean 形式化保证，其余都得等人逐字核查或补出证明。规模上来得快，可信度的建立却快不起来。

    验证侧同样在承压。正是本周，arXiv 宣布引入上传限额以遏制「低价值」提交——它担心的未必单指数学，但数学是模型「可自动生成、且结果可机器判定」的重灾区。生成量与审校量之间的剪刀差，会把「宣称正确」与「被验证正确」进一步掰开：未来对论文的分量，可能越来越取决于是否附带了可机器检查的证明，而非作者的名气或摘要的分量。

    这条路对纯数学是扰动，对「AI 可靠性」却是高信号资产：当机器能生成百万级数学「成果」时，谁的验证体系能跟上、谁就能给这些成果定价。它和 OpenAI 上一轮用 1500 万美元算力解题、以及更强的模型持续出现放在一起看，趋势已相当清楚——瓶颈早已不是「能不能做出来」，而是「如何让人相信它是对的」。
    参考来源：New Scientist（722 篇论文）、New Scientist（arXiv 上传限制）。
