## 论文：Growing Harness——\"增长 harness 而非上下文\"：把 agent 的重复控制决策训练成可复用代码，LLM 调用减 76–92%
- source: arXiv
- date: 2026-09-23
- category: 论文
- url: https://arxiv.org/pdf/2609.26760
- summary: 中国科学院深圳先进技术研究院与大学跨团队（SIAT + UMacau）提出 Growing Harness：从一个不编码控制器的\"无策略脚手架\"出发，用任务反馈训练 agent 的 harness 本身——函数级执行追踪把每次失败定位到有限的代码面，优化器联合修复一批失败，成功优先的 hold-out 门回滚会损害既有能力的修复序列。接受的编辑累积进一个共享 harness，控制结构从任务反馈中浮现。在 BrowseComp-Plus 与 WebArena-Verified 六个基准×模型组合中，Growing Harness 五处获得最高平均成功率，并把 LLM 调用减 76.0–91.8%、部署推理成本减 74.4–98.6%。
- detail: |
    论文要解决的是 agent 系统的一个现实冗余：LLM 处理一连串相关任务时，标准 harness 会要求模型在每个任务上下文里反复重建相同的控制决策——但这类重复控制其实适合编译成可执行代码。Growing Harness 的路径：从只暴露固定模型/工具接口、但不编码解决控制器的脚手架开始，训练运行时维护一个有限的失败窗口；对每次失败，函数级执行 DAG 记录涉及的代码路径/模型调用/工具调用/错误，离线优化器据此合成完整可执行候选，裁剪范围只触及被牵连的函数与少数新 helper；成功优先的 hold-out 门拒绝会降低聚合门集成功率的修复序列。

    结果上，它最抓人的是\"最小模型收益最大\"：在 WebArena-Verified 上，Growing Harness 在 4B 部署模型下成功率仍保持 44.7–45.3%，而 Tool-Calling 在 4B 模型跌到 6.7%——可复用代码把重复浏览器控制交给低成本代码执行，小模型不必每次重组控制。这延续了昨日 Harness-Zero 的\"把 harness 收益压进可复用形态\"线索，代表 agent 系统正在把\"谁做控制\"从\"每次都问 LLM\"向\"驯化成低边际成本的程序\"迁移。对部署长任务 agent 的团队，这是\"不换更大的模型、先让 harness 变聪明\"的一条低成本路线。

- detail: |
