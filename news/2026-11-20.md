## Google 发布 Gemini API Tool Retrieval（预览）：智能体数百个工具按需加载 schema，削减输入 token
- source: Google Blog
- date: 2026-11-20
- category: 应用/产业
- url: https://blog.google/innovation-and-ai/technology/developers-tools/gemini-api-tool-retrieval
- summary: Google 在 Gemini Interactions API 推出 Tool Retrieval 预览：智能体先声明完整工具库，只在任务需要的时刻按名加载对应参数 schema，官方称可削减输入 token、控制延迟并保持工具选择准确率。
- detail: |
    当智能体连接数十上百个工具，若每个请求都把全部参数 schema 发出去，会大幅膨胀输入 token、增加延迟，候选工具越多选择准确率也会下降。Tool Retrieval 让工具库保持待命：模型仍能看到每个工具的名字与简介，但参数 schema 不进上下文；当模型要调用某工具时，API 在同一请求内按名加载完整 schema。开发者加一个 tool_search 工具、在要搁置的工具上设置 defer_loading: true 即可启用。

    支持三种检索方式：服务端检索（Google 默认，无需构建索引）、客户端检索（自建工具注册表/权限过滤，略增一次往返）、以及把整个远程 MCP server 整体延迟加载。无额外费用，按调用模型的标准 token 计价；由于被搁置的 schema 不占 prompt 开头，还能配合前缀缓存（prefix caching）。兼容 Gemini 3.6 及全部 Gemini 4 模型，需 Interactions API 的 v1beta 版本。

## Anthropic 数学家 Alpöge 宣称与 Claude 找到黎曼猜想证明：仅发布 Lean 代码，尚未独立核验
- source: Scientific American
- date: 2026-11-20

- summary: Anthropic 数学家 Levent Alpöge 于 11/20 发文宣称与 Claude 发现黎曼猜想（及广义黎曼猜想）的证明，并以 Lean 证明助手形式化；但只以 14 个压缩存档发布代码、无论文，尚无任何独立数学家确认。
- detail: |
    黎曼猜想是关于素数分布规律的 167 年难题（1859 年提出），是 Clay 数学研究所「千禧年问题」之一（奖金 $100 万）。Alpöge 在个人网站发表四页声明：「我相信，与 Claude 合作，我发现了一个黎曼猜想的证明」，称方法「容易扩展」到广义黎曼猜想（GRH），并已「无假设」地在 Lean 中完全形式化。他刻意不发布人类可读版：AI 生成的非正式稿超过 25 万页，被他形容为「发布那种不可读的 slop 会是明显失当」，于是只给出 Lean——14 个压缩存档文件，外加一份他预计会很快「大幅简化」的说明。

    关键在两点：无论文、无独立验证。Lean 把证明拆成逐个可由机器检查的逻辑步骤，若代码最终编译通过、且最终定理如实陈述了黎曼猜想，就被视为「排除合理怀疑」，但专家指出现实中 Lean 内核有过 bug（历史上曾被用于证明 0=1），类型理论可靠性也有未定之处。Buzzard（帝国理工）回应「先看看能不能编译」；Maynard 称「我怀疑证明会是对的，但检查 Lean 验证本身也要时间」。Aaronson 注意到「至今所有带 Lean 证书的 AI 证明无一被撤回（而多个不带证书的被撤了）」，倾向认为证明会站得住，但强调应优先修复 Lean 本身。Alpöge 也自认「在掌握大量周边数学之前就把完整论证交给世界」，警告部分段落是复述 Claude 的描述可能不成文。

    需注意口径：Anthropic 官方研究页（riemann-zeta）此前只宣称 Claude 改进满足黎曼猜想的零点比例的下界，并未到完整证明；本次是 Alpöge 的个人声明，公司未同步背书——若被确认，是 AI 数学能力里程碑，但要先让 Lean 编译过关。

## Thinking Machines 开源循环 Transformer 模型 Inkling 2 Mini：可离线跑在笔记本上，中间层重复执行
- source: Thinking Machines
- date: 2026-11-20
- category: 开源
- url: https://thinkingmachines.ai/news/inkling-2-mini/
- summary: Mira Murati 的 Thinking Machines Lab 发布 Inkling 2 Mini：26.4B 总参数、3.4B 激活的循环 MoE，中间两层对每个 token 重复执行三次，总内存约 20GB 可离线跑在笔记本，在 <100B 开源模型中领跑 DeepSWE v1.1（48.2%）与 Vals Index v2.2（46.5%）。
- detail: |
    Inkling 2 Mini 是一台「looped transformer」：模型中间的两组块（各 6 层）在每次 token 上重复执行三次，让同一次前向推演投入更多计算——用词来说，是「在不把推理写下来的情况下思考更久」，这正好关系到可监控性：越少把推理写到 CoT，越难用读思维链来监督它。根据官方测试，循环在一遍时把无 CoT 时域从 16 秒拉到 3 遍 37 秒，串行推理基准到 10 遍仍在提升（超出 5 遍的训练深度），思维链变短但全程可读，且循环次数增加并未让 agentic sabotage 测试得分走高。

    工程与开源：大多数权重以 NVFP4 训练与部署、最后 4 层 MXFP8，总内存约 20GB，能在消费级笔记本和 DGX Spark 桌面 AI 电脑上运行——团队在飞机上用离线 MacBook Pro（M5 Pro）几分钟内建出一台可玩飞行模拟器。开源程度很高：完整权重与研究用 variable-loop 变体全部发布（Hugging Face），支持 SGLang、vLLM、Ollama、Unsloth、llama.cpp、NVIDIA Dynamo、TokenSpeed 推理，以及 SkyRL、Miles、NVIDIA AutoModel 的 RL 微调。还与 NDIF 合作向可解释性社区开放，解释性实验室 Goodfire 已给出早期研究。衡量事实量的 AA-Omniscience 得分与同规模模型持平——循环提升推理，却不增加事实存储，知识短板通过搜索与工具补齐。

## 观察：MIT 研究估算 2023 年美数据中心用电引约 650 例过早死亡，污染却落在远离机房的中西部
- source: MIT News
- date: 2026-11-20
- category: 观察
- url: https://news.mit.edu/2026/study-reveals-data-centers-long-distance-damage-air-quality-1119
- summary: MIT 团队在《Environmental Research Letters》发文估算，2023 年美国数据中心新增电力需求引致约 650 例过早死亡（PM2.5 513 例、臭氧 137 例），约占美国电力相关死亡 5.3%，而人均受害率最高竟是无机房的 Iowa/Nevada/南北达科他等中西部州。
- detail: |
    方法与结果：团队建模美国电网超过一万个发电机组的小时级调度，先算出哪些机组针对数据中心新增负荷做出响应，再把产生的 NOx/SO2 排放送入化学传输模型模拟污染物跨区传播，最后用流行病学证据把附加污染折算成过早死亡。结果是 2023 年约 650 例过早死亡（PM2.5 贡献 513 例、臭氧 137 例），约占全国电力相关死亡的 5.3%。关键的反直觉之处：电力需求集中在北弗吉尼亚与德州，人均过早死亡率最高的却是 Iowa、Nevada、南达科他与 Kansas 等中西部州——因为它们电网内用来响应负荷的机组多在俄亥俄河谷，那里的老电厂使用煤与天然气产生更高排放，大气再把污染与暴露扩散到「远在机房之外」的社区。

    讨论与意义：伯克利实验室估计 2023 年数据中心约占美国电力需求 4%、排放约 4.4%，而随着 AI 扩建这一份额只会上升。作者直言数据中心选址与运营应考虑的不只是土地与电价，还要把空气质量纳入等式——「即便你以为身边没有数据中心不受影响，也要再想想」。相比笼统的均摊法，本研究是首个把「具体机组 + 区域间输电 + 大气化学传输」串联起来的量化估算，也正是治理基建外部性的一个具体抓手：数据中心的算力红利与健康代价，正在不同州之间错位分布。
