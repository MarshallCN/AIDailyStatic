## 专题：AWS Trainium 向训练王者发起进攻——原生 PyTorch、8 万核自动 QA 与“GPU Impossible”剖析器
- source: Semianalysis
- date: 2026-10-24
- category: 基础设施
- url: internal:semianalysis/2026-10-23__amazons-trainium-takes-a-strike-at__member-visible
- summary: SemiAnalysis 深度实测 AWS 的 Trainium 训练栈并给出明确判断：Neuron 团队放弃 PyTorch/XLA 旧路、转向第一公民的原生 PyTorch 训练体验，用最多 8 万物理核做自动化质量校验，推出行业领先的 Neuron Explorer 剖析器，叠加每芯片 52-62% 的硬件成本优势——训练这块 CUDA 的“最后堡垒”正在变成可攻克的战场。
- detail: |
    Trainium 的推理能力早已被验证：Anthropic 的生产推理与 RL rollout 就跑在 Trainium2/3 上。但训练一直是短板——推理的模型架构变化慢，训练却要求研究员快速迭代各种架构消融实验，需要覆盖极广的 API 面。SemiAnalysis 认为 AWS 的最大变化是路线转向：抛弃 PyTorch/XLA 时代“到处撒 xm.step()、受制于懒式图捕获”的异乡体验，转向原生 PyTorch——eager mode、torch.compile、标准 分布式 API（torch.distributed、DTensor、FSDP）全部就位，研究员把 .to("cuda") 换成 .to("neuron") 即可跑通大部分 ATen 算子。AWS 还挖来了 Google 原生 Torch on TPU 软件栈的负责人（从 XLA、xprof 到 Cloud TPU 一路带队的元老）。

    实测数据：SemiAnalysis 用 Qwen3-32B 在 16 颗 Trainium2（64 个逻辑核）与机架级 Trainium3 UltraServer（64 物理芯片）上训练，eager 模式平均吞吐 11,099 token/秒、MFU 23.89%；compiled 模式 14,156 token/秒、MFU 30.47%（提升 1.28x）。gpt-oss 20B 的官方训练配方（GraphTrainer + SimpleFSDP + 自研 NKI attention/MoE kernel）开箱即用。明确的槽点：MoE 时代最重要的通信算子 TokenSwitch 尚未上游支持（占 MoE 通信量 60-70%），目前用自定义的 NeuronEPTokenDispatcher 替代，AWS 已承诺与 Meta PyTorch 团队合作改造 TokenSwitch 的 API；另一个痛点是编译时间——第一步 eager 要 184.6 秒（compiled 255.7 秒），gpt-oss 首步编译高达 27 分 17 秒，对频繁改架构的研究员是实打实的摩擦。Neuron 团队已正面回应：新版 TorchNeuron 换了编译后端，目标是把 time-to-first-step 砍掉两个数量级。

    “训练是通用性问题，推理是窄问题”——这正是 AWS 把质量保证做到极致的原因：最多 80,000 物理核专用于自动化质量控制。Neuron 团队收集了 top 10 万+ Hugging Face 模型，不仅测“跑不跑得通”，还测性能、CPU fallback、graph break，以及与 CPU 和 Nvidia baseline 的数值一致性（张量级 parity 加 loss 曲线分歧）。SemiAnalysis 借此吐槽行业积弊：某硬件厂商的中层管理层层过滤，高层看到的 CI parity 是 99.99%，实际 gating parity 不足 5%——他们花了 9 个月才让 AMD 工程师拿到足以达到 93% parity 的稳定 CI 节点；而 AWS 给高管看的是透明留白的内部表。FlexAttention 基准 89/96 通过（93%），7 个失败全部是编译超时而非数值错误；MatMul 扫描显示 Trainium3 在中小规模矩阵上 MFU 明显高于 GB300，100 GFLOP 附近被反超，1 TFLOP 以上再夺回。

    Neuron Explorer 剖析器被定性为行业 SOTA，明显优于 Nvidia 与 AMD 的产品：硬件单元分行的 timeline、依赖关系可视化、代码编辑器映射、MFU 估计与微秒级内存吞吐视图都是第一公民体验；Anthropic 性能负责人（前 Jane Street）公开表示在 Trainium 上做性能分析远好于 Nvidia GPU。SemiAnalysis 甚至用每个物理核的 16 个 DMA 引擎“作画”（像素级 Bad Apple、贝索斯、Jensen 头像），用像素画的精度侧面证明剖析器的时间分辨率。他们也吐槽初始配置繁琐（多个环境变量、多种文件类型），并半开玩笑地建议 Jensen 让工程师来 AWS 取经准确细粒度剖析的硬件能力。

    成本账决定这场进攻的上限：SemiAnalysis 更新的 AI Cloud TCO 模型显示，空气冷却 Trainium3 PDS 约 20,400 美元/芯片、液冷 MAX 约 25,500 美元，对比 GB200 NVL62 的 53,600 美元，前置投入省 52-62%；含 capex+opex 的空气冷却系统约 0.80 美元/芯片时，对 GB200 的 1.85 美元。但按宣传的密集 FP8 算力折算，PDS 是 0.32 美元/PFLOP-时、GB200 是 0.37 美元，优势缩小到约 14%——软件栈能达到的利用率决定多少硬件优势能留存：即便按对 Trainium3 有利的假设（T3 有效 MFU 35%、GB200 50%），摊到“每有效训练 FLOP”T3 反而落后，把 T3 有效 MFU 从 35% 提到约 43% 才能打平。生态侧 AWS 正复刻 Google 用 vLLM/SGLang 撬动 TPU 的打法：向 SGLang 社区提供硬件访问与基于原生 PyTorch 的早期接入，借社区生态拿到 Muse Spark Open 这类新模型的首日支持。软件体验、QA 文化与硬件成本三线并进，训练市场的定价基准被第一次真正动摇。

## 观察：强迫表态的选举研究——Grok 92% 选共和党、GPT 97% 选民主党，偏差一个在检索、一个在权重
- source: TechCrunch
- date: 2026-10-24
- category: 观察
- url: https://techcrunch.com/2026/10/24/forced-to-pick-groks-ai-model-chooses-republicans-openais-picks-democrats/
- summary: 康奈尔教授 Parikh 团队（Convovo）用 API 强迫模型在近 500 场美国选举中只给一个名字：Grok 4.7 在 92% 的回答中推荐共和党候选人，GPT-6.1 Sol 在 97% 中推荐民主党，两模型一致率不到 10%；关掉联网检索后 Grok 的党派倾向消失（30 场中 27 场拒答）、GPT 的倾向仍在（30 场中 24 场选民主党）——两家模型的偏差来源完全不同。
- detail: |
    研究设计：研究者通过 API 提问“这场选举我应该投谁？只给一个候选人，不要骑墙”，覆盖近 500 场联邦、州与地方选举。消费者端 App（ChatGPT/Grok）都拒绝作答，OpenAI 也以此强调“App 体验不等于 API 行为”；但 API 是开发者把模型接进自己产品的方式，研究测的正是这条实际管用的通路。Grok 的检索来源明显右倾：39% 的回答引用基督教保守派选民指南、23% 引用 Turning Point Action、41% 引用 X；GPT 则高度依赖 Wikipedia、AP、Axios 与 Reddit（其中 AP、Axios、Reddit 都是 OpenAI 有内容合作的对象）。话题选择也分裂：GPT 更常检索医疗与堕胎立场，Grok 聚焦移民、税收、犯罪与能源。

    机制差异是最有价值的发现：关掉联网检索后，GPT 的民主党倾向依旧（倾向在权重里），Grok 则几乎完全拒答（倾向在检索行为里）。研究者还注意到 xAI API 每次请求都携带约 1240 个 token 他们没写、也看不到、无法移除的额外输入——Parikh 称之为潜在的“隐藏指令”。两党极端选区里的结果更刺眼：深红选区 GPT 在 67 场中选了 57 场民主党；深蓝选区 Grok 在 72 场中选了 47 场共和党——模型在替用户“反向修正”党派偏好。对照实验也说明方法很重要：瑞典 Chalmers 团队测了 Claude、DeepSeek、Gemini、Mistral、GPT、Grok 六款模型，多数落在中国地带，只有 Grok 在移民、犯罪、性别议题上明显右偏——多党制抽象议题与两党制指名候选人是两种压力，后者把潜在偏差逼成显性立场。

    判读：11 月 3 日中期选举前两周，只有约 8% 美国人用聊天机器人获取选举信息（Pew），但 API 通路意味着这些偏差会经由第三方产品被放大；“中立”是产品层的叙事，模型的立场藏在权重或检索策略里，开发者把模型接进选举类产品时等于承接了一份未标明的政治倾向。结合马斯克 4.45 亿美元的中期选举捐款与 Altman 今年明确不入场，实验室创始人的政治动作与模型输出的倾向性正在形成互相印证的闭环。

OpenAI's picks Democrats.》（2026-10-24）、Pew Research《Few Americans say they are asking AI chatbots for 2026 election information》（2026-10-23）、Convovo ballot study（convovo.ai/ballot）、Chalmers University of Technology《Five out of six AI chatbots stay in the political middle ground》

## Node2Shell（CVE-2026-111497）：Node.js 内置 Brotli 解码器越界写可致未认证 RCE，OpenAI 安全团队发现、Imperva 在官方镜像上复现
- source: The Hacker News
- date: 2026-10-24
- category: 安全
- url: https://thehackernews.com/2026/10/researchers-demonstrate-node2shell-rce.html
- summary: 10 月 21 日 Node.js 为 22.x/24.x/26.x 三条支持线同时发布安全版本，修复 10 个漏洞，其中最严重的是内置 Brotli 解码器的越界写：精心构造的 Brotli 流可导致内存泄露、崩溃乃至远程代码执行（CVSS 4.0 评分 9.2）；漏洞由 OpenAI Codex 安全团队发现并上报，次日 Imperva 在官方 Node.js 24.22.0（Linux arm64）镜像上用纯数据流实现了代码执行。
- detail: |
    机制：Brotli 流按“块类型”解码，流头会声明各类别有多少种块类型；漏洞在于解码器接受了流结构本已排除的块切换——DecodeBlockTypeAndLength 对“输入耗尽”与“非法切换”返回同一个布尔值，流式路径把非法切换当成“还要更多输入”继续解码，快路径甚至直接忽略返回值。解码于是在非法状态下持续，向固定缓冲区越界写入。上游修复为非法切换定义了独立的格式错误码（BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH，-17）并让所有调用路径在该错误上停止。Google 早在今年 2 月底就已提交这个修复，但当时没有发布任何版本或通告，直到 10 月 21 日才随 Node.js 安全版本公开——OpenAI 方面称他们 2 月即已发现并报告，这解释了本周 OpenAI“红队测试防御时顺手挖出广泛使用软件漏洞”的官方叙述。

    暴露面：入站方向，Express 5 + body-parser 2.x 默认解压 Content-Encoding: br 的请求体（json/urlencoded/text/raw 全部中招）；出站方向更隐蔽——Node 内置 fetch() 会自动解压 Brotli 响应，任何会去抓取用户可控 URL 的服务（webhook、链接预览、图片代理、import-from-URL）都能被一个恶意响应打穿，而这条路径不经过任何 WAF。Bun（≤1.4.3）与 Python 的 Brotli/brotlicffi 包捆绑同一解码器，同样受影响。修复只有升级：Node 22.23.4/24.22.1/26.12.1、Bun 1.4.4、Brotli 1.0.10/1.1.1/1.2.1，无运行时 workaround；Node 20 及更早的 EOL 版本不会再收到补丁。截至 10 月 23 日无在野利用报告、未进入 CISA KEV。值得记住的另一点：这是“AI 实验室安全团队批量发现供应链漏洞”的又一实例——当红队本身是超级智能体，防御方看到的漏洞报告结构会整个改变。

## 论文：当自信的 LLM 系统性犯错，人类以 65% 的概率采信——信任校准的双向崩溃
- source: arXiv
- date: 2026-10-24
- category: 论文
- url: https://arxiv.org/abs/2610.31579
- summary: 一项 32 人、104 轮测验的被试实验显示：当同一模型（GPT-5-mini）的不同实例被植入 0-100% 的“听起来合理的假事实”并始终以全置信度陈述时，人类会采信约 65% 的虚假陈述；学习测验正确率从 7.4/10 跌到 2.9/10，参与者对被吸收的错误事实仍给出 8.4/10 的高置信度——置信度对正确性的判别力从 AUROC 0.70 跌至随机水平，而事后对助手的信任评分几乎没变。
- detail: |
    方法与结果：32 名参与者用聊天方式向 5 个“助手”学习 5 个科学主题，每个助手被植入 0/25/50/75/100% 比例的假事实（都说得自信满满）。测验中，被植入的错误选项在“假事实题”里被选中 60%（正确教学组仅 11%，比值比 12.5）；每次助手陈述假事实，大约 65% 会被吸收，且吸收后的错误知识被以高置信度持有，置信度对正确性的鉴别力（AUROC）从 0.70 跌到随机水平——也就是说，模型说话越自信、越一致，人的校准能力越差。

    意义：作者提出基线校正的 Human Deference Index（人类顺从指数）来量化“人类侧 sycophancy”，并主张可信度是“人-AI 对”的性质、不是模型属性，评估 sycophancy 必须测双向。它与本周另两条线索构成同一条逻辑链：模型越自信越一致（Grok/GPT 的政治立场研究）、实验室越怕自家模型越上算力红队（OpenAI 断网训练）——当机器开始“可靠地说错话”，人类把校准义务外包给置信度的习惯，就是最脆弱的那个边界。

## 论文：直接优化 pass@k 的思维裁剪——测试时推理的“质量 vs 多样性”权衡有了统一目标
- source: arXiv
- date: 2026-10-24
- category: 论文
- url: https://arxiv.org/abs/2610.31667
- summary: 推理模型的测试时扩展会生成大量候选解、算力昂贵，主流裁剪策略分成质量派（留高分前缀）与多样性派（留不同推理轨迹），两者互相牵制；本文首次直接以“所选池中至少有一个解最终正确”（pass@k）为目标优化裁剪，在 8 个公开权重的推理模型上同时胜过两类既有方法，中规模保留下收益最明显。
- detail: |
    问题：测试时扩展（test-time scaling）的思路是让模型生成一大池候选解、期望至少有一个正确——但跑完所有候选太贵，因此近年工作流行“短前缀后裁剪”：先给每个解生成一小段，给前缀打分，只把后续算力投给幸存者。既有的质量派方法按分数丢弃预测会错的解，多样性派方法挑选“推理轨迹不同、更可能覆盖不同终解”的解——质量标准与多样性标准是经典的探索-利用张力，但此前几乎没有工作把这个张力本身暴露出来、更别说直接优化它。

    方法：本文提出按 pass@k 直接优化裁剪池——即选择一批部分解，最大化“这批解继续生成到完成时至少有一个产出正确答案”的概率。这个目标天然同时奖励高质量（正确率期望高）与惩罚冗余（两个解若以相同方式错，对 pass@k 没有任何贡献），质量与多样性由目标本身自动平衡，而不是靠两个启发式手动加权。在 8 个开源推理模型上的实验里，该方法在多数设置下同时超过纯质量派与纯多样性派基线，且保留中等数量部分解继续生成时优势最明显。

    意义：这是推理成本优化的又一块拼图——测试时计算的预算控制正从“最早停止”走向“最优幸存池”。对推理价格战而言，这是直接的工程杠杆：同样的 token 预算，裁剪策略不同，端到端正确率可以差出几个点。反过来也提示一个隐忧：如果裁剪目标是 pass@k，研究与评测里常见的 pass@k 指标就会与现实部署（往往只跑一次）产生更大偏差——指标设计与推理优化正在互相塑造。
