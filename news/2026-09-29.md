## Anthropic 的 Claude 自主发现类 CRISPR 的 ART 酶系统
- source: The Next Web
- date: 2026-09-29
- category: 论文

- summary: Anthropic 新组建的分子生物实验室用约 950 个 Claude agent 在 21 小时内自主发现一个此前无人描述的、结构类似 CRISPR 的酶系统 ART（array-associated reverse transcriptases），但功能尚不明确。
- detail: |
    这是 Anthropic 新成立的分子生物学小组（2026 年春季组建）的首个成果。团队让约 950 个 Claude agent 在含约 20 万条逆转录酶序列的数据库中自主搜索，21 小时后，一个 agent 定位到一个此前未被识别的系统：一个逆转录酶基因旁伴生一个功能未知的伙伴基因，以及一串长度 3–21 的、间距规律的 DNA 重复阵列——这套"酶 + 伙伴 + 阵列"的三件套结构与 CRISPR 的架构相似。团队将其命名为 ART（array-associated reverse transcriptases，阵列关联逆转录酶）。

    依据预印本，整个战役跑在 Claude Mythos 5 / Claude Code 上，949 个 agent 会话、21.5 小时无人工干预、消耗约 2.16 亿 token，从 19 亿蛋白簇里采样约 1.1 万个 RT 位点、产出 19 份人类可读报告。湿实验的证据仍有限：公共 RNA-seq 数据显示阵列转录出离散短 RNA，感染 15 分钟后占噬菌体 RNA 可达 8%；但预印本明确承认"尚未证明该逆转录酶具有活性，也不知道它对这些 RNA 做什么"。CRISPR 先驱、MIT/Broad 的 Feng Zhang 审阅了预印本，称对 RNA 重复阵列的识别"确有意思、值得深究"。

    这一结果的意义更多在方法本身：自主 agent 完成了一次可复现性存疑（同一战役重跑 10 次全部漏掉阵列）、却真实落地的生物发现，是"agent 驱动科学发现"从演示走向产物的一次样本。Amodei 把它比作"第一个 standalone"生物学自主发现里程碑。

## 论文：RRSI 用正则化让"自改进 agent"不过拟合基准
- source: arXiv
- date: 2026-09-29
- category: 论文
- url: https://arxiv.org/abs/2609.24972
- summary: Google 与高校团队提出 RRSI（正则化递归自改进 of agent harnesses）：自改进 agent 会"背下"训练基准而在分布外严重退化，正则化搜索路径后 8 个基准上最高 +14.1 分、5 个分布外基准 +4.7 分且省 30% token。
- detail: |
    agent 的能力高度依赖其 harness——冻结骨干模型外的提示、控制流、工具、记忆与上下文管理。越来越多方法用 LLM 自动迭代地提出并选择对 harness 的编辑，形成"agent 系统层的递归自改进（RSI）"。但这篇论文指出了一个被忽视的问题：如此反复进化会"记忆"训练任务，在 evolve 集上大幅上涨、跑到分布外基准就缩水甚至清零。

    作者提出 RRSI，把经典机器学习的"正则化"思想搬进 harness 进化：proposer 在时间退火预算内限制单次捆绑的编辑数量、并鼓励探索历史中未走过的轨迹；selector 配 critic（先筛掉显式编码任务名/实体名的泄漏候选）与 pruner（删掉太小、太贵或不复有用的改动）。约束的是"搜索怎么走"，而保留每个 harness 组件都可改。

    跨覆盖编码、agentic workspace 与工程设计域的 8 个基准，RRSI 在进化目标上最高 +14.1 分、在 5 个分布外基准上 +4.7 分，且最终 harness 比未正则化的进化省约 30% 策略 token。正如负责这次搜索策略的 Claude Opus 4.8 所示，关键洞察是：当反馈被反复复用时，真正的自改进必须区分"可迁移机制"与"基准特有拟合"。代码已在 github.com/google-research/rrsi 公开。

## Semianalysis：GLM-5.3 稀疏注意力如何影响 HBM 内存
- source: Semianalysis
- date: 2026-09-29
- category: 基础设施
- url: internal:semianalysis/2026-09-28__sparse-savings-persistent-demand-inside-glm53__member-visible
- summary: Semianalysis 详解 GLM-5.3 稀疏注意力的推理代价：稀疏化降低 SDPA 访存，却不降低 HBM 容量瓶颈；真正的效率来自记忆层级（HiSparse 的 HBM↔DRAM 卸载）、引擎优化（vLLM/ATOM/TileRT）与成本/吞吐权衡。
- detail: |
    Semianalysis 这份报告的核心结论相当反直觉：稀疏注意力（选择 top-k 相关 token 来注意）确实大幅降低核心 SDPA（缩放点积注意力）操作的访存与带宽需求，但由于 top-k 选择本身需要全文在 HBM 中，稀疏化并不能消除内存容量瓶颈。换言之，"稀疏带来省内存"被高估了——它优化的是计算访存比，而非把容量问题做没。

    系统的解法在记忆层级。SGLang 的 HiSparse 像 LRU 缓存一样把 KV cache 从设备 HBM 主动卸载到主机 DRAM，命中缺失时才回载；并在 HiCache 基础上做层间重叠——层 N 的 KV 装载与层 N-1 的执行并行，从而掩盖 cache miss 的 I/O 延迟。在高并发、长上下文场景，SGLang 借此大幅提升吞吐。这说明：稀疏注意力的内存画像不足以刻画系统 KV 效率全貌，真正的收益来自 serving 引擎在内存层级上的调度。

    报告用 InferenceX 基准对比了实际 serving 成本。以 150 token/s 为目标流式速度，GB200（Dynamo-SGLang）约 $0.044/百万总 token，比 MI355X + ATOM 的 $0.049 低约 12%；GB300 每 GPU 吞吐比 GB200 高 17.5%，但因更高的小时成本在总成本上被抵消。若把首 token 延迟（TTFT）卡在 2 秒内，MI355X+ATOM 比 B200 便宜约 9%；放宽到 10 秒，GB300+Dynamo-TRT-LLM 以 $0.0451 胜出，比 ATOM 低约 26%。后一种配置的 TTFT 约 14–19 秒，是"用延迟换成本"的典型。

    深入到 GLM-5.x 架构本身：它的注意力用 KV 压缩 + 稀疏（DSA）两条路降本，serving 引擎则决定缓存放哪、怎么取。当并发从 8 升到 16，GPU 内存中复用的 prompt token 占比从 90.3% 降到 54.8%，主机内存复用从 6.0% 升至 40.3%，总 cache 命中率仍保持在 95% 以上——复用大量发生在 GPU 内存之外。引擎层面，vLLM 让首个 decode 步骤走一致的 CUDA graph 路径，把平均 TPOT 从约 40ms 压到 22ms；ATOM 跨流水级分块做 prefill，吞吐提升 98%、中位 TTFT 从 28.6s 降到 8.7s。

    面向低延迟，AMD 的 TileRT 把解码编译成单一持久化内核，优先单用户更快的 token 生成而非最大批吞吐；FP8 TileRT MI355X 的 P90 交互性比最好的 FP4 MI335X 高 2 倍、比 GB300 NVL72 高 40%。同时，GLM-5 的 H=64 个 query head（DeepSeek V3.2 为 128）把算术强度调到约 120.8 FLOP/B，被怀疑是为 Moore Threads MTT S4000（约 128 FLOP/B）优化——联合 IndexShare（每 4 层共享一个 indexer）以降 indexer 延迟可见，稀疏注意力的成本之争正从"模型层"下沉到"哪家芯片 + 哪套引擎"的毫厘之间。这份报告把"稀疏注意力真的省内存吗"从厂商话术拉回到可测量的内存层级与 serving 成本，是评估执行层基建重建的重要标尺。
